# 초대 관리 API

Backend [#13](https://github.com/OpenStudyService/OpenStudy-Backend/issues/13)의 구현 범위다. 서버 접두사는 `/api`이며 기존 OpenAPI의 요청·응답 모델을 사용한다. WORKSPACE 세션의 현재 계정·소속·행위 권한을 검사한다.

## 제공 범위

| API | 동작 |
| --- | --- |
| `GET /invitations` | 관리 가능한 지점의 초대 목록·검색·상태 필터·페이지 조회 |
| `GET /invitations/{id}` | 관리 가능한 지점의 초대 상세 |
| `POST /invitations` | 초대·예정 권한·발송 대기 작업 생성 |
| `POST /invitations/{id}/reissue` | 미수락 초대 재발급·새 24시간 부여 |
| `POST /invitations/{id}/cancel` | 수락 전 취소 |
| `POST /invitations/{id}/reject` | 수락 후 사유와 함께 반려 |

메일 worker·SMTP·자동 재시도의 후속 구현은 [#14 발송 계약](invitation-delivery.md)을 따른다. 공개 미리보기·수락·최종 승인은 #15에서 구현한다. 초대 생성의 201과 `발송 대기` 응답은 메일 수신이나 직원 승인을 뜻하지 않는다. 실제 서버·메일·브라우저 전체 흐름은 #18에서 별도로 검증한다.

## 권한과 입력

OWNER는 지점 전체를 관리한다. MANAGER는 해당 지점의 `people:manage`가 있어야 하며 STAFF 초대만 처리한다. STAFF가 같은 행위 권한을 보유해도 관리자 명령을 사용할 수 없다. 현재 대상 계정과 지점 소속도 다시 검사하여 기존 MANAGER를 STAFF 초대로 낮추거나 OWNER를 초대하는 우회를 막는다.

생성은 이름·정규화한 고정 이메일·지점·역할·예정 권한을 받는다. 선택한 프리셋과 권한은 기존 공개 검증 서비스를 사용하고 초대에 권한 집합을 복사한다. 이후 프리셋 수정이 이미 생성한 초대의 예정 권한을 바꾸지 않는다. 입력에 없는 필드나 권한 코드를 임의로 허용하지 않는다.

목록의 `scope=all`은 현재 관리 가능한 지점의 합집합이다. 필터·검색·페이지의 total에도 같은 범위를 적용한다. 관리 응답에는 원문 토큰·토큰 해시·발송 revision·메일 링크가 없다. 초대 상태와 발송 상태를 별도 필드로 제공한다.

## 상태·재전송·트랜잭션

생성은 revision 1과 PENDING 발송 작업을 함께 저장한다. 토큰 원문이나 복호화 payload를 만들지 않으며 해시는 worker가 발송 작업을 claim할 때 생성하도록 NULL로 둔다. 같은 이메일·지점에 활성 소속이나 진행 중인 초대가 있으면 생성하지 않는다. 만료 스케줄러가 늦었더라도 이미 기한이 지난 PENDING 초대를 신규 생성 트랜잭션에서 만료 처리해 중복 슬롯을 해제한다.

재발급은 미수락 PENDING/EXPIRED에만 허용한다. 다른 진행 초대와 충돌하지 않는지 다시 확인하고 새 24시간·새 revision·새 발송 작업을 예약한다. 이전 해시를 지우고 이전 미완료 발송 작업을 무효화한다. #14의 자동 재시도는 원래 TTL을 유지하며 수동 재발급과 구별한다.

취소는 PENDING에서, 반려는 ACCEPTED에서만 새 전이를 수행한다. 반려는 해당 초대의 수락 계정·지점에 대응하는 PENDING 소속만 회수하고 기존 ACTIVE 소속이나 다른 지점은 보존한다. ACCEPTED에는 별도 승인 기한이 없으므로 링크 기한이 지났다는 이유로 만료시키지 않는다.

새 전이는 API version(DB version + 1)을 검사한다. 이미 같은 취소·반려 종료 상태인 반복 명령은 현재 권한을 재확인한 뒤 현재 결과를 반환한다. 다른 상태의 새 전이를 낡은 version으로 허용하지 않는다. 생성의 `Idempotency-Key`는 작업자·작업·대상 지점에 한정하고 같은 정규화 입력만 원래 응답을 재사용한다. 재사용 시에도 현재 권한을 검사한다.

기존 `AuthorizedCommands`의 관리 가드·직원·지점·초대 부모 잠금을 사용한다. 초대·권한 snapshot·발송 작업·감사·workspace outbox는 같은 트랜잭션에서 커밋하거나 롤백한다. outbox에는 비밀값이나 초대 본문을 넣지 않으며 기존 지점·권한 필터 SSE를 재사용한다. 외부 메일 호출을 트랜잭션 안에서 실행하지 않는다.

## 검증과 후속 범위

실제 실행 결과와 인수 조건별 근거는 [개발 기록](../../development-log/2026-10-27-invitation-management.md)에 남긴다. 테스트는 전용 Testcontainers MySQL을 사용하며 사용자 DB·원래 작업 폴더의 통합 V1 변경을 사용하지 않는다. 이 구현은 main의 기존 V1~V3 스키마를 재사용한다.

SMTP 수신·worker lease·실제 수락/승인·전체 브라우저 흐름·운영 HTTPS 프록시 검증은 이 범위의 HTTP/DB 시험 성공으로 대체하지 않는다.
