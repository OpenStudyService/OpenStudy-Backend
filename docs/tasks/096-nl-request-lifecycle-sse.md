# BE-096 요청 수명주기·SSE·취소·확인 재실행·빈도 제한·진단 로그

- 이슈: [#96 요청 수명주기·SSE·취소·확인 재실행·빈도 제한·진단 로그](https://github.com/OpenStudyService/OpenStudy-Backend/issues/96) · M10 · `type:feature`, `layer:controller`, `layer:service`, `layer:persistence`
- 상태: **선행 대기** (#92 이후 #93~#95와 병행 가능)
- 선행: #92 (열림). 실행 연결은 #94·#95와 함께 검증
- 후속: #97, #102 (요청 ID 연결), #125
- 인수 조건 진행: 0 / 11 (2026-11-06 조회)

## 목표

질문 접수부터 완료·취소·실패까지를 요청 ID로 추적하고, SSE로 상태를 전하며, 단계별 지연과 진단 정보를 남긴다.

## 작업 단계

1. 마이그레이션(새 버전): `ai_threads`, `ai_requests`, 진단 로그 테이블. V1 수정 금지, 번호는 병합 직전 확정.
2. 입력 검증: 빈 값, 1,000자 초과, `ai:read` 없음은 실행 전 거부.
3. 상태 관리: 접수·생성·검증·실행·완료·추가 확인·취소·실패. SSE와 상태 재조회가 같은 값을 보이고 재연결 시 현재 상태를 받는다.
4. 중복 제출 방지(클라이언트 요청 키), 취소, 취소된 요청의 늦은 이벤트가 다른 결과를 덮어쓰지 않게 한다.
5. 확인 선택 후 재실행: 서버가 준 선택 ID만 받고 현재 권한을 다시 검증한다.
6. 빈도·동시 실행·예산 제한 구조: 설정값으로 바꿀 수 있고 초과 시 공통 429. 값 확정은 #97 측정 후.
7. 진단 로그: 요청 ID·QuerySpec 식별정보·IR 검증 결과·적용 범위·권한·제한 검사·상태·단계별 소요 시간.
8. 질문 원문은 인증·세션 정보를 제거해 저장하고 30일 뒤 원문만 삭제하는 정기 작업을 만든다.
9. 모델 장애·해석 실패는 조회 오류로 끝내고, 세션 종료·권한 변경 시 진행 중 스트림을 닫는다(#17 SSE 회수 재사용).
