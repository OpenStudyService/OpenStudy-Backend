## 목표

어떤 생성기가 만든 IR이든 서버가 다시 검증해, 등록된 의미·현재 권한·실행 예산 안의 명세만 실행기에 넘긴다.

## 작업 단계

1. 구조 검증: QuerySpec·ViewSpec 스키마·버전·필수 필드·타입. 실패 시 IR 검증 실패.
2. 의미 검증: 등록된 지표·필드·관계·연산만 허용. SQL·JPQL·JavaScript·미등록 컬럼 차단.
3. 쓰기 의도(결제 실행·권한 변경 등) 차단: 조회 실행 전에 거부하고 업무 쓰기 API를 호출하지 않는다.
4. 정규화: 상대 기간을 Asia/Seoul 기준 시각으로 고정 변환, 지점 표현을 등록 지점·사용자 접근 범위로 해석.
5. 권한 검증: 지점·행·필드 권한, 매출은 `ai:read` + 대상 지점 모두의 `sales:read`. 권한 밖 지점은 다른 지점 정보를 노출하지 않는 재입력 안내.
6. 예산 검증: 366일 초과 기간, 1,000행 초과 예상 요청 처리.
7. 확인 질문: 지점·기간·지표가 모호하면 선택 ID를 포함한 확인 질문을 만들고, 기본값을 쓰면 적용 값을 명시한다.
