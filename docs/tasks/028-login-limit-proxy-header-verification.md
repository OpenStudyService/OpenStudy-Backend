## 목표

출처별 제한(30회/15분)과 인증 사건 감사는 구현·시험을 마쳤다. 남은 것은 실제 Nginx·Gateway 경로에서 전달 헤더를 위조해도 출처 제한을 우회할 수 없는지 확인하고 이슈 종료 여부를 판단하는 일이다.

## 작업 단계

1. Infra#2에서 신뢰할 프록시와 전달 헤더(`X-Forwarded-For` 등) 계약이 문서와 일치하는지 확인한다.
2. 운영 경로에서 클라이언트가 넣은 전달 헤더를 바꿔 반복 로그인해도 같은 출처로 계수되는지 확인한다.
3. 제한 초과 시 공통 429와 요청 ID, 감사 행의 클라이언트 주소를 확인한다.
4. 결과를 기록하고 이슈 종료를 사용자에게 요청한다.

## 제외 범위

- 다중 인스턴스 공유 저장소, CAPTCHA, 계정 잠금 해제(#119)

## 검증

- 운영 경로 위조 요청 결과 기록
- 재기동 시 계수 초기화는 문서로만 명시된 한계로 유지한다.
