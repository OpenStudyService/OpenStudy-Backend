# BE-114 중복 고객 확인과 수동 병합

- 이슈: [#114 중복 고객 확인과 수동 병합](https://github.com/OpenStudyService/OpenStudy-Backend/issues/114) · M13 · `type:feature`, `layer:controller`, `layer:service`, `layer:persistence`

## 목표

중복이 의심되는 고객을 확인하고, OWNER가 수동으로 병합하되 기존 거래 참조와 병합 이력을 보존한다.

## 작업 단계

1. 마이그레이션: `customers`에 병합 대상·병합됨 상태 칼럼, 병합 이력 테이블.
2. 중복 후보 조회(같은 연락처·이름 등)와 병합 전 두 고객의 구매·결제·이용 이력 비교 조회.
3. 병합 실행(OWNER만): 흡수 고객은 삭제하지 않고 병합됨 상태와 대상 참조를 가진다. 결제·이용권·이용 기록의 고객 참조는 바꾸지 않는다.
4. 이력: 대상·흡수 고객·처리자·시각·사유.
5. 거부: 이미 병합된 고객, 자기 자신과 병합, 동시 병합 중복 처리.
6. 대상 고객의 상세·이력·M9 집계에 흡수 고객 기록을 포함하고, 병합 전후 전체 합계가 같은지 확인한다.
7. 흡수 고객으로 신규 판매·입실을 막고 대상 고객으로 안내한다.

## 제외 범위

- 병합 취소, 자동 병합

## 검증

- HTTP·DB 통합 테스트: 권한, 참조 보존, 집계 합계, 병합 이력, 재병합·자기 병합 거부, 흡수 고객 판매 거부
