# 구버전 문서의 Git 추적 해제

## 1. 배경 / 문제

사용자가 원격 저장소의 불필요한 문서를 정리하고 로컬 파일은 보존하도록 요청했다. 이전 요구사항 기반의 검토용 실행 계획과 선택 전 비교 설명이 현재 기반 설계·이슈와 함께 노출되어 읽는 기준이 모호했다.

## 2. 검토한 선택지

파일을 삭제하는 대신 `git rm --cached`와 경로별 `.gitignore`를 사용해 로컬 보관과 원격 정리를 함께 수행했다. 확정 결정까지 제거하지 않고 기존 선택 기록표와 최신 기반 정책을 유지했다.

## 3. 결정 및 이유

현재 작업의 범위·선행 관계는 foundation 구현 계획과 GitHub 이슈에서 관리하므로 구버전 실행 계획 두 개를 추적하지 않는다. 선택 전 장단점 설명 두 개는 로컬로 보존하고 확정한 선택·이유는 decision-register.md에서 계속 제공한다. 기존 개발 기록과 API/DB 설계·요청된 전달 산출물은 유지한다.

## 4. 구현 내용

Git 추적에서 제외한 파일 4개:

- `docs/OpenStudy_에이전트_개발_실행계획_v1.0.md`
- `docs/OpenStudy_에이전트_개발_실행계획_v1.1.md`
- `docs/design-decisions/01-m1-decisions.md`
- `docs/design-decisions/02-domain-decisions.md`

원래 경로의 파일을 유지하고 작업공간의 `outputs/docs-untracking-2026-10-24/openstudy-backend/`에도 복사했다. 이 경로는 이 작업환경의 보관 위치이며 clone 시 제공되는 산출물이 아니다. 설계 결정 안내를 현재 문서 중심으로 줄이고 선택 기록표의 링크를 갱신했다. 원본 문서의 수정 전 사본도 같은 작업공간의 before-edit/에 보존했다.

## 5. 검증 결과

- 대상 4개의 원래 파일과 별도 보관본이 사전 SHA-256과 일치했다.
- 대상의 Git 추적 해제와 ignore 적용, 수정 Markdown의 로컬 링크, `git diff --check`를 확인했다.
- 변경 범위는 docs와 .gitignore이며 기존 개발 기록을 수정하거나 삭제하지 않았다.
- 실행 코드·DB migration·테스트는 변경하지 않아 앱 빌드와 런타임 테스트는 다시 실행하지 않았다.

## 6. 남은 작업 / 보류 사항

Git 과거 커밋의 문서는 이력으로 유지한다. 이 기록은 구현·검증 결과이며 원격 반영 여부는 해당 정리 PR의 상태를 따른다.
