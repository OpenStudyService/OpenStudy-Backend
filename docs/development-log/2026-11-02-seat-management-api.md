# 2026-11-02 좌석 원장·운영 중단·현황 조회 API

관련: Issue [#61](https://github.com/OpenStudyService/OpenStudy-Backend/issues/61), [계약 문서](../design/foundation/seat-usage-api.md), [ADR-M5-001](../db/ADR-M5-001.md), [M5 계약 기록](2026-10-29-m5-seat-usage-contract.md).

## 1. 배경 / 문제

좌석 화면은 로컬 샘플로만 동작했고 `modules/seat`은 비어 있었다. #60 계약이 병합되어 좌석 목록·상세·등록·수정·운영 중단/재개·배치도·현황 operation 7개를 구현할 수 있게 됐다. 입퇴실(#62)이 아직 없으므로 "사용 중" 판정은 활성 `seat_sessions`가 있을 때 성립하는 계산이어야 하고, 이번 범위는 그 계산과 좌석 원장만 다룬다.

## 2. 검토한 선택지

- **좌석 번호 중복 판정**
  - DB 유니크 제약 위반을 잡아 409로 바꾼다: 제약 이름과 예외 구조에 의존한다.
  - 공통 guard 잠금 안에서 먼저 조회한다: 모든 명령이 guard로 직렬화되어 있어 이쪽을 택했다. 컬럼 collation(`utf8mb4_0900_ai_ci`)으로 비교하므로 `uk_seats_1`과 같은 기준이다. 대소문자만 다른 번호도 중복이다.
- **활성 이용 기록 읽기**
  - 시각 열을 네이티브 쿼리로 읽는다: 시각 타입 변환이 JVM 시간대에 기대게 된다.
  - 읽기 전용 entity `SeatSession`을 둔다: 이쪽을 택했다. 좌석에 필요한 열만 매핑하며, #62가 같은 entity를 확장해 쓰기 가능하게 만든다.
- **권한 값**
  - 기존 `EDIT_PRODUCT`·`MANAGE_PRODUCT`를 재사용한다: 상품 의미라 읽기 어렵고, `NEW_OPERATION`은 운영 중지 지점을 막아 계약("운영 중지 지점도 좌석 등록·수정·상태 변경 허용")과 다르다.
  - `WRITE_SEATS`(operations:write)·`MANAGE_SEATS`(MANAGER + operations:write)를 추가한다: 이쪽을 택했다.
- **감사의 사유 기록**: `AuditEvent.change`에는 사유를 넣을 수 없었다. `reason` 열이 이미 있으므로 사유를 받는 `change` 오버로드를 추가했다. 본문 JSON에 섞지 않았다.
- **샘플의 `/api/seats`**: 업무 때와 같은 이유로 샘플 경로에서 뺐다. 홈·조회용 샘플 데이터의 `seats` 항목은 M9 전까지 둔다.

## 3. 결정 및 이유

- **표시 상태는 저장하지 않고 계산한다.** 활성 이용 기록이 있으면 "사용 중", 없으면 저장 상태(`사용 가능`·`운영 중단`)다. 목록·상세·배치도·현황 모두 같은 기준(`active_seat_id`)을 쓴다.
- **목록 필터와 현황 수치는 `SeatSearchRepository`의 같은 WHERE 조립을 쓴다.** 현황은 지점별로 한 문장의 집계라 네 수치가 같은 기준 시점에서 나온다.
- **배치도 수치는 반환한 좌석에서 직접 센다.** 별도 집계를 하지 않으므로 배치도와 그 수치가 어긋날 수 없다. `kind` 필터는 좌석과 수치에 함께 적용된다.
- **점유율은 `inUse ÷ total × 100`, 소수 첫째 자리 HALF_UP이며 좌석이 없으면 `null`이다.** 운영 중단 좌석은 분모에 포함한다. 33.3, 66.7, 40.0과 0.0(좌석은 있고 이용 없음)을 구분해 확인했다.
- **명령 순서는 입력 검증 → 범위(404) → 잠금 → 권한(403) → version(409) → 도메인 규칙(SEAT_OCCUPIED, DUPLICATE_SEAT_NO)이다.** 범위 밖 좌석이 존재 여부나 version 정보를 드러내지 않게 한다.
- **같은 값의 수정과 같은 상태 요청은 version·감사·알림을 만들지 않는다.**
- **등록은 `Idempotency-Key` 필수, 결과를 24시간 보관한다.** 요청 해시는 지점·구역·번호·유형·상태다. 수정과 상태 변경은 version으로 막고 키를 받지 않는다(계약).
- **알림(`seats`)은 등록·수정·상태 변경마다 좌석 지점으로 보낸다.** `WorkspaceEventService`에 매핑을 추가했다.

계약이 정하지 않아 판단한 점:

- 배치도의 접근할 수 없는(없는 지점 포함) `branchId`는 404다. 목록·현황에서 `scope`로 접근할 수 없는 지점을 지정하면 기존 규칙대로 403이다.
- 좌석 수정에서 `branchId`를 보내면 `status`와 같이 422 `IMMUTABLE_FIELD`다(계약은 `status`만 명시). 그 밖의 모르는 필드는 422 `VALIDATION_FAILED`다.
- 수정 요청에 `version`만 있고 바꿀 필드가 없으면 422다(고객 수정과 같다).
- 등록 시 `status`에 "사용 중"을 주면 422다. 요청에서 보낼 수 있는 값은 `사용 가능`·`운영 중단`뿐이다.
- 목록의 `zone` 필터는 컬럼 collation의 일치(대소문자 무시)다. 빈 값은 422다.

## 4. 구현 내용

- `modules/seat`: entity(`Seat`, `SeatSession` 읽기 모델, 열거형 3개), repository 3개, `SeatService`, `SeatInputs`, `SeatFilters`, `SeatController`, 응답 DTO 6개
- `BranchAction.WRITE_SEATS`·`MANAGE_SEATS`, `AuditEvent.change`(사유 포함 오버로드), `WorkspaceEventService`의 `seats` 매핑
- `LocalPreviewController`: 샘플 경로에서 seats 제거. `LocalPreviewIntegrationTests`는 샘플 자원을 `facilities`로 바꿨다.
- OpenAPI 7개 operation을 `implemented`로 변경하고 `seat-usage-api.md`에 구현 상태를 표기했다.

마이그레이션은 없다(V1 `seats`·`seat_sessions` 그대로).

## 5. 검증 결과

- `./gradlew test` 전체: 47개 suite, 339개 테스트, 실패·오류·건너뜀 0. Testcontainers MySQL 사용. (직전 기록은 46개 suite, 320개였다.)
- 신규 `SeatIntegrationTests` 19개를 HTTP와 DB로 확인했다.
  - 등록: 공백 정리, 감사·알림 기록, 운영 중단 상태로 등록, 번호 중복 409(다른 지점은 허용, 대소문자만 달라도 409), 권한(읽기 직원·다른 지점 직원 403), 입력 검증 422, 멱등 재요청과 키 충돌
  - 수정: 구역·번호·유형 변경과 전후 값 감사, 이용 중 좌석도 수정 가능, `status`·`branchId` 거부, 번호 중복, 같은 값 요청, 버전 충돌의 최신 version·reloadUrl
  - 운영 중단·재개: 직원·권한 없는 점장 403, 점장·사장 허용, 사유·작업자·시각·전후 값 감사, 이용 중 좌석 409(`SEAT_OCCUPIED`, 상태·감사 불변)와 이용 종료 뒤 성공, 같은 상태 요청, 입력 검증, 운영 중지 지점에서의 허용
  - 조회: 활성 이용 기록으로 "사용 중"과 `activeSession`(고객 최소 정보 3개), 종료된 기록은 "사용 가능", 구역·좌석 번호·id 순서와 유형·구역·상태 필터, 페이지, 범위 밖 지점(목록 제외, 상세 404, 지정 scope 403)
  - 현황: 4/10 → 40.0, 1/3 → 33.3, 2/3 → 66.7, 좌석 없음 → 0과 null, 좌석 있고 이용 없음 → 0.0, 운영 중단이 분모에 포함, 합계 = 전체, `scope=all` 지점 id 순서
  - 배치도: 120개를 넘는 좌석 전체 반환(페이지 없음), 구역별 묶음과 순서, 수치가 현황과 일치, `kind` 필터가 좌석과 수치에 함께 적용, 범위 밖·없는 지점 404, 파라미터 검증 422
- 이용 기록은 입실 API가 없어 테스트가 DB에 직접 넣었다. 이용권·결제 연쇄를 만들지 않으려고 그 insert 한 문장 동안만 같은 연결에서 외래 키 검사를 껐다. 이 fixture는 #62에서 실제 입실 흐름으로 바꿔야 한다.

**실행하지 않은 것**

- 실제 서버 실행과 Frontend 연결. Frontend는 샘플 경로·입력 모양이라 계약에 맞춰야 한다.
- 두 사용자의 동시 요청 경합 테스트. 명령은 공통 guard 잠금으로 직렬화되며, 별도 동시성 테스트는 추가하지 않았다. 입실과 운영 중단의 경합은 입실 API(#62)가 생긴 뒤 검증해야 한다.
- 인프라 서버 검증.

## 6. 남은 작업 / 보류 사항

- #62: 입실·퇴실 구현 시 `SeatSession` entity를 확장하고, 좌석 행 잠금 순서와 운영 중단의 `SEAT_OCCUPIED` 확인이 맞물리는지 동시성 테스트로 확인한다.
- 좌석 번호 정렬은 문자열 비교라 `A-10`이 `A-2`보다 앞에 온다(계약에 명시). 자연 정렬이 필요하면 번호 체계를 맞추거나 정렬 열을 추가해야 한다.
- 점유 추이 분석은 M13, 자유 배치 좌표는 스키마 변경이 필요해 범위 밖이다.
- 홈(M9)의 좌석 수치와 `local-preview`의 `seats` 샘플은 아직 샘플이다.
