# 2026-11-10 M14 계정 복구·프로필 사진·감사 조회 API 계약 (#118)

## 1. 배경 / 문제

- M14 기능(비밀번호 변경·관리자 초기화, 프로필 사진, 감사 로그 검색)의 API 설계가 없었다.
- Backend #119·#120·#122와 Frontend #43·#45가 같은 계약으로 병행하려면 먼저 계약을 확정해야 했다.
- 정책은 ADR-M14-001(#117)에 있었다. 다만 계약을 쓰려면 정해야 하는데 ADR에 없는 항목이 네 가지 있었다.
  - 관리자 초기화 뒤 기존 비밀번호를 언제 무효로 하는지
  - 감사 검색의 기본 기간과 최대 기간
  - 사진 조회 방식(앱 경유 또는 서명 URL)
  - 다른 직원 사진의 열람 범위
- 1:1 대화·채팅 스트림(M14-D07·D08)은 ADR-M10-002로 범위에서 빠져 이번 계약에 넣지 않았다.

## 2. 검토한 선택지

| 항목 | 선택지 | 결과 |
| --- | --- | --- |
| 초기화 후 기존 비밀번호 | 요청 즉시 무효 / 새 비밀번호를 정할 때 무효 | 요청 즉시 무효(M14-D11) |
| 감사 검색 기간 | 기본 7일·최대 92일 / 기본 30일·최대 366일 | 기본 7일·최대 92일(M14-D12) |
| 사진 조회 | 앱 경유 / 짧은 만료 서명 URL | 앱 경유(M14-D13) |
| 사진 열람 범위 | 지점 공유 직원과 OWNER / 모든 활성 직원 | 지점 공유 직원과 OWNER(M14-D14) |

- 2026-11-10 사용자에게 네 항목을 물었고, 모두 권장안으로 결정받았다.

## 3. 결정 및 이유

- **M14-D11**: 초기화는 주로 유출 대응이다. 세션만 끊고 기존 비밀번호를 남기면 유출된 비밀번호로 다시 로그인할 수 있다.
  - 대가: 메일 발송이 끝내 실패하면 직원은 관리자가 다시 요청할 때까지 로그인할 수 없다. 계약에 이 점을 적었다.
- **M14-D12**: 무제한 조회를 막으면서 분기 단위 확인은 한 번에 할 수 있게 했다.
- **M14-D13**: 요청마다 권한을 확인할 수 있고, S3와 로컬 대체 저장소가 같은 방식으로 동작한다.
- **M14-D14**: 함께 일하는 사람에게만 얼굴을 보인다.

사용자 결정 없이 계약에서 정한 세부 사항은 다음과 같다. 모두 ADR 범위 안의 구현 기준이며, 리뷰에서 조정할 수 있다.

- **본인 변경의 기존 비밀번호 확인 실패**: 로그인 계정 기준 제한에 집계한다. 열린 세션을 얻은 사람이 기존 비밀번호를 대입해 볼 수 없게 하기 위해서다.
- **새 비밀번호가 기존과 같은 경우**: 422 `PASSWORD_SAME_AS_CURRENT`로 막는다.
- **관리자 초기화의 대상**
  - 본인은 대상이 될 수 없다(403 `SELF_RESET_FORBIDDEN`, 본인은 변경 API를 쓴다).
  - 대상 상태가 `활성`이 아니면 409 `INVALID_STATE`다.
- **재설정 토큰**
  - 초대 메일과 같은 claim 구조를 쓴다.
  - 링크 fragment(`#token=`)로 전달하고 본문으로 제출한다. 서버·프록시 로그에 토큰이 남지 않게 하기 위해서다.
- **잠금 해제**
  - 권한은 초기화와 같다(ADR M14-D06에 권한이 없어 D05를 따랐다).
  - 잠금 상태를 조회하는 API는 두지 않고, 응답의 `wasLocked`로 알린다.
- **사진 업로드·삭제**
  - 계정 version을 올리되 요청에 version을 받지 않는다. 사진은 본인만 바꾸므로 마지막 요청이 남는다.
  - 크기 초과도 413이 아니라 422로 답한다.
- **`SessionUser.avatar`·`Employee.avatar`**
  - 지금은 `avatar_url` 원값을 그대로 응답한다. 저장소 키가 나가지 않도록 앱 경유 경로로 바꾼다.
  - 구현된 schema이므로 M13과 같이 `x-planned-changes`에 두고 #120이 옮긴다.
- **감사 상세의 민감 값**: 쓸 때 이미 빼지만, 조회 때 키 이름 기준으로 한 번 더 가린다(비밀값은 `***`, 연락처는 끝 네 자리).

- `docs/design/foundation/account-collab-api.md`: 계약 문서. 엔드포인트, DTO, 판정 순서, 오류 코드, 권한, 감사 기록, 한계를 담았다.

- `docs/design/foundation/README.md`: M14 계약 안내를 추가했다.
- `src/test/java/com/openstudy/architecture/AccountContractTests.java`
  - 인수 조건 1: operation·오류 응답·문서화
  - 인수 조건 2: 응답 schema에 비밀번호·토큰·저장소 키 필드가 없음
  - 인수 조건 3: 권한이 ADR과 일치
