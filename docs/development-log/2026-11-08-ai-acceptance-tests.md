# 2026-11-08 M10 인수 조건 일반 테스트 보강 (#93~#96)

## 1. 배경 / 문제

- #93~#96을 닫으려고 인수 조건을 대조했지만, 상당수가 **로컬 전용 테스트**(별도 MySQL 3307의 데모 DB, `@EnabledIf localAiTestsEnabled`)에만 있었다. 평소 실행하는 전체 테스트에서는 건너뛴다.
- 테스트가 아예 없는 조건도 있었다.
  - 모델에 보내는 내용(#93)
  - 429(#96)
  - 진단 로그 필드와 원문 정제(#96)
  - 모델 실패 처리(#96)
  - ViewSpec 바인딩 거부(#95)
  - M9 수치 동등성(#95)
- 각 이슈에 남긴 근거 현황 댓글(2026-11-08)의 "남은 일"을 일반 테스트(Testcontainers)로 옮겼다.

## 2. 검토한 선택지

- **로컬 전용 테스트를 그대로 켜기**: 데모 DB와 데모 데이터가 필요해 일반 실행에 넣을 수 없다.
- **같은 조건을 Testcontainers 픽스처로 다시 쓰기(선택)**: 데모 데이터 없이 조건 자체를 확인한다.
- **모델 전송 내용 확인 방법**
  - 실제 모델 호출: 키와 비용이 필요하고 결과가 바뀐다.
  - 로컬 HTTP 대역 서버(선택): live 모드에서 요청 본문을 가로채고 응답(정상·500·깨진 JSON)을 고를 수 있다.

## 3. 결정 및 이유

- 공통 픽스처(`AiTestSupport`)를 두고 이슈 조건별로 테스트를 나눴다.
- 권한 없는 직원(`ai:read` 없음)의 질문은 AI 서비스보다 앞의 API 권한 검사에서 403(`FORBIDDEN`)으로 막힌다. "실행 전에 거부"라는 조건은 충족하므로 그대로 확인했다.
- **M9 수치 동등성 테스트에서 버그를 찾았다.** 이 PR에는 넣지 않았다(아래 6절).

## 4. 구현 내용

- `AiTestSupport`(신규): 직원·지점·권한·로그인·질문 픽스처와 정리
- `AiQuestionGuardIntegrationTests`(4개, #94·#96)
  - 빈 질문과 501자는 400이고, 500자는 길이 오류가 아니다. `ai:read`가 없으면 403이다. 실행된 기록은 없다.
  - 스크립트(`REJECT_ARBITRARY_HTML`), SQL(`REJECT_RAW_SQL`), 변경 의도(`UNSUPPORTED_MODIFICATION_INTENT`)는 400이다. 결제 행 수가 그대로다.
  - "최근 3년"은 `DATE_RANGE_LIMIT_EXCEEDED`이고, 1,001행 요청은 `ROW_LIMIT_CLAMPED`로 1,000행에서 잘린다.
  - 진단 로그
    - 요청 ID·실행 ID·상태·단계(accepted~completed)·범위·판정·소요 시간이 남는다.
    - 원문의 `token=…`과 전화번호는 `[REDACTED]`로 바뀐다.
    - 보관 기한은 생성 후 30일이다.
- `AiRateLimitIntegrationTests`(1개, #96): 분당 2회 설정에서 세 번째 질문은 429·`Retry-After: 60`이다. 실행은 2건이고, 다른 직원은 영향받지 않는다.
- `AiModelBoundaryIntegrationTests`(2개, #93·#96, live 모드 + 로컬 대역 서버)
  - 모델에 가는 내용은 시스템 프롬프트 + `scope / retrievedCandidates / question` 세 줄뿐이다. 고객 이름·전화번호·결과 행·인증 정보가 없다.
  - 모델 응답 스키마의 분석 ID는 등록 분석 enum이다.
  - 모델이 500이나 깨진 JSON을 돌려줘도 응답은 5xx가 아니고, 규칙 판정으로 처리된다. 결제 데이터는 그대로다.
- `AiViewBindingTests`(3개, #95): 등록 분석이 쓰는 `ViewBinder`가 결과에 없는 필드와 등록되지 않은 컴포넌트를 렌더링 전에 거부한다.

## 6. 남은 작업 / 보류 사항

- **발견한 버그(#95 핵심 조건)**
  - AI 매출 분석(POC-001·007·008)은 M9 매출 API(`SalesRevenueService`)가 아니라 이식된 `SalesAggregationService`를 쓴다.
  - 이 서비스는 결제를 **승인 시각이 아니라 행 생성 시각(`createdAt`)으로** 거른다.
  - aggregation-api.md 계산 예시로 재현했다. AI의 11월 지점 1 승인액은 63,000원(10월 31일 결제 포함), M9 API는 53,000원이었다. 지점 2도 12월 1일 결제 9,000원이 11월에 들어갔다. 테스트 데이터의 행이 모두 실행 당일에 생성됐기 때문이다.
  - M10-D05("자연어 결과의 수치는 M9 공통 집계를 같은 조건 객체로 호출해 계산한다")에 어긋난다.
  - 수정은 AI 매출 분석을 M9 서비스 호출로 바꾸는 별도 작업이다. 그 PR에 동등성 테스트(`AiSalesEquivalenceIntegrationTests`)를 함께 넣는다.
- 위 수정 전까지 #95는 닫을 수 없다. #93·#94·#96은 이 PR 병합 후 근거와 함께 닫을 수 있다.
