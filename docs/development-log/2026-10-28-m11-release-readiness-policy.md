# 2026-10-28 M11 보존 기간 미정 상태의 파기 구조·인프라 작업 관리·기존 검증 이슈·관측 방식 정책 확정

## 1. 배경 / 문제

M11(릴리스 검증·운영 준비) 이슈를 작성하려고 SRS v1.8의 M11 요구사항 10개와 기존 이슈를 확인했다.

- 개인정보·감사 이벤트·백업의 보존 기간이 모두 미정이고, POL-02·03은 임의 기간 적용을 금지한다.
- 이미 Backend #10·#18·#29, Infra #1·#2가 M11 범위의 일부(HTTPS 쿠키·CSRF·SSE, 마이그레이션 인계, 실행 이미지, 흐름 검증)를 다룬다. Infra 저장소에는 M1 마일스톤만 있다.
- 지표·로그 수집 방식이 정해지지 않았다. Actuator 의존성은 이미 있다.

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 보존 기간 | 규칙 구조만 만들고 기간은 별도 결정 / 지금 기간 확정 |
| 인프라 작업 | Infra 저장소에 M11 마일스톤과 이슈 등록 / Backend 이슈에만 적기 |
| 기존 이슈 | 그대로 두고 M11에서 참조 / M11 마일스톤으로 이동 |
| 관측 방식 | Actuator + JSON 로그 + CloudWatch / Prometheus·Grafana 추가 |

## 3. 결정 및 이유

사용자가 결정했다. 상세는 [ADR-M11-001](../db/ADR-M11-001.md)에 있다.

- 파기·정리 규칙은 구조만 만들고 기간이 정해질 때까지 비활성으로 둔다. 기간 확정은 별도 결정 이슈로 관리한다.
- 인프라 작업은 Backend 이슈에 요청 사항으로 적고 인프라 팀원에게는 메시지로 전달한다. 사용자가 권장안(Infra 저장소 등록) 대신 이 방식을 골랐다.
- 기존 검증 이슈는 그대로 두고 M11 이슈가 참조한다.
- 관측은 Actuator·JSON 로그·CloudWatch로 한다.
- 익명화 방식, Playwright 회귀, live 빌드 번들 검사, 보안 헤더 위치(M11-D05~D08)는 SRS와 V1에서 도출한 구현 기준으로 함께 기록했다.

## 4. 구현 내용

- `docs/db/ADR-M11-001.md`: M11-D01~D08을 기록했다.
- 저장소 밖 변경(이 커밋에 포함하지 않음): 작업공간 SRS를 v1.9로 만들었다. POL-31~34를 추가하고 FR-MEM-09, FR-AUD-05, NFR-OPS-05, NFR-PERF-08을 갱신했다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 `customers`·`audit_events` DDL, `build.gradle`의 Actuator 의존성, Frontend `package.json`의 Playwright, 기존 이슈 체크리스트를 읽어 결정과 맞는지 확인했다.

## 6. 남은 작업 / 보류 사항

- 개인정보·감사 이벤트·백업 보존 기간은 별도 결정 이슈에서 근거를 확인해 정한다.
- 인프라 팀원에게 M11 인프라 요청 사항을 전달해야 한다.
