# 2026-10-28 M7 업무·문의·시설 점검·공지·채널 권한 정책 확정

## 1. 배경 / 문제

M7(업무·채널·현장 협업) 이슈를 작성하려고 SRS v1.4와 V1 스키마를 대조했다. 테이블은 모두 있고 관련 모듈 코드는 비어 있다. 다음이 정해지지 않았다.

- 업무·문의에 대응하는 권한 코드가 없다. 기본 직원 프리셋에는 권한이 하나도 없어, 권한 코드를 요구하면 일반 직원이 업무·문의를 처리할 수 없다.
- SRS는 시설 점검 항목에 담당자·처리 상태를 요구하지만, V1 `facilities`에는 담당자 컬럼이 없고 `facility_works`에 담당자와 진행 상태가 있다.
- "전체 공지를 작성할 수 있는 권한"과 전체 채널 관리자가 정해지지 않았다.

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 업무 권한 | 지점 직원 등록 + 관련자 수정 / 새 권한 `tasks:write` |
| 문의 권한 | 지점 직원 누구나 / `members:write` 보유자 |
| 시설 담당 | 진행 중인 점검 작업에 둔다 / 시설에 담당자 컬럼 추가(마이그레이션) |
| 전체 공지·채널 | OWNER만 / OWNER + 모든 지점 `notices:write` 보유자 |

## 3. 결정 및 이유

사용자가 모두 권장안을 선택했다. 상세는 [ADR-M7-001](../db/ADR-M7-001.md)에 있다.

- 업무는 지점 직원이 등록하고 등록자·담당자·MANAGER 이상이 수정한다. 현장 협업을 막지 않으면서 다른 직원의 업무를 임의로 바꾸지 못하게 한다.
- 문의는 지점 직원 누구나 등록·답변한다. 고객 조회 범위는 M4·M5 기준을 그대로 쓴다.
- 시설 담당자·처리 상태는 열린 점검 작업에 둔다. 스키마 변경이 없다.
- 전체 공지와 전체 채널은 OWNER만 만든다.
- 시설 권한 매핑, 다음 점검일 계산, 채널 참여 자격과 권한 회수(M7-D05~D07)는 SRS 문구와 V1 스키마에서 도출한 구현 기준으로 함께 기록했다.

## 4. 구현 내용

- `docs/db/ADR-M7-001.md`: M7-D01~D07을 기록했다.
- 저장소 밖 변경(이 커밋에 포함하지 않음): 작업공간 SRS를 v1.5로 만들었다. POL-15~18을 추가하고 FR-TASK-02·03, FR-INQ-02, FR-FAC-01, FR-NOTI-02를 갱신했다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 DDL과 권한 정의·프리셋 시드를 읽어 결정과 맞는지 확인했다.

## 6. 남은 작업 / 보류 사항

- DM과 채팅 실시간 전송은 M14 범위다.
- 홈 화면 수치(업무·문의·점검)는 M7에서 같은 집계 API를 제공하고, 홈 화면 구성은 M9(FR-DASH-02·03·05·06)에서 다룬다.
