# GitHub 이슈 참조 통일과 상품 삭제 정책 정합성 정리

- 날짜: 2026-10-26
- 범위: OpenStudy-Backend, OpenStudy-Frontend의 이슈 메타데이터 및 기반 설계 문서
- 정본 정책: 검토 완료 SRS v1.1 (작업공간의 요구사항 명세 및 마일스톤 계획)

## 배경과 문제

기존 개발 작업은 `[B01]`, `[F01]`, `[V01]` 접두사로 작업 ID를 표현했고, 추가 M1 이슈는 `[M1]`을 제목에 사용했다. 이 체계는 고유 GitHub 번호 및 Milestone과 역할이 겹치고, 마일스톤 이동 후 제목 불일치를 만들 수 있다.

기반 설계의 과거 Q8은 거래가 없는 상품의 조건부 물리 삭제를 허용했지만, SRS v1.1 확정 정책은 **상품 물리 삭제 미제공, 판매 중지·재개로 운영, 기존 거래·변경 이력 보존**이다. 이전 설계의 DELETE 계약·인수 조건을 남겨 두면 추후 잘못된 기능을 구현할 수 있다.

## 검토한 방식과 결정

- 이슈 제목은 작업 내용만 표시한다. 같은 저장소 의존성은 GitHub `#번호`, 교차 저장소는 `owner/repo#번호`나 링크를 사용한다. Milestone, 유형, 상태는 GitHub 기능으로 관리한다.
- 초기 개발 단위 B/F/V가 남아 있는 **과거 개발·검증 기록은 삭제하지 않는다.** 현재 사용 중인 이슈 본문과 기반 설계의 참조만 정리한다.
- 과거 Q8의 존재 자체는 삭제하지 않고 '현재 폐기된 결정'임을 표시한다. 상품 및 거래 DB의 구조나 이전 마이그레이션을 이 문서 작업에 맞춰 소급 변경하지 않는다.
- Backend·Frontend의 이슈와 문서만 수정한다. Infra 저장소에는 변경하지 않는다.

## 반영 내용

- Backend 이슈 #7~#18, #27~#29의 제목 접두사와 기존 B/F/V 작업 참조 변경.
- Frontend 이슈 #4~#7, #13의 제목 접두사와 작업 참조 변경.
- Backend #16, Frontend #7에서 조건부 물리 삭제 인수·검증 항목을 제거하고 판매 중지·재개/기록 보존으로 교체.
- 완료된 Backend #8의 Q8 설명은 당시의 설계 이력으로 유지하고, SRS v1.1 우선 정책 안내 추가.
- 기반 설계의 결정 문서, API 설명, DB 설명, 요구사항 추적, 개발 계획, README와 OpenAPI에서 신규 상품 DELETE 계약 제거.
- OpenAPI 버전은 `0.1.4-product-retention`으로 변경. 이 버전은 문서상 목표 계약이며 상품 관리 API 구현·DB 마이그레이션의 완료를 의미하지 않는다.

## 검증 및 미완료 항목

- GitHub 이슈 쓰기 작업의 성공 응답을 확인했다. 이슈 번호·상태·마일스톤·라벨은 수정 요청 대상에서 제외했다.
- OpenAPI JSON 재직렬화·JSON 파싱 및 `DELETE /products/{id}` 제거 여부를 확인했다.
- 이 변경은 이슈·설계 문서 수정이므로 애플리케이션 테스트, 프론트 빌드, 운영 통합 시험은 실행하지 않았다.
- **미완료:** `docs/design/foundation/OpenStudy-Foundation-API.xlsx`는 기존 `0.1.3-profile` 동기화본이다. 현 OpenAPI `0.1.4-product-retention`의 삭제 정책과 표기를 다시 맞춰야 한다. 동기화 전에는 OpenAPI JSON을 최신 기준으로 사용한다.
- **후속 검토:** 기존 Flyway V2/V3의 `DELETED` enum과 nullable 상품 revision 참조는 조건부 삭제를 고려한 스키마 흔적이다. 무리하게 변경하지 않고 별도 DB 설계·마이그레이션에서 유지 필요성을 결정한다.
- 기존 상품 API 코드 및 UI의 신규 삭제 동작은 이 작업에서 구현하거나 제거했다고 주장하지 않는다. 구현 착수 시 Backend #16·Frontend #7의 현행 인수 조건으로 검증한다.
