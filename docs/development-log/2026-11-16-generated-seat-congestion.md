# 2026-11-16 요일·시간대 혼잡도를 LLM 생성 경로(QuerySpec·ViewSpec)로 조회

## 1. 배경 / 문제

- 사용자 요청(2026-11-16): 요일·시간대 혼잡도 질문("강남점은 언제 가장 붐벼?")을 LLM 호출로 만든 QuerySpec·ViewSpec으로 조회한다.
- 기존에는 키워드 규칙("붐벼·혼잡·피크")이 등록 분석 POC-002를 골랐다.
  - POC-002는 Java 코드로 혼잡도를 계산하고, 화면 명세도 고정이다.
  - 계산 방식: 날짜마다 9·12·15·18·21시에 이용 중인 좌석 수를 세어 가용 좌석 수로 나눈다.
- 생성 경로 엔진은 필드를 엔티티 속성에 그대로 연결한다. 그래서 다음을 표현할 수 없었다.
  - 시각에서 요일·시를 뽑는 차원
  - "특정 시각에 이용 중" 같은 구간 판정

## 2. 검토한 선택지

- **등록 분석 호출형**
  - LLM이 POC-002와 지점·기간을 고르면, 엔진이 `REGISTERED_ANALYSIS` QuerySpec으로 실행한다.
  - 수치는 그대로 유지되지만, 계산은 여전히 분석 코드에 묶인다.
- **범용 집계형(채택)**
  - 좌석 점유 샘플을 DB 뷰로 만들고, 요일·시간대 차원과 점유율 지표를 카탈로그에 추가한다.
  - LLM이 지표·차원을 고르면 서버가 AGGREGATE QuerySpec과 히트맵 ViewSpec을 만든다.
  - 사용자가 이 방식을 선택했다(2026-11-16).

## 3. 결정 및 이유

- **샘플 원천은 뷰**(V20 `seat_occupancy_samples`)
  - 저장 테이블과 수집 작업 없이 입퇴실 기록을 바로 반영한다. POC-002와 정의가 같다(입실 ≤ 샘플 시각 < 퇴실, 미퇴실 포함, 가용 좌석은 현재 AVAILABLE 수).
  - 지점마다 최근 371일 × 5개 시각을 만든다. 생성 경로의 기간 상한(366일)을 덮는다.
- **점유율 지표** `seats.occupancy_pct` = 샘플별 점유율의 평균(AVG).
  - 한 지점에서는 가용 좌석 수가 일정하다. 그래서 POC-002의 "이용 좌석 샘플 합 ÷ (좌석 수 × 샘플 수)"와 같다.
  - 여러 지점이면 지점 간 단순 평균이 된다.
- **질문 해석은 서버가 한다**(의도 분석기)
  - "붐벼·붐비·혼잡·점유율·피크"는 이 지표로 읽는다.
  - "요일"은 요일 차원, "시간대·시간별·몇 시"는 시간대 차원, "언제"는 두 차원 모두로 읽는다.
  - 기간을 말하지 않으면 POC-002처럼 지난 2주를 쓴다.
- **경로**
  - live 모델이 있으면 이 질문은 키워드 규칙과 등록 분석 선택기를 건너뛰고 생성 경로로 간다.
  - live 모델이 없으면(playback) 기존 POC-002가 답한다.
  - "지금·현재·실시간"이 들어간 질문은 실시간 분석(POC-004)에 남긴다.
- **화면**
  - 질문이 화면 표현을 말하지 않으면 모델의 선택은 쓰지 않는다(기존 원칙).
  - 대신 서버 기본값에 "차원 2개 × 지표 1개 → 히트맵 + 표"를 추가했다.
  - 두 차원이 모두 정수라 열 타입만으로는 축을 정할 수 없다. 히트맵만 열 순서(요일 → 시간대 → 지표)로 바인딩한다.
  - 기본 히트맵 조회는 격자 전체(35칸)가 필요하다. 그래서 기본 행 수를 10 대신 50(엔진 상한)으로 둔다.

## 4. 구현 내용

- `V20__seat_occupancy_samples.sql`: 좌석 점유 샘플 뷰.
- `SeatOccupancySample`: 뷰 엔티티(`@Immutable`)와 의미 카탈로그 애노테이션. 지점 행 범위 정책을 적용한다.
- `OpenStudyCatalogConfiguration`
  - 원천 `seat_occupancy_sample`과 지표 `seats.occupancy_pct`(단위 %, 소수 1자리)를 등록했다.
  - 기간 필드와 용어를 추가했다.
  - 생성 경로 우선 지표 목록(`GENERATION_FIRST_METRICS`)을 만들었다.
- `OpenStudyIntentAnalyzer`: 요일·시간대 묶음과 혼잡도 기본 기간(지난 2주).
- `AiGenerationService.firstFor`, `AiWorkspaceService`, `OpenStudyPlaybackGateway`
  - live 모델이 있고 생성 경로 우선 지표인 질문은 키워드 규칙과 선택기를 거치지 않는다.
  - 결과 영역은 `seats`로 기록한다.
- 엔진
  - `ComponentCatalog`: 생성 컴포넌트 `Heatmap`(category·series·value)을 추가했다.
  - `PlanCompiler`: 기본 히트맵, 히트맵 열 순서 바인딩, 기본 히트맵의 50행 조회.
  - 배치는 기존 규칙(`ViewLayouts`)을 그대로 쓴다. 히트맵과 표가 좌우로 놓인다.

### 외부 모델 응답 재생으로 찾은 문제와 수정

실제 Qwen 대신, 서버가 Qwen에 보내는 요청을 그대로 추출해(시험 `exportsTheRequestTheServerSendsQwen`, opt-in) 사용자가 ChatGPT에 전달했다. 받은 답을 모델 응답 자리에 재생했다(`OPENSTUDY_AI_RECORDED_PLAN`). ChatGPT는 Qwen과 다른 모델이므로 확인되는 것은 서버 처리이고, Qwen의 응답 품질은 아니다.

| 회차 | 모델의 답 | 서버 결과 | 조치 |
|---|---|---|---|
| 1 | "질문이 없다"는 확인 요청 | 해당 없음 | 사용자 메시지가 ChatGPT에 전달되지 않음. 붙여 넣기 방식 안내 |
| 2 | UNSUPPORTED: "강남점을 거를 승인된 필드가 없다" | "등록 분석 지표를 찾지 못했습니다" | 아래 1·2 |
| 3 | READY: 점유율 × 요일·시간대, 지난 2주. 근거 없이 점유율 내림차순·limit 1 추가 | 근거 검증 실패로 생성 경로 거절 → POC-002가 대신 답함 | 아래 3. 수정 후 생성 경로, 35칸 POC-002와 일치 |

1. **모델용 질문에서 지점 이름을 중립 표현으로**
   - 지점 범위는 서버가 정한다(M10: 모델은 범위를 정하지 않는다). 그런데 질문에 지점 이름이 남아 있으면 모델이 지점 필터 근거를 찾다가 거절한다.
   - 그래서 서버가 인식한 지점 이름을 "선택 지점"으로 바꿔 모델에 보낸다(`OpenStudyUserContextResolver.withoutBranchNames`).
   - 저장되는 질문과 화면 제목은 원래 질문이다. 지점을 말하는 매출 생성 질문에도 같이 적용된다.
2. **생성 경로가 답하지 못하면 POC-002**: 혼잡도 질문에서 모델이 거절하면 등록 분석으로 다시 계획해 답한다.
3. **근거 없는 순위의 행 수 제한도 버림**
   - 컴파일러는 이미 질문이 요구하지 않은 모델의 정렬을 버렸다. 그런데 그 정렬에 딸린 limit은 남겨 두어서, 근거 검증에서 계획 전체가 거절됐다.
   - 이제 정렬을 버릴 때 page·size·limit과 그 근거 항목도 함께 버린다. 정렬 없는 "첫 N행"은 임의로 자른 결과이기 때문이다.
   - 피크는 히트맵이 강조한다. POC-002가 답하던 방식과 같다.

### 전체 구축 SQL 추출과 뷰

- 추출 시험이 모든 객체를 `SHOW CREATE TABLE`로 내보내 뷰가 `null`로 들어갔다.
  - 표만 이 방식으로 내보내고, 뷰는 `SHOW CREATE VIEW`로 표 뒤에 붙인다.
  - 뷰를 만든 계정(DEFINER) 절은 지운다.
- MySQL은 별칭 없는 CTE 식에 식 전체를 열 이름으로 붙인다. 그래서 다시 출력한 뷰 정의가 64자 이름 제한에 걸렸다. V20의 모든 식에 짧은 별칭을 붙였다.

  - ChatGPT 3회차 답 원문을 재생해도 통과한다(`OPENSTUDY_AI_RECORDED_PLAN`, 수동 실행).
  - "○○점은 언제 가장 붐벼?"

    - ViewSpec은 히트맵(d0·d1·m0)과 표가 split으로 놓인다.
    - 35칸 모두 같은 입퇴실 기록의 POC-002 결과와 같다.
  - live 모델이 없으면 POC-002가 답한다.
  - "지금 ○○점에 빈자리가 얼마나 있어?"는 POC-004로 간다.
- AI·DomainLens 모듈과 AI 매출 대조 시험: 132개 중 실패 0, 건너뜀 26(기존 opt-in 시험).

  - 대화 다시 열기 시험은 새 계획 메서드(7번째 인자)로 호출 수를 센다.

## 6. 남은 작업 / 보류 사항

- **실제 Qwen 확인**: 모델이 같은 계획을 내는지 확인해야 한다. 서버가 의도 분석으로 지표·차원·기간을 정하므로 모델의 역할은 그 선택을 계획으로 내는 것이다.
- **뷰 성능**: 뷰는 조회할 때마다 모든 지점의 371일치 샘플을 계산한다. 지점과 입퇴실 기록이 많아지면 샘플 테이블과 주기 수집으로 바꾸는 것을 검토한다.
- **결과 범위**
  - 생성 결과의 요일은 1~7 숫자다. 히트맵은 이름으로 표시한다.
  - 히트맵 기본 조회는 50칸까지다. 지금은 7요일 × 5시각 = 35칸이다.
- **등록 분석 POC-002**: playback 모드와 저장된 대화의 다시 실행에 남겨 두었다.
