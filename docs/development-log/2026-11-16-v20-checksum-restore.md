# 2026-11-16 V20 체크섬 불일치: V20 복원과 V21 추가

## 1. 배경 / 문제

- 로컬 DB(`localhost:3306/openstudy`, MySQL 8.0.46)로 Spring Boot를 실행하자 Flyway가 V20 체크섬 불일치로 기동을 멈췄다.
  - DB의 체크섬: `513928538`
  - 파일의 체크섬: `590005157`

## 2. 원인

- `flyway_schema_history`에 V20이 체크섬 `513928538`, 적용 시각 2026-11-16 11:44:41로 기록돼 있었다. DB의 뷰 정의에는 CTE 식 전체가 열 이름으로 붙어 있었다(별칭 없음).
- V20은 같은 날 혼잡도 작업 중 두 번 쓰였다.
  1. 11:40쯤 처음 작성: CTE 식에 별칭 없음 → Flyway 체크섬 `513928538`
  2. 12:20쯤 수정: 전체 구축 SQL 추출이 뷰 정의의 64자 열 이름 제한에 걸려 CTE 식에 짧은 별칭을 붙임 → `590005157`. 이 버전만 커밋(`1c51d26`)·병합(PR #241)됐다.
- 두 시각 사이에 같은 폴더에서 Spring Boot가 실행되어, 커밋되지 않은 첫 버전이 로컬 DB에 적용됐다.
  - 체크섬 확인: 수정 세 곳을 되돌린 내용을 Flyway 방식(줄 단위 CRC32)으로 계산하면 `513928538`로 DB와 정확히 같다.
- 근본 원인: 적용될 수 있는 작업 폴더에서 마이그레이션 파일을 작성 후 다시 고쳤다.
- 두 버전의 뷰는 CTE 안쪽 열 이름만 다르다. 뷰가 내보내는 열과 데이터는 같다(로컬 12,964행).

## 3. 검토한 선택지

- **로컬 DB만 맞추기**: 병합된 V20을 기준으로 로컬 뷰를 다시 만들고 `flyway repair`로 체크섬 한 행을 맞춘다.
  - 이미 main을 적용한 DB에는 영향이 없다.
  - 대신 repair가 필요하다.
- **V20 복원 + V21 추가(채택, 사용자 결정)**: V20을 로컬 DB에 적용된 내용으로 되돌리고, 별칭을 붙인 뷰는 V21이 `CREATE OR REPLACE VIEW`로 교체한다.
  - repair·체크섬 수정·초기화 없이 로컬 DB가 검증을 통과하고, V21만 추가로 적용된다.
  - 대신 병합된 V20(`590005157`)을 이미 적용한 DB가 있으면 그쪽이 같은 불일치를 겪는다.

## 4. 구현 내용

- `V20__seat_occupancy_samples.sql`: 별칭 없는 첫 내용으로 복원했다. 체크섬 `513928538`을 계산으로 확인했다.
- `V21__seat_occupancy_samples_short_aliases.sql`: 같은 뷰를 CTE 별칭과 함께 `CREATE OR REPLACE VIEW`로 다시 만든다. 열과 데이터는 같다.
- 마이그레이션 시험 기대값을 V21 기준으로 바꿨다(실행 개수, 버전 목록, OWNER 초기화의 최신 버전).
- 전체 구축 SQL을 V21 기준으로 다시 추출했다(`docs/db/schema-full.sql`, `docs/db/README.md`).

## 5. 검증 결과

- **체크섬 계산**(Flyway 방식): V20 파일 `513928538`, V21 파일 `2110769407`. 모두 로컬 DB 이력과 같다.
- `./gradlew slowTest`(마이그레이션·OWNER 초기화): 통과. 빈 DB에서 V1~V21을 적용하고, 전체 구축 SQL을 추출·복원 검증했다.
- **로컬 DB로 Spring Boot 실행**(`bootRun`, 포트 18080)
  - "Successfully validated 21 migrations"
  - 현재 버전 21
  - 정상 기동(14.5초)
- **로컬 DB 상태**
  - V21이 적용돼 있다. 적용 시각은 13:43:41로 제 확인 실행(13:48) 전이다. 같은 폴더에서 실행된 다른 앱 프로세스가 적용한 것으로 보인다. V21 파일은 13:39에 만든 뒤 바뀌지 않았다.
  - 뷰 정의에 짧은 별칭(`AS day_kst`)이 들어 있다.
  - 샘플 12,964행은 V21 전과 같다.
- repair, 체크섬 직접 수정, DB 초기화는 하지 않았다.
- 실행하지 않은 검증: 전체 테스트(`./gradlew test`)

## 6. 남은 작업 / 보류 사항

- 병합된 V20(`590005157`)을 이미 적용한 DB가 있다면 그 DB는 V20 불일치가 난다. 그 DB에서는 원인이 같으므로 V20 체크섬을 `513928538`로 맞추는 repair가 필요하다. 뷰는 V21이 다시 만든다.
- 재발 방지: 마이그레이션은 앱이 실행될 수 있는 작업 폴더에서 작성 후 다시 고치지 않는다. 고쳐야 하면 새 버전으로 추가한다.
