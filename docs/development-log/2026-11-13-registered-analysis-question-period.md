# 2026-11-13 등록 분석이 질문의 기간을 읽는다

## 1. 배경 / 문제

- 사용자 확인: "이번 달 지점별 매출을 비교해줘"와 "지난 달 지점별 매출을 비교해줘"의 결과가 똑같았다.
- 원인
  - 두 질문 모두 키워드 규칙("지점별 매출")으로 등록 분석 POC-001(지점별 순매출 비교)로 간다.
  - 등록 분석은 분석마다 기본 기간이 고정돼 있다(`OpenStudyAnalyses.defaultPeriod`: POC-001 이번 달, POC-007 지난달, POC-010 지난주 등).
  - 질문 속 기간은 읽지 않았다. ADR-M10-003의 해석("상대 기간은 분석마다 정해진 기간을 쓴다. 질문에서 임의 기간을 읽지 않는다")대로였다.
  - 화면 제목도 "이번 달 전체 순매출 요약"처럼 기본 기간으로 고정돼 있었다.
- 그 결과 사용자가 다른 기간의 수치를 자기 질문의 답으로 오해할 수 있었다.

## 2. 검토한 선택지

- 기간 해석: 생성 경로용으로 만든 서버 기간 해석기(`OpenStudyIntentAnalyzer`, #232)를 등록 분석에도 쓴다(선택). 모델이 아니라 서버 시계로 확정하므로 재현 가능하다.
- 기간 적용: 등록 분석의 기간 덮어쓰기는 이미 "조건 바꿔 재실행"(#125)이 쓰는 `executeWithOverrides` 경로에 있다. 같은 경로로 넘긴다(선택).
- 제목: 분석마다 기간별 제목을 따로 만드는 대신, 기간을 덮어쓴 결과의 제목 앞 기간 표현("이번 달", "지난달", "이번 주", "지난주")을 실제 기간으로 바꾼다(선택). 조건 바꿔 재실행·후속 질문에서도 같은 문제가 있었으므로 공통 경로에서 처리한다.

## 3. 결정 및 이유

- 질문이 기간을 지정하면 분석 기본 기간과 이전 결과에서 이어받은 기간보다 우선한다.
- 같은 말이 기본 기간을 뜻하면 기본 기간을 쓴다. 예: POC-001의 "이번 달"은 이번 달 1일부터 오늘까지다. 해석기의 "이번 달"(달 전체)과 시작이 같고 기본 기간을 포함하므로 기본으로 본다. "변경한 기간"으로 표시하지 않기 위해서다.
- 기간이 없는 분석(실시간 빈자리, 긴급 업무)은 질문 기간을 무시한다.
- 기간이 둘 이상이면 `PERIOD_AMBIGUOUS`, 분석별 상한(`AiReuse.editable`, 조건 변경과 같은 상한)을 넘으면 `PERIOD_TOO_LONG` 확인 질문을 돌려준다.
- 적용한 기간은 실행 기록의 기간 칸에 저장한다. 다시 열기·다시 실행·후속 질문에서 그 기간을 유지한다. 응답 조건의 `periodSource`는 기존 값 `EDITED`를 쓴다(API 계약 변경 없음).

## 4. 구현 내용

- `OpenStudyIntentAnalyzer.questionPeriod`: 질문의 기간을 "없음 / 하나 / 둘 이상"으로 돌려준다. "YYYY년 M월부터 … 까지"는 엔진의 달력 해석(`CalendarPeriod.months`)을 쓴다.
- `AiWorkspaceService`
  - 등록 분석 실행 전에 질문 기간을 확인하고(`askedPeriod`), 확인 질문 또는 기간 덮어쓰기를 정한다.
  - 후속 질문에서 질문이 새 기간을 지정하면 응답 맥락의 "유지" 목록에서 기간을 빼고 "변경된 조건"에 넣는다.
- `AiPeriodTitles`(신규): 기간을 덮어쓴 결과의 화면 제목과 답변 문장의 앞 기간 표현을 "2026년 10월" 또는 "2026-11-02~2026-11-08"로 바꾼다.

## 5. 검증 결과

- `AiQuestionPeriodIntegrationTests`(4개, Testcontainers MySQL)
  - "이번 달"과 "지난 달" 지점별 매출이 서로 다른 결과다. 각각 그 달의 승인 결제 합계와 같다.
  - 지난달 결과의 조건 기간은 지난달 1일~말일이고, 제목은 "YYYY년 M월 …"이다. 이번 달 결과는 기본 기간(`DEFAULT`)이고 제목은 그대로다.
  - 다시 실행해도 지난달 기간과 수치를 유지한다.
  - "이번 달과 지난달"은 `PERIOD_AMBIGUOUS`, "올해 직원별 근무시간"(상한 92일)은 `PERIOD_TOO_LONG` 확인 질문이다.
- `AiQuestionPeriodUnitTests`(3개): 고정 시계에서 기간 해석(지난 달, 저번달, 범위, 없음, 둘 이상)과 제목 표기
- `./gradlew test --tests "com.openstudy.modules.ai.*" --tests "com.openstudy.domainlens.*"`: 120개 중 실패 0, 건너뜀 25(기존 opt-in 테스트)
- 실행하지 않은 검증
  - 전체 테스트(`./gradlew test`)
  - 정형 매출 API와의 수치 대조
  - 브라우저 확인

## 6. 남은 작업 / 보류 사항

- 응답 조건의 `periodSource`가 질문 지정 기간도 `EDITED`("변경한 기간")로 표시된다. "질문에서 지정한 기간"으로 구분하려면 API 계약에 값을 추가해야 한다.
- "최근 400일"처럼 해석기 상한(366일)을 넘는 표현은 기간 없음으로 읽혀 기본 기간이 쓰인다. 확인 질문으로 바꿀지 판단이 필요하다.
- live 모드의 등록 분석 선택기(Qwen)가 고른 분석에도 같은 규칙이 적용된다. 실제 Qwen으로는 확인하지 않았다.
