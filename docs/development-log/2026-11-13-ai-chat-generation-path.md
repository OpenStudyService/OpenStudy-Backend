# 2026-11-13 AI 채팅에 DomainLens 생성 경로 연결 (#233)

## 1. 배경 / 문제

- #232(PR #235, 병합됨)로 생성 경로가 OpenStudy 스키마에서 동작하게 됐다. 하지만 AI 채팅은 여전히 등록 분석 10개 중 하나만 골랐다. 그래서 등록 분석이 없는 질문은 모두 "지원하는 업무 지표로 질문해 주세요."로 끝났다.
- 작업 브랜치는 사용자 요청대로 로컬 `main`(#235 병합 커밋 3666fba)에서 만들었다.

## 2. 검토한 선택지

- **어떤 질문을 생성 경로로 보낼지**
  - 등록 분석이 없다고 판정된 질문만 보낸다(선택, 2026-11-13 결정: 등록 분석 우선).
  - 날씨·주식 같은 명백한 도메인 밖 질문, 권한·수정 의도·개인정보 거절, 확인 질문은 보내지 않는다.
- **매출 권한 확인 시점**
  - 모델 호출 뒤 엔진 정책에 맡긴다: 결제 원천이 모델 문맥에서 빠져 "지원하지 않음"으로 끝난다. 권한이 없다는 사실을 알려 주지 못하고, 토큰도 쓴다.
  - 서버 의도 분석으로 결제 지표를 읽으면, 모델 호출 전에 기존 매출 권한 판단(`authorizeQuestion`)을 적용한다(선택).
- **모델 응답 실패를 어떻게 돌려줄지**
  - 처음에는 모델 실패를 502로 돌려줬다. 그러자 기존 M10 계약 테스트(`AiModelBoundaryIntegrationTests`, "모델 실패는 일반 답변으로 끝난다")가 실패했다.
  - 기존 계약을 따랐다(선택). 깨진·거절·불완전한 모델 응답은 일반 "지원하지 않음" 답변으로 끝낸다. 시간 초과만 504 공통 오류다.
- **저장된 생성 결과를 다시 실행할 때 기간**
  - 저장된 날짜 범위를 그대로 쓴다: "이번 달" 질문을 다음 달에 다시 열면 지난달 결과가 나온다.
  - 등록 분석처럼 새 기준 시각으로 실행한다(선택). 질문을 서버 의도 분석기로 다시 읽어, 지표 기간 항목의 조건만 바꾼다. 다른 조건은 그대로 둔다.

## 3. 결정 및 이유

- 생성 경로는 live 모델이 있을 때만 동작한다. playback 모드에는 계획을 세울 모델이 없으므로 동작이 바뀌지 않는다.
- 모델 출력은 계획 생성 후 서버 컴파일 방식이다(#232 결정).
- 생성 결과의 조건 바꿔 재실행(refinement)은 1차 범위에서 제외했다(2026-11-13 결정). 수정 가능 조건은 없음으로 응답한다.

## 4. 구현 내용

- `AiGenerationService`(신규)
  - 생성 실행 결과를 완료(Completed), 답변 불가(Declined), 오류(Failed) 세 가지로 나눈다.
  - 저장된 생성 조회를 모델 없이 다시 실행하고(`rerun`), 상대 기간을 다시 계산한다(`rebase`).
  - 엔진 오류 매핑

    | 엔진 오류 | 응답 |
    |---|---|
    | SCOPE_DENIED, PII_DENIED | 403 FORBIDDEN |
    | MODEL_TIMEOUT, QUERY_TIMEOUT | 504 AI_TIMEOUT |
    | BUDGET_EXCEEDED | 422 AI_BUDGET_EXCEEDED |
    | NOT_READY | 503 AI_NOT_READY |
    | CANCELED | 409 |
    | INTERNAL_ERROR | 502 AI_GENERATION_FAILED |
    | 그 밖(모델 응답 실패, IR 검증 실패 등) | 일반 "지원하지 않음" 답변 |

- `OpenStudyGenerationModel`(신규): live 모드에서만 계획 생성 모델을 제공한다.
- `OpenStudyQueryPipelineFactory.execute`: 저장된 쿼리를 현재 정책으로 검증·계획·실행하고 화면을 다시 연결한다.
- `OpenStudyPlaybackGateway.noRegisteredAnalysis`: 생성 경로로 넘길 판정인지 확인한다. 명백한 도메인 밖 질문의 거절 문구를 상수(`OUT_OF_DOMAIN_MESSAGE`)로 빼서 구분한다.
- `AiWorkspaceService`
  - 질문: 등록 분석이 없으면 매출 권한을 먼저 확인하고 생성 경로를 실행한다. 생성 결과는 `GENERATED_EXECUTION`으로 저장한다(분석 ID 없음, 생성 쿼리·ViewSpec 저장). 생성 경로도 답하지 못하면 기존 "지원하지 않음" 응답에 시도 단계를 남긴다.
  - 대화 다시 열기, 결과 페이지 조회, CSV 내보내기, 최근 질문 다시 실행: 생성 결과도 모델 없이 저장된 쿼리로 실행한다.
  - CSV 조건 문구는 "AI 생성 조회"와 "질문 기준, 지금 시각으로 다시 계산"으로 쓴다.
- `AiReuse.editable(null)`: 분석 ID가 없으면 수정 가능 조건 없음(이전에는 예외가 났다)

## 5. 검증 결과

- `AiGenerationPathIntegrationTests`(8개): 실제 HTTP API, Testcontainers MySQL, ONNX 검색, 모델 자리에는 계획을 재생하는 게이트웨이
  - 등록 분석이 없는 질문이 생성 조회로 답하고, 이번 달 승인 결제만 지점명별로 합산된다(DB 합계와 같음). 생성 쿼리가 저장된다.
  - 대화 다시 열기, 결과 조회, CSV 내보내기, 최근 질문 다시 실행이 모델 호출 없이 동작한다.
  - 등록 분석 질문은 모델을 부르지 않고 등록 분석으로 답한다.
  - 날씨 질문은 모델을 부르지 않는다.
  - 매출 권한 없는 직원은 모델 호출 전에 403으로 거절된다.
  - 모델 시간 초과는 504 `AI_TIMEOUT`이다.
  - 생성 경로도 답하지 못하면 기존 "지원하지 않음"(`OUT_OF_DOMAIN`)이다.
  - live 모델이 없으면 동작이 바뀌지 않는다.
- `AiGenerationServiceUnitTests`(3개): 다시 실행할 때의 기간 재계산, 엔진 오류 매핑
- 기존 테스트 기대값 변경 1건: `AiModelBoundaryIntegrationTests`에서 모델 요청 수가 2회에서 3회로 늘었다. 등록 분석이 없는 깨진 응답 질문에 생성 경로가 한 번 더 묻기 때문이다. 깨진 응답이 일반 답변으로 끝나고 데이터가 바뀌지 않는다는 기존 검증은 그대로다.
- `./gradlew test --tests "com.openstudy.modules.ai.*" --tests "com.openstudy.domainlens.*"`: 111개 중 실패 0, 건너뜀 24(기존 로컬 픽스처 23개, live Qwen 1개)
- **실행하지 않은 검증**
  - 실제 Qwen으로 채팅 API 왕복
  - 전체 테스트(`./gradlew test`)
  - 프론트엔드 화면(OpenStudy-Frontend#122)

## 6. 남은 작업 / 보류 사항

- 프론트엔드에서 생성 결과(분석 ID 없음, `GENERATED_EXECUTION`) 렌더링: OpenStudy-Frontend#122
- 생성 결과는 대화 후속 질문의 기준이 되지 않는다(이전 결과 기준은 등록 분석만). 후속 질문 지원은 별도 판단이 필요하다.
- 생성 경로의 모델 호출은 질문 트랜잭션 안에서 이뤄진다. 지연이 길어지면 트랜잭션 분리를 검토한다.
- 단계별 지연 p95 측정과 제한값 제안은 #97에서 한다.

## 7. 실제 Qwen으로 채팅 API 확인 (2026-11-13, 사용자 확인 뒤 2회)

- 조건: `qwen3.8-flash`, live 모드, Testcontainers MySQL, 실제 HTTP API(`POST /api/ai/queries`). 테스트는 `AiGenerationLiveIntegrationTests`이며, `OPENSTUDY_AI_LIVE_TESTS=true`일 때만 실행된다. 픽스처는 지점 두 곳, 이번 달 승인 결제, 100일 전 승인 결제, 실패 결제다.

| 질문 | 응답 | 경로 | 모델 호출 | 시간 |
|---|---|---|---|---|
| 이번 달 지점별 결제 금액 합계 보여줘 | 200 COMPLETED, 지점별 42,000 / 50,000(DB와 같음), 다시 실행 같음 | 등록 분석 `branchComparison` | 1회, 764토큰 | 2.6초 |
| 이번 달 결제 건수를 지점별로 보여줘 | 200 COMPLETED, 승인 건수 2 / 1 포함 | 등록 분석 `branchComparison` | 1회, 765토큰 | 2.7초 |

- **생성 경로는 실행되지 않았다.** live 모드에서는 키워드 규칙이 등록 분석을 못 찾으면, 등록 분석 선택기가 Qwen에게 등록 분석 10개 중 하나를 고르게 한다. Qwen이 두 질문 모두 등록 분석(지점별 순매출 비교)에 맞췄다. 그래서 "등록 분석 없음" 판정이 나오지 않았다.
- 결과 수치는 틀리지 않았다. 순매출 분석 결과에 승인 금액·승인 건수 열이 들어 있고, 픽스처에 환불이 없어 순매출과 승인 금액이 같다. 하지만 화면의 중심은 순매출이다. 환불이 있으면 사용자가 물은 "결제 금액"과 다른 값을 먼저 보게 된다.
- 판단 보류(사용자 결정 필요): 등록 분석 우선 원칙을 키워드 규칙에만 적용할지, live 선택기에도 적용할지. 서버 의도 분석기가 일반 지표 용어("결제 금액", "결제 건수")를 확정한 질문은 live 선택기 대신 생성 경로로 보내는 안을 검토한다.

## 8. 일반 지표 질문은 live 선택기를 건너뛴다 (2026-11-13 사용자 결정)

- 결정: 등록 분석 우선은 키워드 규칙에 적용한다. 키워드 규칙이 등록 분석을 못 찾았고 서버 의도 분석기가 일반 지표 용어("결제 금액", "결제 건수", "이용권 발급 수")를 확정한 질문은 live 등록 분석 선택기를 부르지 않고 생성 경로로 보낸다. 사용자가 물은 지표 그대로 답하고, 선택기 호출 1회를 줄인다.
- 구현: `OpenStudyPlaybackGateway`가 live 선택기 호출 전에 확인한다(이전 결과를 잇는 후속 질문은 제외). 판정은 기존 "등록 분석 없음"으로 끝나고, 7절과 같은 경로로 생성 경로가 받는다.
- 검증
  - `AiModelBoundaryIntegrationTests.aGeneralMetricQuestionSkipsTheRegisteredAnalysisPicker`: 가짜 모델 서버에 선택기 요청이 가지 않고 생성 요청만 간다.
  - `./gradlew test --tests "com.openstudy.modules.ai.*" --tests "com.openstudy.domainlens.*"`: 113개 중 실패 0, 건너뜀 25(기존 로컬 픽스처 23개, live 테스트 2개)
  - 실제 Qwen 1회(사용자 확인 범위): "이번 달 지점별 결제 금액 합계 보여줘" → 200 `GENERATED_EXECUTION`. 결제 승인액 지표, 지점명 묶음, 서버가 확정한 이번 달 기간(2026-10-31T15:00Z~2026-11-30T15:00Z). 지점별 42,000 / 50,000으로 DB와 같고, 다시 실행도 같다. 생성 단계 5.7초, 3,370토큰, 요청 전체 6.1초(선택기 호출 없음).
- 남은 점: 생성 결과의 열 별칭이 `d0`, `m0`처럼 서버 컴파일러가 붙인 이름이다. 화면 표시용 이름은 열 메타데이터나 카탈로그 이름에서 만들어야 한다(OpenStudy-Frontend#122, 또는 컴파일러 별칭 규칙 보강).
