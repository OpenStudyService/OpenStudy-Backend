# 기반 PR의 저장소 추적 범위 정리

## 1. 배경 / 문제

사용자가 프로젝트 저장소에 작업용 스크립트와 잡다한 파일이 과도하게 포함되었다고 지적했다. PR #5에는 설계 정본 외에 제작 도구 5개, 이슈 본문 복제본, release 폴더의 SQL/OpenAPI/보고서 사본과 metadata·해시 파일이 들어 있었다.

## 2. 검토한 선택지

재생성 도구를 정식 프로젝트 도구로 유지하는 방법을 앞서 제안했으나, 사용자는 프로젝트와 직접 관련된 자료만 추적하기를 원했다. 제작 과정 전체를 저장하기보다 실제 개발·협업에 필요한 정본과 요청한 산출물을 남기는 방향으로 변경했다.

## 3. 결정 및 이유

실행 코드·설정·DB migration·통합 테스트, DB/API 설계·정책·요구사항 추적·개발 계획은 유지한다. 팀원에게 필요한 전체 DDL·ERD·API 엑셀은 각 정본 위치에 한 번만 둔다. 제작 도구·등록 중간 파일·중복 패키지는 Git 추적에서 제외하되 로컬에 보존한다. 개발 기록은 사용자 작업 규칙에 따라 삭제하거나 수정하지 않는다.

## 4. 구현 내용

- 작업용 scripts 5개, github-drafts, agent-workflow, docs/releases를 로컬 보관 대상으로 전환하고 ignore 처리했다.
- 전체 구축 SQL·전체 Mermaid ERD는 docs/db/, API 엑셀·기반 ERD PDF는 docs/design/foundation/에서 관리한다. 동일 내용의 기존 로컬 사본은 덮어쓰지 않고 정본으로 추적했다.
- README·DB 적용 안내·설계 안내·개발 계획의 경로를 정리했다. 실행 migration과 애플리케이션 동작은 변경하지 않았다.
- main에 남은 과거 디렉터리 골격·초기 안내 파일의 정리는 별도 작업 브랜치/PR로 분리한다.

## 5. 검증 결과

- 제거 대상 파일을 outputs/repository-cleanup-2026-10-24/backend에 복사하고 내용 보존을 확인했다.
- 유지할 SQL·ERD·엑셀의 원본/배치 후 파일 hash를 비교했다. 요구사항·정책·OpenAPI와 주요 문서 링크, PR 최종 추적 범위를 검사했다.
- 코드·migration·테스트 파일은 이번 정리에서 변경하지 않았다. 이전 53개 테스트 결과는 해당 구현 커밋의 기록이며 이번 문서 정리에서 다시 실행하지 않았다.

## 6. 남은 작업

PR #5 검토·병합과 GitHub 마일스톤·이슈 등록은 남아 있다. 로컬 제작 도구는 프로젝트의 공식 실행 도구가 아니며 필요 시 별도로 사용한다.
