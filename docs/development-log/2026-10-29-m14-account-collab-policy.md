# 2026-10-29 M14 비밀번호 초기화 전달·세션 처리·프로필 사진 저장소·감사 로그 조회 범위 정책 확정

## 1. 배경 / 문제

M14(계정·협업·설정 확장) 이슈를 작성하려고 SRS v1.11의 M14 요구사항 7개와 V1 스키마·현재 코드를 확인했다.

- 공통 SSE(`WorkspaceEventService`)와 `employees.avatar_url`은 이미 있다.
- 파일 저장소 설정, 비밀번호 재설정 토큰 저장 구조가 없다.
- 비밀번호 초기화의 "안전한 전달" 방식, 비밀번호 변경 후 다른 세션 처리, 프로필 사진 저장 위치, 감사 로그 조회 범위가 정해지지 않았다.

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 초기화 전달 | 이메일 재설정 링크 / 임시 비밀번호 1회 표시 |
| 세션 처리 | 다른 세션 모두 종료 / 세션 유지 |
| 사진 저장 | S3 비공개 버킷 / DB 저장 |
| 감사 조회 | OWNER 전체 + MANAGER 자기 지점 / OWNER만 |

## 3. 결정 및 이유

사용자가 결정했다. 상세는 [ADR-M14-001](../db/ADR-M14-001.md)에 있다.

- 초기화는 이메일 재설정 링크로 한다. 관리자가 비밀번호를 알 수 없다.
- 비밀번호 변경·초기화 시 다른 세션을 종료한다.
- 프로필 사진은 S3 비공개 버킷에 저장한다. 버킷·권한은 인프라 팀원에게 요청한다.
- 감사 로그는 OWNER만 조회한다. 사용자가 권장안(MANAGER 자기 지점 포함) 대신 이 방식을 골랐다.
- 초기화 권한·토큰 규칙, 잠금의 의미, 1:1 대화 상대, 채팅 전용 스트림, 테마 저장, 이미지 검증(M14-D05~D10)은 SRS와 V1·현재 코드에서 도출한 구현 기준으로 함께 기록했다.

## 4. 구현 내용

- `docs/db/ADR-M14-001.md`: M14-D01~D10과 스키마 영향을 기록했다.
- 저장소 밖 변경(이 커밋에 포함하지 않음): 작업공간 SRS를 v1.12로 만들었다. POL-43~46을 추가하고 FR-AUTH-13·14, FR-SET-02, FR-AUD-04를 갱신했다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 `employees`·`audit_events`·`conversations` DDL, `WorkspaceEventService`, `LoginAttemptLimiter`, 결정 등록부 M1-06·M1-07을 읽어 결정과 맞는지 확인했다.

## 6. 남은 작업 / 보류 사항

- S3 버킷·IAM 권한을 인프라 팀원에게 요청해야 한다.
- 로그인 제한기와 SSE의 다중 인스턴스 동작은 기존 후속 과제(Backend #18, #65)와 함께 다룬다.
