# 2026-11-07 AI 조회 결과 미저장(M10-D12 정합)

## 1. 배경 / 문제

- 이식된 DomainLens 백엔드(#169)는 AI 조회 결과 자체를 DB에 저장했다.
  - `ai_executions.envelope_json`·`legacy_execution_json`: 결과 데이터셋과 화면용 결과
  - `ai_work_records.snapshot_json`: 작업 기록의 결과 사본
- ADR-M10-002 M10-D12는 "질문·검증된 QuerySpec/ViewSpec·처리 상태·기준 시각만 저장하고 결과 데이터는 저장하지 않는다"이다.
  - 권한이 회수된 뒤에도 과거 수치가 남아 보이는 일을 막는다.
  - 결과 행이 보존·파기 대상이 되지 않게 한다.
- 대화 기록 PR(OpenStudyService/OpenStudy-Backend#172)에서 이 차이를 후속으로 남겼고, 사용자가 정책대로 제거하기로 했다.

## 2. 검토한 선택지

- 정책대로 제거 / 이슈로만 남기고 유지: 사용자가 제거를 골랐다.

## 3. 결정 및 이유

- 결과 칼럼 세 개를 지운다(V8). 이미 저장된 값도 함께 사라진다.
- 결과가 필요한 곳은 대화 다시 열기(#172)와 같은 방식으로 다시 실행한다.
  - 저장된 분석 ID를 현재 권한으로 다시 확인한다(`verifyBranchReaccess`).
  - 같은 지점 범위로 다시 실행하고, 새 기준 시각을 쓴다.
- 결과가 필요한 곳은 세 군데다.
  - `GET /api/executions/{id}`
  - 작업 기록 열기(`GET /api/ai/records/{id}`)
  - CSV 반출: 승인 요청의 행 수 계산과 승인된 CSV 다운로드. CSV는 다운로드 시점의 데이터가 된다.

## 4. 구현 내용

- `V8__ai_no_stored_results.sql`
  - `ai_executions`에서 `envelope_json`·`legacy_execution_json`을 지운다.
  - `ai_work_records`에서 `snapshot_json`을 지운다.
- 엔티티·저장 경로에서 결과 필드를 지웠다(`AiExecutionEntity`, `AiWorkRecordEntity`, `persistExecutionAndTrace`).
- `AiWorkspaceService.rerunSaved`
  - 실행된 질문(READY)을 현재 권한으로 다시 확인한 뒤 같은 지점 범위로 다시 실행한다.
  - 실행된 적 없는 질문(확인 필요·거부)은 422(`NOT_EXECUTABLE`)로 응답한다.
- 작업 기록을 열 때 원본 질문이 지워졌거나 다시 실행할 수 없으면, 결과 대신 `snapshotUnavailableReason`을 돌려준다.
- 마이그레이션 테스트의 최신 버전 기대값을 V8로 바꿨다. 테이블 수(73)는 그대로다.

## 5. 검증 결과

- 신규 통합 테스트(`noResultIsStoredAndEveryResultIsRunAgainUnderTheCurrentPermissions`)를 추가했다.
  - 결과 칼럼이 없다.
  - 실행 재조회와 작업 기록 열기가 결과를 다시 실행해 돌려준다.
  - 대화를 지우면 작업 기록에 사유만 남는다.
  - 매출 권한이 없는 직원의 실행 재조회는 403이다.
- 영향받는 테스트(대화 기록·마이그레이션·DomainLens) 통과
- 전체 `./gradlew test`(88개 스위트): 1001개 중 978개 통과, 23개 건너뜀(로컬 전용 AI 테스트), 실패 0
- **미검증**: CSV 반출 승인·다운로드 흐름의 HTTP 테스트(기존에도 로컬 전용 테스트에만 있었다)

## 6. 남은 작업 / 보류 사항

- 같은 질문이라도 다시 열 때마다 새 기준 시각으로 조회하므로, 작업 기록·CSV의 수치가 처음 조회 때와 다를 수 있다. 정책이 의도한 동작이다.
- 원래 질문의 부가 조건(원결제일 기준 환불, 0원 채우기)은 저장되지 않아 기본값으로 다시 실행한다(#172와 같음).
- 마이그레이션 버전은 병합 직전에 main의 최대 버전 + 1로 맞춘다(V8).

## 추가: 실행 조건 보존·V8 확인·캐싱 분리 (같은 날, 사용자 요청)

### 배경

- 사용자가 결과 저장 제거(3번, 원래 정책)를 확정했다.
- 함께 요청한 것:
  - 다시 열 때 원래 질문의 부가 조건이 빠져 결과의 의미가 달라지는 문제를 고친다.
  - 병합 전에 V8 번호 충돌과 기존 데이터 삭제 영향을 확인한다.
  - 캐싱은 별도 이슈로 검토한다.

### 실행 조건 보존

- **문제:** `executeWithOverrides`는 분석 ID 외에 두 조건을 받는다. 환불 기준(`ORIGINAL_PAYMENT_DATE`, 항목별 매출 POC-008)과 0원 날짜 채우기 요청(일별 매출 POC-007)이다.
  - 이 둘은 저장되지 않았다. 다시 열기·실행 재조회·작업 기록·CSV는 기본값으로 실행돼, "원결제일 기준"으로 물은 질문이 처리일 기준 결과로 바뀌었다.
- **변경**
  - V8에서 `ai_executions`에 `refund_basis`(NULL이면 기본값)와 `zero_fill_requested`를 더한다. 질문을 처리할 때 계획의 두 조건을 저장한다.
  - 모든 재실행 경로(대화 다시 열기, `rerunSaved`, 실행 재조회의 화면용 결과)가 저장된 조건으로 실행한다.
  - 마이그레이션 파일 이름은 `V8__ai_execution_spec_without_results.sql`로 바꿨다(결과 제거와 조건 보존을 함께 담음).
- **한계**
  - V8 이전에 저장된 질문은 조건을 알 수 없어 기본값으로 남는다.
  - 이식된 엔진에서 원결제일 기준 조건은 요약 값(`summary`)만 바꾸고 표·차트 데이터셋(`envelope`)은 바꾸지 않는다. 엔진 동작이라 이번 범위에서 고치지 않았고, 별도 확인이 필요하다.
  - "이번 달", "지난달" 같은 기간은 다시 열 때의 기준 시각으로 계산된다. M10-D12의 "새 기준 시각" 규칙이 의도한 동작이다.

### V8 번호 충돌 확인

- main의 최대 버전은 V7이다.
- 열린 PR과 원격 브랜치 가운데 `db/migration/V*`를 추가하는 것은 #173(V8)뿐이다. 충돌이 없다.
- 병합 직전에 다시 확인한다(마이그레이션 README 규칙).

### 기존 데이터 삭제 영향

- **지워지는 것:** `ai_executions.envelope_json`·`legacy_execution_json`, `ai_work_records.snapshot_json`. V7(#169) 이후 저장된 AI 조회 결과 값이다.
- **남는 것:** 질문, 분석 ID, 검증된 QuerySpec·ViewSpec, 상태, 기준 시각, 대화·메시지, 작업 기록·반출 승인의 메타정보, 진단 로그
- **영향**
  - 결과를 읽던 곳은 모두 재실행으로 바뀌었다. 기존 질문도 다시 열면 그대로 조회된다(조건은 기본값).
  - 지운 값은 되돌릴 수 없다. Flyway에는 되돌리기 마이그레이션이 없고, 필요하면 적용 전 DB 백업으로만 복구할 수 있다.
  - 어떤 테이블도 지우는 칼럼을 FK·인덱스로 참조하지 않는다.
- **미확인:** 배포·공유 DB에 실제로 쌓인 행 수는 이 환경에서 조회하지 못했다. 운영 DB가 있다면 적용 전에 백업 여부를 확인해야 한다.

### 캐싱

별도 이슈 OpenStudyService/OpenStudy-Backend#174로 분리했다. 다음을 검토 범위로 정리했다.

- 모델 출력 중 사용자와 무관한 분석 계획만 캐시하고, 권한 판단은 매번 한다.
- 인메모리 결과 캐시(TTL 상한, 키, 적중 시 재인가, outbox 이벤트로 무효화)와 그것이 M10-D12와 맞는지 판단
- 엔진에 있지만 OpenStudy 경로에 연결되지 않은 `BoundedQueryCache`의 활용 여부

### 검증

- 신규 통합 테스트(`reopeningKeepsTheConditionsTheQuestionAskedFor`): 통과
  - 원결제일 기준·0원 채우기 조건이 다시 열기에 반영된다.
  - 조건이 없는 질문은 기본값으로 실행된다.
  - 실행 재조회의 `refundBasis`가 저장된 조건을 따른다.
- 전체 `./gradlew test`(88개 스위트): 1002개 중 979개 통과, 23개 건너뜀(로컬 전용 AI 테스트), 실패 0
- **미검증**: 실제 질문 처리(live·playback 계획)에서 조건이 저장되는 경로. 테스트는 저장된 행에서 다시 실행하는 쪽만 확인했다.
