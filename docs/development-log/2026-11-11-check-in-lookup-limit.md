# 2026-11-11 입실 정확 일치 조회 횟수 제한 (#65)

## 1. 배경 / 문제

- 입실 화면의 회원번호·연락처 정확 일치 조회(`POST /customer-lookups/check-in`)는 다른 지점 고객도 찾는다(M5-D05).
- 횟수 제한이 없으면 한 직원이 연락처를 바꿔 가며 고객 정보를 대량으로 확인할 수 있다(NFR-SEC-06).
- M5에서는 제한을 빼고 후속 과제로 미뤘다(ADR-M5-001 M5-D08).
  - 이유: 기존 로그인 제한기(`LoginAttemptLimiter`)의 고정 창 계수기가 클래스 안에 묶여 있어 재사용하려면 분리가 필요했다.

## 2. 검토한 선택지

| 항목 | 선택지 | 결과 |
| --- | --- | --- |
| 제한값 | 10분 60회 / 10분 120회 / 10분 30회 | 10분 60회(2026-11-11 사용자 결정). 운영 사용량 자료가 없어, 붐비는 입실 시간에도 입실 1건당 조회 1~2번이면 충분하다는 판단으로 정했다 |
| 계수기 | 로그인 제한기의 계수기를 공통으로 분리 / 새로 작성 | 분리. 용량 초과 시 정리, 창마다 한 번만 보고하는 기존 동작을 그대로 쓴다(이슈 범위) |
| 제한 확인 위치 | 권한 확인 전 / 권한 확인 안(트랜잭션 안) | 권한 확인 전. 트랜잭션 안에서 429를 던지면 거절 감사도 함께 롤백된다. 조회도 하기 전에 거절하므로 고객 정보가 드러나지 않는다 |

## 3. 결정 및 이유

- **키**: 직원 ID + 지점 ID. 한 직원이 여러 지점에서 일하면 지점마다 따로 센다.
- **거절**
  - 429 `RATE_LIMITED`(공통 응답)로 거절하고, 조회도 조회 기록도 하지 않는다.
  - 거절된 요청은 세지 않는다. 시간창이 지나면 다시 조회할 수 있다(로그인 제한과 같은 방식).
- **감사**
  - 한 시간창에서 처음 거절할 때만 `CHECK_IN_LOOKUP_RATE_LIMITED`(DENIED)를 남긴다. 반복 요청이 감사 기록을 채우지 않게 하기 위해서다.
  - 지점은 아직 권한을 확인하기 전이라 `branch_id`가 아니라 `after_json`에 넣는다. 없는 지점 ID여도 감사 저장이 실패하지 않는다.
- **저장 위치**: 인스턴스 메모리. 재기동하면 처음부터 다시 센다. 다중 인스턴스 공유 저장소는 이슈 범위에서 제외했다.
- **설정**: `openstudy.customer-lookup-limit.max-attempts`(60), `window-minutes`(10), `capacity`(10000)

## 4. 구현 내용

- 새 `common/limit/FixedWindowCounter`: `LoginAttemptLimiter`의 내부 `Window`를 그대로 옮겼다(동작 변경 없음).
- `LoginAttemptLimiter`: 공통 계수기를 쓰도록 바꿨다. 공개 메서드와 설정은 그대로다.
- 새 `CheckInLookupLimiter`(seat 모듈): 직원·지점 키로 확인하고, 거절이면 시간창의 첫 거절인지 돌려준다.
- `CheckInLookupService`: 입력 검증 뒤, 권한 확인·조회 전에 제한을 확인한다.
- `application.yaml`: 제한 설정
- 계약
  - `openapi.json`: 조회의 `x-error-codes`에 `RATE_LIMITED`를 추가했다(429 응답은 이미 있었다).
  - `seat-usage-api.md`: 제한 기준과 거절 동작

## 5. 검증 결과

- 실행함(`-PtestForks=1`)

    - 60회까지 통과하고 61회째는 거절, 거절 보고는 창마다 한 번
    - 다른 지점·직원은 따로 세고, 시간창이 지나면 다시 가능
    - 잘못된 설정은 거부
  - 로그인 제한 회귀: `LoginAttemptLimiterTests` 13건, `AuthHttpTests` 16건, `AccountCredentialUnitTests` 16건 모두 통과(분리 후 그대로)
  - `SeatSessionIntegrationTests` 36건 통과. 새 HTTP 시험 1건 포함:
    - 60번 조회는 200이고, 61·62번째는 429 `RATE_LIMITED`이며 응답에 고객 정보가 없다.
    - 조회 기록은 60건이고, 거절 감사는 1건(DENIED)이며 검색값이 없다.
  - 아키텍처·계약 테스트 109건 통과
- 실행하지 않음
  - 전체 `./gradlew test`: 마일스톤 검증(#104) 때 실행한다.
  - 운영 사용량 대비 제한값 적정성: 운영 자료가 생기면 다시 확인한다.
