# 2026-10-28 M9 정형 집계 기간·환불 기준·매출 범위·추세 구간 정책 확정

## 1. 배경 / 문제

M9(운영 홈·정형 집계) 이슈를 작성하려고 SRS v1.6과 V1 스키마를 대조했다. 집계 전용 테이블은 없고 `modules/sales`·`modules/home`은 비어 있다. 다음이 정해지지 않았다.

- 기간이 없을 때의 기본값과 최대 조회 기간(FR-AGG-08)
- 두 환불 기준 중 기본값(FR-AGG-17)
- 매출에 스터디룸·사물함 결제를 넣을지
- 주 시작 요일과 거래 없는 구간 처리(FR-AGG-14)

또 SRS는 "무료·수동 발급"을 판매량과 구분하라고 하지만, V1에서는 이용권이 반드시 결제와 연결되어(`passes.purchase_payment_id` 필수) 그런 발급이 존재하지 않는다.

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 기간 규칙 | 이번 달·최대 1년 / 최근 30일·최대 1년 / 기본값 없음·최대 1년 |
| 기본 환불 기준 | 환불 처리일 / 원결제일 |
| 매출 범위 | 이용권·룸·사물함 모두 + 용도별 구분 / 이용권만 |
| 추세 구간 | 월요일 시작·빈 구간 0 / 일요일 시작·빈 구간 0 / 월요일 시작·빈 구간 생략 |

## 3. 결정 및 이유

사용자가 모두 권장안을 선택했다. 상세는 [ADR-M9-001](../db/ADR-M9-001.md)에 있다.

- 기본 기간은 이번 달, 최대 366일이다.
- 기본 환불 기준은 환불 처리일이다. 지난 기간의 수치가 바뀌지 않는다.
- 매출은 세 용도를 모두 포함하고 용도별로 나눠 보여 준다.
- 주는 월요일에 시작하고 빈 구간은 0으로 채운다.
- 매출·환불의 지점 귀속, 발급 건수와 판매량 정의, 집계 권한, 홈의 "오늘" 기준, 비율 반올림(M9-D05~D09)은 SRS와 V1에서 도출한 구현 기준으로 함께 기록했다.

## 4. 구현 내용

- `docs/db/ADR-M9-001.md`: M9-D01~D09를 기록했다.
- 저장소 밖 변경(이 커밋에 포함하지 않음): 작업공간 SRS를 v1.7로 만들었다. POL-23~26을 추가하고 FR-AGG-01·08·14·17, FR-PASS-05를 갱신했다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 DDL(`payments`, `refunds`, `passes`)과 기존 인덱스, 권한 정의를 읽어 결정과 맞는지 확인했다.

## 6. 남은 작업 / 보류 사항

- 인덱스 추가 여부는 구현 이슈에서 실행 계획을 보고 정한다.
- 자연어 응답과 정형 API의 수치 동등성은 M10에서 최종 검증한다.
