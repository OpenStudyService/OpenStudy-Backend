# 사용하지 않는 초기 골격의 추적 종료

## 1. 배경 / 문제

사용자가 GitHub 저장소에 프로젝트와 직접 관련 없는 작업 파일이 많다고 지적했다. main을 확인하니 현재 코드 구조와 다른 docs/directory-architecture 아래에 181개의 과거 골격 파일이 남아 있었다. 자동 생성 HELP.md와 실행 도구 없이 향후 계획만 적은 scripts/README.md도 현재 개발에 필요하지 않았다.

## 2. 검토한 선택지

과거 골격을 현재 tree에 계속 보관하거나, 로컬·Git 이력에서 확인하도록 추적을 종료하는 방법을 검토했다. 현재 src의 실제 구조와 두 개의 구조가 함께 노출되어 혼동을 주므로 후자를 선택했다. 제품 설계 자료·정책·개발 기록은 이번 정리 대상에서 제외했다.

## 3. 결정 및 이유

main 기준 chore/repository-cleanup 브랜치에서 기존 불필요한 보관본을 정리한다. 신규 기반 설계 PR #5의 제작 파일/중복 산출물 정리와 분리해 검토할 수 있게 했다. 현재 코드·설정·테스트·실행 migration과 개발 기록은 유지한다.

## 4. 구현 내용

- docs/directory-architecture의 옛 골격 181개, HELP.md, 빈 scripts 안내 총 183개를 Git 추적에서만 제외했다.
- 추적 제외 대상은 로컬에 남기고 outputs/repository-cleanup-2026-10-24/backend에도 복사해 보존했다. 이전 Git 커밋에도 원본이 있다.
- ignore 규칙을 추가하고 README와 현재 구조 안내에서 이전 골격 경로의 직접 링크를 제거했다.
- 기존 개발 기록은 삭제하거나 덮어쓰지 않았다. 기록 안의 옛 경로는 당시 tree를 가리키며 Git 이력에서 확인한다.

## 5. 검증 결과

- 추적 제외한 183개 파일이 보존본과 동일하고 현재 src/·Gradle·실행/테스트 설정이 main과 동일한지 검사했다.
- 현재 안내 문서의 내부 링크가 추적된 자료를 가리키는지 확인하고 git diff --check를 수행했다.
- 실행 코드·테스트·의존성 변경이 없어 빌드·DB 테스트를 다시 실행하지 않았다. 이전 실행 결과를 이번 정리에서 재수행한 것처럼 기록하지 않는다.

## 6. 남은 작업

이 정리 PR과 기반 설계 PR #5는 각각 검토·병합이 필요하다. 프론트엔드 저장소의 계약 생성 도구와 화면 참조 자료는 실제 프로젝트와 관련되어 있어 임의 제거하지 않았다.
