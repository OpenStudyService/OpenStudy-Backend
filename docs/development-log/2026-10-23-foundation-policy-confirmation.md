# 1차 기반 설계의 세 가지 정책 확정 반영

작성일: 2026-10-23. 작업 브랜치: `docs/foundation-db-api`.

## 1. 배경 / 문제

[1차 설계 기록](2026-10-23-foundation-db-api-design.md)에서 승인 대기 세션·기간권 날짜 결정 시점·직원 전역 정보 수정 권한을 가정으로 남겼다. 사용자가 비동기 질문 세 개에 모두 권장안을 명시적으로 선택해 정책 대기 조건을 해제할 수 있게 됐다.

## 2. 검토한 선택지

새로운 대안을 추가 검토하지 않았다. 이전 설계에서 제시한 선택지 중 사용자가 선택한 답변을 적용했다. 미선택 대안과 검토한 논점은 decisions.md에 남기고 확정 정책과 구현 방법을 구분했다.

## 3. 결정 및 이유

- Q1: 신규 직원은 승인 확인용 제한 세션을 사용한다. 기존 직원의 추가 지점 초대는 새 소속만 승인 대기로 두고 기존 유효 지점 업무는 유지한다. 사용자의 ‘위 방식으로 처리’ 답변을 반영했다.
- Q2: 상품에 기간 일수를 저장하고 실제 시작일·종료일은 구매·발급 시 결정한다. 사용자의 해당 선택을 반영했다.
- Q3: 직원 이름·전역 계정 상태는 OWNER만 변경하고 지점 관리자는 자기 지점의 소속·역할·권한만 관리한다. 사용자의 해당 선택을 반영했다.
- 승인 완료 후 재로그인, 날짜 구간의 배타 종료 표현은 확정한 사업 정책을 구현하는 설계 방법으로 별도 표기했다. 사용자가 이 세부 구현까지 직접 지정했다고 기록하지 않는다.

## 4. 구현 내용

- decisions.md에 2026-10-23 사용자 답변과 정책 확정 기록을 추가하고 검토한 대안을 보존했다.
- DB·API·README·요구사항 추적표·개발 계획의 가정·답변 대기 표시를 확정 정책으로 변경했다. 관련 개발 이슈의 정책 선행 조건을 해제하고 기술적 의존 관계는 유지했다.
- OpenAPI 버전을 `0.1.1-design`으로 갱신하고 `x-policy-assumptions`를 `x-policy-decisions` 참조로 대체했다. 루트의 `x-confirmed-policies`에 확정 주체·날짜·내용을 기록했다. API 경로·요청·응답 구조는 이전 권장안과 동일하다.
- 검증 스크립트에 세 정책의 확정 메타데이터·참조·가정 잔존 검사 항목을 추가했다.
- 원본 SRS와 추출 JSON은 당시 원문·해시를 유지했다. 다음 SRS 개정의 문구 동기화 대상을 decisions.md에 정리했으며, 이 원문 정리를 개발 착수의 추가 승인 조건으로 두지 않았다.

## 5. 검증 결과

- OpenAPI 표준 유효성 검사 통과.
- 로컬 설계 검사 통과: 요구사항61·중분류8·operation39·schema57·내부 참조531·이슈16·확정 정책3.
- `git diff --check` 통과. 운영 코드·기존 V1·DB에는 변경이 없어 서버 빌드·DB 실행·브라우저 테스트는 수행하지 않았다.

## 6. 남은 작업 / 보류 사항

- 세 정책에 대한 사용자 답변 대기 사항은 없다. 개발 계획의 기술적 선행 순서로 후속 구현에 착수할 수 있다.
- 실제 새 migration, 운영 API·화면 구현, GitHub 마일스톤·이슈 등록과 실행 검증은 기존 개발 계획의 후속 작업이다. 이번 답변 반영만으로 구현 완료 처리하지 않는다.
- 다음 원본 SRS 개정 때 확정된 세 정책의 문구를 동기화한다. 기존 요구사항 추출 사본을 조용히 덮어써 과거 설계 근거를 바꾸지 않는다.
