# 2026-11-12 직원 비밀번호 조합 규칙 적용

## 배경과 결정

신규 직원 초대에서 비밀번호의 길이만 검사했다. 사용자가 새로 정하는 비밀번호에 같은 기준을 적용하기 위해 초대 수락, 본인 비밀번호 변경, 링크 재설정에서 공통 검증을 사용한다. 기존 자격증명을 확인하는 로그인과 현재 비밀번호 입력에는 기존 검증을 적용한다.

## 구현

- 영문 대·소문자, ASCII 숫자, ASCII 특수문자를 각각 하나 이상 포함하고 유니코드 코드 포인트 기준 8자 이상이어야 한다. 공백은 입력값에 보존하며 특수문자로 세지 않는다. BCrypt의 UTF-8 72바이트 제한을 적용한다.
- 검증 오류는 초대 수락에서 `password`, 변경 및 재설정에서 `newPassword` 필드로 반환한다.
- OpenAPI와 API 문서에 규칙을 반영했다. 문자 종류 누락, 8자 미만, 멀티바이트 상한에 대한 회귀 검증을 보강했다.

## 검증

- 계정·초대 모듈과 계정 API 계약의 Gradle 테스트 95개를 통과했다. 실제 서버 테스트 환경에서 신규 비밀번호 검증과 기존 자격증명 로그인을 확인했다.
- 첫 전체 실행에서 계정 모듈이 초대 메일 설정을 이미 참조해 순환 의존이 생기는 것을 모듈 경계 테스트로 확인했다. 정책을 공통 웹 입력 검증으로 옮긴 뒤 계정·초대 모듈과 모듈 경계 테스트를 다시 통과했다.
