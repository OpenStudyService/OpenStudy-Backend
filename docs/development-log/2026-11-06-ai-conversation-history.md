# 2026-11-06 AI 대화 기록(목록·다시 열기·제목 변경·삭제)

## 1. 배경 / 문제

- 사용자 피드백: 다른 메뉴에 갔다가 `업무 AI`로 돌아오면 이전 대화가 사라진다. 이전 기록을 확인하는 기능이 필요하다.
- 화면 상태만 있었고, 백엔드는 대화를 저장하지만 목록·다시 열기 API가 없었다. #71(선행: Backend #92 계약)의 범위다.

## 2. 검토한 선택지

사용자가 세 가지 중에서 골랐다.

- 로그인 동안만 화면에 유지: 프런트만 고치면 되지만 새로고침에 사라진다.
- 브라우저 저장소에 목록 저장: 조회 결과(매출 등)가 기기에 남는다.
- **서버 대화 목록(#71)**: 백엔드 API를 더해 목록·다시 열기·제목 변경·삭제를 제공한다. ← 선택

## 3. 결정 및 이유

ADR-M10-002 M10-D12를 따랐다.

- 대화는 만든 직원 본인만 본다.
- 결과 데이터는 다시 보여 주지 않는다. 다시 열면 저장된 분석을 **현재 권한·지점 범위로 다시 검증·실행**하고, 새 기준 시각으로 보인다. 모델은 호출하지 않는다.
- 다시 실행할 수 없는 질문은 결과 대신 사유만 보인다.

## 4. 구현 내용

### Backend (`feature/ai-conversation-history`, `feature/domainlens-ai-porting` 위, 로컬 커밋)

- API
  - `GET /api/ai/conversations`: 본인 대화 목록, 최근 질문 순
  - `GET /api/ai/conversations/{id}?scope=`: 다시 열기
    - 저장된 질문마다 `authorizeQuestion`으로 현재 권한·범위를 다시 확인하고, 저장된 분석 ID를 `executeWithOverrides`로 다시 실행한다.
    - 확인 필요·거부였던 질문은 상태만 돌려준다.
  - `PATCH /api/ai/conversations/{id}`: 제목 변경(1~200자)
  - `DELETE /api/ai/conversations/{id}`: 대화·메시지·저장된 질문(`ai_executions`)을 삭제한다. 진단 로그(`ai_traces`)는 M10-D04의 30일 보관을 따른다.
- 남의 대화는 모든 작업에서 404로 응답한다.
  - `POST /api/ai/queries`에 남의 `conversationId`를 보내도 404다. 이식본은 소유자를 확인하지 않아서 남의 대화에 질문을 덧붙일 수 있었다.
  - 질문할 때마다 대화의 `updatedAt`을 갱신해 목록 순서를 맞춘다.
- `ApiException.notFound` 추가

### Frontend (`feature/ai-conversation-history`, `feature/openlens-ai-chat` 위, 로컬 커밋)

- 팀 채팅과 같은 왼쪽 목록(`chat-list`)에 `대화 기록`과 `새 대화`를 둔다.
- 항목을 누르면 다시 열고, 각 항목에서 제목 변경(인라인 입력)과 삭제(확인 창)를 할 수 있다.
- 다시 연 대화에서도 같은 대화로 이어서 질문한다.
- 질문하면 목록을 다시 불러온다.
- 휴대폰 폭에서는 `대화 기록` 버튼으로 목록과 대화를 전환한다.
- MSW: 브라우저 메모리의 대화 저장소와 목록·다시 열기·제목 변경·삭제 핸들러를 추가했다. 새로고침하면 mock 대화가 사라진다.
  - 공통 `response()` 래퍼가 `Response`(204)를 그대로 돌려주도록 했다.

## 6. 남은 작업 / 보류 사항

- 다시 열 때 원래 질문의 부가 조건(원결제일 기준 환불, 0원 채우기 요청)은 저장돼 있지 않아 기본값으로 다시 실행한다.
- 이식본은 `ai_executions`에 결과(`envelope_json`)도 저장한다. 이는 M10-D12("결과 데이터는 저장하지 않는다")와 어긋나며 별도 정리가 필요하다.
- API 계약 문서(`openapi.json`, #92)에는 아직 반영하지 않았다.
- PR은 사용자가 화면을 확인한 뒤 올린다.
