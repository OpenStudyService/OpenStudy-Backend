# 2026-11-16 계획 캐시가 같은 질문에도 LLM을 다시 부르던 문제 수정

## 1. 배경 / 문제

계획 캐시(`2026-11-16-ai-plan-cache.md`) 병합 후 사용자가 live 모드에서 직접 시험했다. 두 가지 문제가 확인됐다.

1. "이번 달 가장 많이 판매된 이용권을 보여줘" 다음에 "이번 달 제일 많이 팔린 이용권 보여줘"를 물었는데 Qwen이 호출됐다.
   - 두 질문은 같은 대화에 있었다(로컬 DB의 `ai_executions`로 확인).
   - 캐시는 대화에 이전 결과가 있으면 찾지도 저장하지도 않았다.
   - 유사도 문제는 아니었다. 이 두 질문의 유사도는 0.96이고, 서버 판독도 같다.
2. 완전히 같은 질문("지난 달 지점별 매출을 비교해줘")을 새 대화에서 다시 해도 Qwen이 호출됐다.
   - 첫 질문의 결정이 캐시에 저장되지 않았다(`ai_plan_cache`에 행이 없음).
   - 이 질문은 키워드 규칙이 분석(`branchComparison`)을 정한다. 그런데 live 모드에서는 그 뒤에 Qwen도 부른다.
   - 캐시는 **Qwen의 응답이 등록 분석을 지목했을 때만** 저장했다. Qwen 원 응답은 기록되지 않아 확인할 수 없었지만, 저장을 건너뛰는 조건은 이것뿐이다.

## 2. 검토한 선택지

| 문제 | 선택지 | 결정 |
|---|---|---|
| 1 | 대화 안에서도 후속 질문이 아니면 캐시를 찾고, 저장은 대화의 첫 질문만 | 적용 |
| 2 | 키워드 규칙이 분석을 정하면 Qwen을 부르지 않음 | 사용자가 이번에는 적용하지 않기로 함 |
| 2 | Qwen 응답 대신 서버가 실제로 실행한 결정을 저장 | 적용 |

## 3. 결정 및 이유

- **찾기와 저장 조건을 나눴다.**
  - 찾기: 후속 질문이나 선택지 응답이 아니면 대화 안에서도 찾는다.
  - 저장: 대화의 첫 질문만 저장한다. 그래서 캐시에는 이전 맥락 없이 읽은 결정만 쌓인다.
  - 맥락에 기대는 짧은 질문("그럼 지난달은?")은 저장된 완전한 질문과 유사도가 낮고, 서버 판독도 달라서 잘못 재사용되지 않는다.
- **저장하는 것은 서버가 실행한 결정이다.**
  - 등록 분석, 의도 도메인, 환불 기준, 0원 채우기를 저장한다.
  - 키워드 규칙이 정했든 Qwen이 정했든 같다.
  - Qwen 응답을 조건으로 두면 Qwen이 분석을 지목하지 않을 때마다 같은 질문이 계속 Qwen을 부르게 된다.
- **캐시 결정을 로그로 남긴다.**
  - 기록: 적중, 미적중(가장 가까운 유사도, 서버 판독이 달라 제외된 수), 저장, 건너뜀(후속 질문)
  - 질문 문장은 로그에 남기지 않는다.

## 4. 구현 내용

- `OpenStudyPlaybackGateway.planQuestion`
  - 찾기 조건을 "후속 질문·선택지 응답이 아님"으로 넓혔다.
  - 저장은 EXECUTE로 끝날 때 최종 결정(`resolvedAnalysisId` 등)으로 한다. 조건은 Qwen을 부른 경우이면서 대화의 첫 질문인 경우다.
- `AiPlanCache`: 적중·미적중·저장 로그를 추가했다.
- `AiModelBoundaryIntegrationTests`(Qwen 대신 로컬 가짜 서버)에 테스트 두 개를 추가했다.
  - Qwen이 분석을 지목하지 않아도(CLARIFICATION 응답), 키워드로 정해진 같은 질문은 새 대화에서 Qwen을 다시 부르지 않는다.
  - 같은 대화의 두 번째 질문(후속 질문 아님)이 캐시를 쓴다. 저장은 첫 질문만 한다.

## 5. 검증 결과

- `AiModelBoundaryIntegrationTests` 통과(추가한 두 테스트 포함).
  - 로그로도 확인했다. 같은 질문은 유사도 1.0, 같은 대화의 다른 표현은 0.962로 적중했다.
- 백엔드 AI 범위 테스트 통과: `modules.ai.*`, `domainlens.*`, `AiSalesEquivalenceIntegrationTests`.
  - 처음 실행에서 `AiPlanCacheIntegrationTests`가 다른 테스트가 남긴 캐시 행 때문에 실패했다. 이제 키워드로 정해진 질문도 저장되므로 생긴 일이다. AI 테스트가 시작 전에도 캐시를 비우게 하고, 적중 횟수 확인을 그 테스트의 버전 키로 한정해 해결했다.
- live 모드(실제 Qwen) 재확인은 하지 않았다. 병합 후 사용자가 같은 시나리오로 확인할 수 있다. 백엔드 로그의 `AI plan cache hit`/`miss`/`stored`로 결과를 볼 수 있다.
- 전체 백엔드 테스트(`./gradlew test`)는 실행하지 않았다. M11 마일스톤 테스트로 미뤘다.

## 6. 남은 작업 / 보류 사항

- 키워드 규칙이 분석을 정한 질문도 처음 한 번은 Qwen을 부른다. 아예 부르지 않게 하는 안은 사용자 결정으로 보류했다.
- 로컬 DB에 이미 있는 캐시 행(이전 규칙으로 저장된 것)은 그대로 쓸 수 있다. 저장 형식은 바뀌지 않았다.
