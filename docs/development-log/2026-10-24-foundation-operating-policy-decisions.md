# 권한·상품·직원 운영 정책 선택 반영

작성일: 2026-10-24. 작업 브랜치: `docs/foundation-db-api`.

## 1. 배경 / 문제

사용자가 1차 설계의 추가 확인 항목을 검토하고 선택지로 결정할 수 있게 요청했다. 권한 관련3개, 상품 관련3개, 승인·복구·기한 관련3개의 질문에 명시적으로 답했다. 기존 Q1~Q3에 이어 Q4~Q12로 기록해 설계의 운영상 모호함을 줄였다.

## 2. 검토한 선택지

- 권한 위임은 ‘보유 권한 내 관리자까지 관리’, ‘일반 직원만 관리’, ‘지점 권한 전권’ 중 일반 직원만 관리하는 안을 선택했다.
- 일반 직원 기본 권한은 조회만 시작하는 안과 현장 변경 권한을 기본 부여하는 안 중 조회만 선택했다. 상품 등록·가격·구성은 운영 변경 권한을 가진 직원에게 허용하는 기존 SRS를 유지했다.
- 공유 상품과 지점별 독립 상품 중 공유 방식을 선택했다. 상품 삭제는 전면 미제공 대신 거래 이력0건이면 물리 삭제를 선택했다. 유형은 이력 유무와 무관하게 등록 후 변경하지 않는다.
- 승인 후 자동 세션 전환 대신 재로그인, 소속 직접 복구 대신 기존 계정의 재초대·수락·승인, 수동 재발급의 최초 만료 시각 유지 대신 새24시간 부여를 선택했다.

## 3. 결정 및 이유

이번 변경은 사용자가 선택한 운영 정책을 반영한 것이다. 권장 표시 여부를 승인으로 해석하지 않고 실제 답변을 적용했다. 특히 사용자가 권장안과 다르게 선택한 다음 두 항목을 기존 설계에서 변경했다.

- 지점 관리자는 일반 직원만 관리한다. 다른 관리자 임명·권한 변경·승인은 OWNER만 가능하고 자기 권한 변경도 거부한다.
- 미거래 상품은 물리 삭제를 허용한다. 원래 상품 ID·조건·작업자·시각·삭제 감사를 보존하도록 이력 구조를 보완한다.

이미 승인한 지점별 저장·프리셋 복사·직원 전역 수정 OWNER 전용·제한 세션 정책은 유지했다. 일반 직원 기본 권한은 빈 집합, 지점 관리자 기본 권한은 담당 지점9종 전체로 기록했다.

## 4. 구현 내용

- decisions.md에 Q4~Q12의 실제 선택과 적용 경계를 추가하고 README·DB·API·개발 계획·추적표를 동기화했다.
- 소속 변경은 현재·요청 역할을 모두 검사하도록 명시했다. MANAGER를 STAFF로 낮춘 뒤 편집하거나, STAFF 초대로 MANAGER 역할을 우회 변경하는 경로도 제한했다.
- 기본 권한 프리셋과 대상 역할 제한을 OpenAPI 확장 메타데이터에 기록하고 관련 operation에 정책 ID를 연결했다.
- `DELETE /products/{id}`를 추가해 query version·CSRF·전체 지점 관리 권한·거래 참조0건을 요구한다. 성공200, 참조/버전 충돌409, 삭제 후 일반 상세404로 정했다.
- product_revisions는 nullable 생존 상품 FK와 불변 original_product_id를 분리했다. DELETED 이력의 before는 삭제 직전 조건, after는 NULL이다. 상품 삭제 뒤에도 원래 ID와 과거 지점 범위로 history를 조회한다. 기존 결제·발급의 RESTRICT는 유지했다.
- Q12에 따라 수동 재발급은 미수락 PENDING/EXPIRED에 새24시간을 부여하되 중복 진행 초대가 없어야 한다. 자동 retry는 기존 expires_at, 수락 후 승인 대기는 무기한이다.
- OpenAPI를 `0.1.2-design`으로 올렸다. 검증 스크립트에 확정 정책12개·기본 프리셋·역할 위임·초대 대상·삭제 요청/이력 schema 검사를 추가했다.

## 5. 검증 결과

- 캐시된 swagger-cli OpenAPI 표준 검사 통과.
- 로컬 설계 검사 통과: 요구사항61·중분류8·operation40·schema57·내부 참조544·이슈16·확정 정책12.
- `git diff --check` 통과. 원본 SRS와 요구사항 추출 사본의 해시 일치 확인.
- 운영 코드·Flyway V1·개발 DB는 변경하지 않았다. 실행용 migration과 DB·HTTP·브라우저 동작 검증은 이번 설계 갱신에서 수행하지 않았다.

## 6. 남은 작업 / 보류 사항

- 제시한 후속9개 질문에 대한 답변 대기는 모두 해제했다. 기존 기술적 선행 관계에 따라 구현할 수 있다.
- 실제 migration·상품 삭제 경합·관리자 권한 위임 거절·프리셋 seed·화면 동작은 구현 이슈의 인수 조건으로 검증한다.
