# 2026-10-28 M13 지점 휴무 효과·판매 한도·고객 병합·마감 후 변경 정책 확정

## 1. 배경 / 문제

M13(운영·거래 확장) 이슈를 작성하려고 SRS v1.10의 M13 요구사항 7개와 V1 스키마를 대조했다. 지점 휴무, 상품 판매 기간·한도, 고객 병합, 일별 마감에 쓸 테이블·칼럼이 V1에 없다. 마일스톤 비고도 "원문이 확정하지 않은 세부 정책은 구현 전에 결정한다"고 적고 있다. 다음이 정해지지 않았다.

- 휴무일이 어떤 업무를 막는지
- 판매 한도의 범위와 환불 시 복원 여부
- 고객 병합 권한과 병합 취소 지원 여부
- 마감된 날의 거래가 바뀔 때의 처리

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 휴무 효과 | 안내 + 룸 예약만 차단 / 안내만 / 신규 업무 전체 차단 |
| 판매 한도 | 상품 전체·환불 시 복원 / 상품 전체·복원 없음 / 지점별 |
| 고객 병합 | OWNER만·되돌리기 없음 / members:write 보유자 / OWNER만·병합 취소 지원 |
| 마감 후 변경 | 허용하되 조정 기록 / 마감 해제 후 변경 |

## 3. 결정 및 이유

사용자가 모두 권장안을 선택했다. 상세는 [ADR-M13-001](../db/ADR-M13-001.md)에 있다.

- 휴무일은 안내하고 그날 시작하는 룸 예약만 막는다.
- 판매 한도는 상품 전체 수량이고 환불하면 복원한다.
- 고객 병합은 OWNER만 하고 되돌리지 않는다.
- 마감 후 변경은 허용하고 조정 이력으로 남긴다.
- 휴무 관리 권한, 판매 가능 확인 순서, 병합 시 참조 처리, 마감 단위, 점유 추이 계산, 고급 필터 범위(M13-D05~D10)는 SRS와 V1에서 도출한 구현 기준으로 함께 기록했다.

## 4. 구현 내용

- `docs/db/ADR-M13-001.md`: M13-D01~D10과 스키마 영향을 기록했다.
- 저장소 밖 변경(이 커밋에 포함하지 않음): 작업공간 SRS를 v1.11로 만들었다. POL-39~42를 추가하고 FR-BR-09, FR-PROD-10, FR-MEM-08, FR-PAY-14를 갱신했다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 `products`·`customers` DDL과 휴무·마감 관련 테이블이 없음을 확인했다.

## 6. 남은 작업 / 보류 사항

- 병합된 고객의 일반 조회 범위(M4-D05)는 대상 고객 기준으로 합쳐 보이게 구현에서 검증한다.
- 환불 유형이 늘어나면(부분 환불 등) 고급 집계 필터를 다시 정한다.
