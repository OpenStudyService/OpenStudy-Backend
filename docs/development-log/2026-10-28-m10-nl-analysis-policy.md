# 2026-10-28 M10 DomainLens 엔진 경계·자연어 질의 제한·결과 상한·진단 로그 보관 정책 확정

## 1. 배경 / 문제

M10(자연어 분석·동적 시각화) 이슈를 작성하려고 SRS v1.7의 M10 요구사항 47개와 V1 스키마, DomainLens 저장소를 확인했다.

- SRS는 DomainLens 엔진과 LLM으로 QuerySpec·ViewSpec을 만들도록 요구한다. 그러나 DomainLens(`D:\Dev\workspace\DomainLens`)는 Boot 3.3 기반 실험 단계이고, OpenStudy가 의존할 엔진 starter가 없다. 이 폴더는 git 저장소도 아니다.
- 자연어 질의 빈도 제한(NFR-SEC-10)의 값, 결과 표시 상한(FR-VIZ-07)의 값이 없다.
- 진단 로그에 질문 원문을 남길지(FR-AUD-02) 정해지지 않았다.
- V1 `ai_requests`에는 진단에 필요한 칼럼이 없다.

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 엔진 의존 | 포트 분리 + 엔진은 별도 작업 / Spring AI 직접 연동(SRS 변경) / 엔진 개발까지 M10에 포함 |
| 빈도 제한 | 구조만 만들고 값은 측정 후 / 지금 값 확정 |
| 결과 상한 | 표 50행·최대 1,000행·차트 20개 / 표 100행·최대 5,000행·차트 30개 |
| 질문 원문 | 저장 안 함 / 저장 + 짧은 보관 |
| 원문 보관 기간 | 7일 / 30일 / 90일 |

## 3. 결정 및 이유

사용자가 결정했다. 상세는 [ADR-M10-001](../db/ADR-M10-001.md)에 있다.

- 명세 생성은 포트 뒤에 두고, OpenStudy 쪽 카탈로그·검증·실행·SSE·화면을 먼저 만든다. 실제 엔진 연동은 starter가 나온 뒤 별도 이슈로 한다.
- 빈도·예산 제한은 구조만 만들고 값은 측정 후 정한다. M5 조회 제한과 같은 방식이다.
- 결과는 표 50행 페이지·최대 1,000행, 차트 상위 20개로 제한한다.
- 질문 원문은 해석 품질 분석을 위해 저장하고 30일 뒤 삭제한다. 사용자가 권장안(저장 안 함) 대신 이 방식을 골랐다.
- M9 공통 집계 재사용, 매출 질문 권한, 모델 전송 데이터 제한, 진단 테이블 추가(M10-D05~D08)는 SRS와 V1에서 도출한 구현 기준으로 함께 기록했다.

## 4. 구현 내용

- `docs/db/ADR-M10-001.md`: M10-D01~D08을 기록했다.
- 저장소 밖 변경(이 커밋에 포함하지 않음): 작업공간 SRS를 v1.8로 만들었다. POL-27~30을 추가하고 FR-NL-02, FR-AUD-02, FR-VIZ-07, NFR-SEC-10, NFR-OPS-07을 갱신했다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 DDL(`ai_threads`, `ai_requests`)과 DomainLens의 `compatibility.md`, `docs/task/00-current-state.md`를 읽어 결정과 맞는지 확인했다.

## 6. 남은 작업 / 보류 사항

- DomainLens starter 개발은 DomainLens 쪽에서 관리한다. 등록할 저장소와 일정은 정해지지 않았다.
- 빈도·예산 제한값은 실제 모델 측정 후 사용자가 정한다.
- M10 마일스톤 인수(실제 모델·MySQL 대표 질문 수치 일치)는 엔진 연동 후에 가능하다.
