# 2026-10-28 M4 이용권 유효기간·환불·고객 범위 정책 확정

## 1. 배경 / 문제

M4(고객·이용권 판매·환불) 이슈를 작성하는 중에 구현에 영향을 주는 정책 여섯 가지가 비어 있거나 기존 결정과 달라질 필요가 있었다.

- V1의 `customers`는 전사 원장이라 지점 열이 없다. FR-MEM-01의 "접근 가능 지점의 고객만" 조건을 판정할 수 없다.
- FR-MEM-02의 응대 메모를 저장할 열이 없다.
- ADR-M3M4-001은 Mock 결제의 승인·실패 제어 방식과 시간권·정액권의 유효기간 시작 기준을 미결로 남겼다.
- ADR-M3M4-001 D03은 기간권을 첫 입실 시 개시하도록 정했으나, 사용자는 모든 이용권을 발급 시각에 시작하도록 바꾸기로 했다.
- 환불 권한은 문서마다 "관리자"로만 되어 있었다.
- 환불 규칙은 "실제 사용 이력이 없으면 전액 환불"만 정하고 만료 여부를 다루지 않았다. 유효기간이 발급 시각에 시작되면 기간권도 사용하지 않은 채 만료될 수 있어 이 공백이 커진다.

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 고객 범위 | 등록 지점 + 결제 지점 / 등록 지점만 / 전사 공유·정확 일치 검색 / 전사 공유 목록 |
| Mock 결과 | 요청 필드로 선택 / 항상 승인 / 개발 환경에서만 실패 허용 |
| 환불 권한 | OWNER + 원결제 지점 MANAGER / OWNER만 / `payments:write` 보유자 |
| 유효기간 시작 | 모두 발급 시각 / 기간권만 첫 입실 시(기존 D03) |
| 만료 이용권 환불 | 만료 전까지만 / 만료돼도 미사용이면 허용 / 만료 후 일정 기간까지 |

## 3. 결정 및 이유

사용자가 다음과 같이 확정했다. 상세는 [ADR-M4-002](../db/ADR-M4-002.md)에 있다.

- 모든 이용권의 유효기간은 결제 승인·발급 시각에 시작한다. 세 유형을 같은 기준으로 다뤄 조회·만료·환불 판정이 단순해지고, SRS의 "발급 시 시작·종료 결정" 문구와도 다시 일치한다.
- 기간권 1일 = 연속 24시간(D04)은 유지하고 기준 시각만 발급 시각으로 바꾼다.
- 환불은 원결제 지점의 `payments:write` 보유자가 처리하고, 사용 이력이 없고 만료되지 않은 이용권만 허용한다. 기간권은 잔량을 차감하지 않으므로 사용 이력은 `seat_sessions` 존재로도 판정한다.
- 고객 범위는 등록 지점 + 결제 지점, 메모는 `customers.memo`, Mock 결과는 `mockOutcome` 요청 필드로 정한다.

기존 결정은 지우지 않았다. ADR-M3M4-001의 결정 표와 본문은 그대로 두고, 상태 줄과 변경 이력에 대체 사실만 추가했다.

## 4. 구현 내용

- `docs/db/ADR-M3M4-001.md`: 2026-10-26 원본을 먼저 저장소에 추가한 뒤, D03·D05 대체 표시와 변경 이력을 덧붙였다. 이 파일은 그동안 로컬에만 있었다.
- `docs/db/ADR-M4-002.md`: 신규 결정 M4-D01~D08, 미사용·만료 판정 규칙, 스키마 정합성 확인 결과를 기록했다.
- 스키마 확인: V1의 `ck_passes_period_activation`은 기간권 `ACTIVE`에 시작·만료 시각이 있기를 요구하므로, 발급 시각에 시작하는 새 값과 맞는다. P4 때문에 바꿀 스키마는 없다. `NOT_STARTED` 값과 CHECK 분기는 V1에 남기고 신규 흐름에서 만들지 않는다. V2는 고객 지점·메모 열 두 개만 추가하며 실제 SQL은 M4 계약 이슈에서 작성한다.
- 저장소 밖 변경(이 커밋에 포함하지 않음)
  - 작업공간 `docs/planning/SRS/OpenStudy_Service_SRS_v1.2.xlsx`를 v1.1에서 만들었다. POL-04~06을 추가하고 FR-MEM-01·FR-PASS-08·FR-PAY-09와 M4 완료 기준을 갱신했으며, FR-PAY-09의 목표 마일스톤을 M6에서 M4로 옮겼다. v1.1은 그대로 두었다.
  - 로컬 설계 문서 `docs/db/data-integrity.md`(저장소 미추적)의 3~5절과 검증 표를 새 정책에 맞추고, 이전 결정 문구를 함께 남겼다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 DDL의 `passes` CHECK 제약을 읽어 새 발급 값과 맞는지 확인했다. 실제 DB 적용 검증은 하지 않았다.
- SRS v1.2는 저장 후 다시 열어 시트 6개와 행 수(정책 20행, 변경 이력 13행)를 확인했다.

## 6. 남은 작업 / 보류 사항

- V2 SQL 작성과 기존 고객 행의 `registered_branch_id` 처리는 M4 계약 이슈에서 진행한다.
- M4 이슈 등록은 사용자 확인 후 진행한다.
- Frontend의 "환불은 관리자 전용" 안내 문구는 M4 Frontend 이슈에서 바꾼다.
- `docs/design/foundation/decisions.md` Q2(기간권 발급 시점)와의 관계는 M4 계약 문서 작성 시 함께 정리한다.
