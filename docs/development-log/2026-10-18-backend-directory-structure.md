# 백엔드 디렉토리 골격 구성

작업일: 2026-10-18 KST.

## 배경과 문제

사용자가 요구사항 명세서 v1.1과 요구조건 식별/WBS v1.1을 바탕으로 백엔드 프로젝트의 디렉토리 구성을 요청했다. 기존 백엔드에는 설계 문서만 있으며 소스·빌드 설정·Git 저장소가 없었다.

## 검토한 선택지

전체 controller/service/repository를 최상위에 모으는 방식과 기능별 패키지 안에 계층을 두는 방식을 비교했다. 기능별 소유 범위를 명확히 하고 기존 P24와 M1-02를 따르기 위해 후자를
선택했다. 근무표/근태/휴가/대체근무의 개별 모듈 분리도 검토했으나 전 지점 시간 충돌·승인 트랜잭션의 중첩을 고려해 workforce 내부 하위 영역으로 묶었다.

## 결정과 이유

- 단일 빌드 안에 20개 업무 모듈, 모듈별 api/presentation/application/domain/infrastructure를 둔다.
- api는 모듈 간 Java 계약으로 사용하고 HTTP 처리는 presentation에 둬 경계를 구별한다.
- 공통 기반은 shared/platform, 설정 조립과 최초 사장님 명령·시드는 bootstrap에 둔다.
- `com.openstudy`는 이번 골격의 기본 네임스페이스다. 조직 네임스페이스는 별도 확정 전이다.
- 문서에 정확한 JDK/Boot/Wrapper 버전이 미확정으로 기록되어 있어 이번 디렉토리 작업에서 버전을 임의 고정하지 않는다.

## 구현 내용

소스/리소스/테스트/스크립트 디렉토리와 Git 보존용 .gitkeep, 모듈 책임을 설명하는 package-info.java를 추가했다. README와
architecture/directory-structure.md에 요구사항/WBS 대응·공개 경계·트랜잭션·테스트 배치를 기록했다. 프로필·이메일 ID·초대 토큰·일반 좌석 예외 지원·최소 매출
원장·DomainLens 컨슈머 정책을 책임 설명에 반영했다. 기존 문서·첨부 파일은 수정하지 않았다.

## 검증 결과

정적 구조 검증을 통과했다. 20개 모듈의 100개 계층 디렉토리와 모듈별 테스트 위치, Java 패키지 설명 20개의 선언/경로 일치, 새 문서의 상대 링크 4개 대상, workbook 128개 요구사항의 구조
문서 대응 범위를 확인했다. 기존 백엔드 파일 5개는 SHA-256 비교로 변경 없음을 확인했다. 새 파일은 빈 디렉토리 보존 파일을 포함해 183개다.

실행 가능한 업무 코드·빌드·ArchUnit 테스트는 추가하지 않아 서버 기동/테스트·실DB/SMTP/엔진 연결은 수행하지 않았다. 이는 기능 인수나 실제 의존성 검증의 통과를 의미하지 않는다.

## 남은 작업

BE-002 빌드/Wrapper/실행 클래스, BE-003 ArchUnit, BE-004 공통 오류/검증, BE-005~007 DB/시드 작업이 남아 있다. 현재 구조는 BE-003 중 패키지 골격만 충족하며 해당
Task 전체를 완료 처리하지 않는다. M1 전체 범위도 확정하지 않았다.

문서 저장소 분리/이관도 후속 작업으로 유지했다.
