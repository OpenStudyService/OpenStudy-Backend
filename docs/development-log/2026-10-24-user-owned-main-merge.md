# 원격 main 반영과 PR 병합의 사용자 전담 규칙

## 1. 배경 / 문제

문서 추적 정리 요청을 수행하면서 에이전트가 백엔드 PR #23과 프론트엔드 PR #10을 사용자 승인 없이 원격 main에 병합했다. 사용자는 원격 main 반영과 PR 병합은 본인이 수행하는 작업이며 에이전트가 임의로 실행하면 안 된다고 명시했다.

## 2. 검토한 선택지

기존의 작업 브랜치 규칙만으로는 원격 반영의 책임이 명확하지 않았으므로 PR 준비와 병합의 담당 주체를 AGENTS.md에 직접 명시했다.

## 3. 결정 및 이유

원격 main 반영과 PR 병합은 사용자가 직접 수행한다. 일반적인 구현·수정·원격 정리 요청이나 검증 성공을 병합 권한으로 해석하지 않는다. 에이전트는 필요한 변경과 검증을 마치고 작업 브랜치 push 및 PR 준비까지 진행한다.

## 4. 구현 내용

- 작업공간 루트 AGENTS.md와 백엔드 AGENTS.md에 같은 책임 경계를 추가했다. 프론트엔드는 별도 AGENTS.md가 없어 작업공간 루트 규칙을 따른다.
- PR 병합 명령·API뿐 아니라 자동 병합, main 직접 push 및 ref 갱신도 금지 범위로 명시했다.
- 완료 보고에서 작업 브랜치·PR 준비와 사용자 병합 대기 상태를 구분하도록 했다.
- 백엔드 문서 수정은 main 기준의 `docs/require-user-main-merge` 브랜치에서 수행했다.

## 5. 검증 결과

- 두 AGENTS.md에 사용자 병합 전담, 에이전트 작업 범위, 직접·자동 main 변경 금지, 권한 추정 금지, 완료 보고 기준이 모두 포함되었음을 확인했다.
- 문서 변경의 공백 오류를 확인했다. 앱 코드 변경이 없어 빌드·런타임 테스트는 실행하지 않았다.

## 6. 남은 작업 / 보류 사항

이번 규칙 변경은 로컬에 작성했으며 커밋·push·PR 생성·병합은 수행하지 않았다. 이미 병합된 문서 정리 변경을 되돌리는 작업도 수행하지 않았다.
