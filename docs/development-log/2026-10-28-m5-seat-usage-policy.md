# 2026-10-28 M5 이용권 사용 지점·타 지점 입실 조회·좌석 차감 정책 확정

## 1. 배경 / 문제

M5(좌석 이용·이용권 차감) 이슈를 작성하는 중에 구현에 영향을 주는 정책이 비어 있었다.

- FR-PASS-13(이용권 사용 가능 지점)은 기존 설계 문서에서 "정책 보류"였다.
- 정액권 차감 금액의 반올림 기준, 기간권 이용 중 만료 처리, 수동 조정 권한이 정해지지 않았다.
- 이용권을 모든 지점에서 쓰기로 정하자, M4의 고객 조회 범위(등록 지점·결제 지점, ADR-M4-002 M4-D05)로는 다른 지점 직원이 그 고객을 찾지 못해 입실을 처리할 수 없는 충돌이 생겼다.

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 사용 지점 | 구매 당시 판매 지점 / 구매 지점만 / 현재 판매 지점 / 모든 지점 |
| 정액권 금액 | 원 단위 올림 / 내림 / 반올림 |
| 기간권 이용 중 만료 | 만료 이후분을 초과량 기록 / 그대로 허용 / 자동 퇴실 |
| 수동 조정 권한 | OWNER + 구매 지점 MANAGER / `payments:write` 보유자 / OWNER만 |
| 타 지점 입실 조회 | 정확 일치 조회만 / 정확 일치 조회 + 이용 지점을 고객 조회 범위에 추가 |

조회 횟수 제한은 기존 `LoginAttemptLimiter`를 재사용할 수 있는지 코드를 읽고 검토했다.

## 3. 결정 및 이유

사용자가 다음과 같이 확정했다. 상세는 [ADR-M5-001](../db/ADR-M5-001.md)에 있다.

- 이용권은 모든 활성 지점에서 사용한다.
- 정액권은 원 단위 올림, 기간권 이용 중 만료는 만료 이후 이용 분을 초과량으로 기록한다.
- 수동 조정은 구매 지점의 `payments:write` 보유자가 한다. 환불과 같은 기준이다.
- 타 지점 입실은 회원번호·연락처 정확 일치 조회로만 지원하고, 일반 고객 조회 범위는 넓히지 않는다. 입실 이후 퇴실·이동은 이용 기록의 지점 권한으로 처리한다. 조회는 `customer_service_interactions`에 기록한다.
- 조회 횟수 제한은 M5에서 제외하고 후속 과제로 둔다. 기존 제한기는 계수기가 클래스 내부에 묶여 있고 공개 API·예외·429 처리가 로그인 전용이라, 재사용하려면 공통 컴포넌트 분리와 로그인 제한 수정이 함께 필요하다. 사용자가 "간단한 확장이면 포함, 복잡하면 분리"를 기준으로 제시했고, 제한값도 실제 사용량 없이 정하지 말라고 했기 때문이다.

## 4. 구현 내용

- `docs/db/ADR-M5-001.md`: M5-D01~D08과 Rate Limiter 재사용 검토 결과를 기록했다.
- 스키마 변경 없음. 일치하는 고객이 없는 조회는 `customer_service_interactions.customer_id`가 필수라 기록할 수 없어 `audit_events`에 남기도록 정했다.
- 저장소 밖 변경(이 커밋에 포함하지 않음): 작업공간 SRS를 v1.3으로 만들었다. POL-07~10을 추가하고 FR-SEAT-06·FR-SEAT-14·FR-PASS-12·FR-PASS-13을 갱신했다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 DDL(`seat_sessions`, `seat_session_moves`, `customer_service_interactions`, `audit_events`)과 `LoginAttemptLimiter` 소스를 읽어 결정과 맞는지 확인했다.

## 6. 남은 작업 / 보류 사항

- 조회 횟수 제한은 후속 이슈로 등록한다. 제한값은 실제 사용량을 근거로 사용자가 정한다.
- 타 지점 이력 요약(POL-01)은 M6 범위다.
- 이 ADR은 ADR-M4-002(PR #54)를 참조한다. 두 PR의 병합 순서는 상관없다.
