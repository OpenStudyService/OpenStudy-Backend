# 2026-10-28 M8 근무표 관리 권한·근태 조회 범위·근무 길이·운영 중지 지점 정책 확정

## 1. 배경 / 문제

M8(근무표·본인 출퇴근) 이슈를 작성하려고 SRS v1.5와 V1 스키마를 대조했다. 테이블은 모두 있고 `modules/workforce`는 비어 있다. 다음이 정해지지 않았다.

- SRS는 근무표 관리자를 "관리자"로만 적었고, 근무 전용 권한 코드가 없다.
- "관리자는 권한 범위의 직원 근태를 조회"의 범위가 기록 지점 기준인지 소속 직원 기준인지 정해지지 않았다.
- 예정 근무의 "시간 범위 확인" 기준이 없다.
- 운영 중지 지점에서 출근·근무 등록을 허용할지 정해지지 않았다.

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 근무표 권한 | 대상 지점 MANAGER 이상 / `people:manage` 보유자 |
| 근태 조회 범위 | 기록 지점 기준 / 소속 직원 기준 |
| 근무 길이 | 24시간 이하 / 상한 없음 |
| 운영 중지 지점 | 신규 거부·진행 중 허용 / 모두 허용 |

## 3. 결정 및 이유

사용자가 모두 권장안을 선택했다. 상세는 [ADR-M8-001](../db/ADR-M8-001.md)에 있다.

- 근무표는 대상 지점 MANAGER 이상이 관리한다. 새 권한 코드가 필요 없다.
- 근태 조회는 기록 지점 기준이다. 다른 지점의 개인 근태가 노출되지 않는다.
- 예정 근무는 24시간 이하로 제한해 날짜 입력 실수를 막는다.
- 운영 중지 지점은 FR-BR-08과 같이 신규만 거부한다.
- 충돌 오류의 노출 범위, 승인 휴가 비교 방식, 실근무 분 계산, 출근과 예정 근무 연결(M8-D05~D08)은 SRS와 V1 스키마에서 도출한 구현 기준으로 함께 기록했다.

## 4. 구현 내용

- `docs/db/ADR-M8-001.md`: M8-D01~D08과 스키마 영향을 기록했다.
- 저장소 밖 변경(이 커밋에 포함하지 않음): 작업공간 SRS를 v1.6으로 만들었다. POL-19~22를 추가하고 FR-SHIFT-02·03, FR-ATT-01·05를 갱신했다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 DDL(`shifts`, `shift_events`, `attendance_records`, `attendance_breaks`, `leave_requests`, `shift_swaps`)을 읽어 결정과 맞는지 확인했다.

## 6. 남은 작업 / 보류 사항

- 휴가 승인·대체근무 흐름과 근태 정정은 M12에서 같은 충돌 검사에 연결한다.
- M8용으로 예약했던 V3 마이그레이션 번호는 필요하지 않게 되었다.
