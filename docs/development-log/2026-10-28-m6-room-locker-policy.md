# 2026-10-28 M6 스터디룸 예약 단위·사물함 요금·예약 취소·공간 업무 권한 정책 확정

## 1. 배경 / 문제

M6(룸 예약·사물함 유료 운영) 이슈를 작성하려고 SRS v1.3과 V1 스키마를 대조했더니 다음이 맞지 않거나 비어 있었다.

- 스터디룸: SRS는 정시 시작·1시간 단위·시간당 요금인데, V1은 00/30분 시작·30분 슬롯·30분당 요금이다.
- 사물함 요금: SRS(FR-PAY-12)는 지점별 4주 요금인데, V1은 사물함마다 요금 컬럼이 있다.
- 룸 예약 취소·환불을 언제까지 허용할지 정해지지 않았다.
- 예약·배정은 Mock 결제를 만들지만 기본 직원 프리셋에 결제 권한이 없어, 누가 처리하는지 정해야 했다.
- POL-01의 "관리자가 별도 응대 권한을 부여한 직원"에 해당하는 권한 코드가 없다.

## 2. 검토한 선택지

| 항목 | 선택지 |
| --- | --- |
| 룸 단위 | SRS 기준 + 새 마이그레이션 / V1 유지 + 서버 검증만 / SRS를 30분 단위로 변경 |
| 사물함 요금 | 사물함별 요금 유지 / 지점별 단일 요금(새 마이그레이션) |
| 룸 취소 시한 | 예약 시작 시각 전까지 / 이용 시작 전이면 종료 시각까지 |
| 업무 권한 | 원장 `operations:write` + 결제 `payments:write` / 원장 `facilities:write` + 결제 `payments:write` |

## 3. 결정 및 이유

사용자가 모두 권장안을 선택했다. 상세는 [ADR-M6-001](../db/ADR-M6-001.md)에 있다.

- 룸은 SRS 기준으로 새 마이그레이션을 만든다. 서버 검증만 두면 DB가 30분 예약을 허용해 원장이 요구사항과 어긋날 수 있기 때문이다.
- 사물함 요금은 사물함별로 두고 지점 일괄 적용을 제공한다. 스키마 변경이 없고 사물함마다 다른 요금도 표현할 수 있다.
- 사물함 기간은 V1 제약대로 28일 배수만 허용한다(사용자에게 질문할 때 함께 안내함).
- 룸 취소·환불은 시작 시각 전까지만 허용한다.
- 원장은 `operations:write`, 결제가 따르는 업무는 `payments:write`, 현장 처리(이용 시작·완료, 반납)는 지점 직원 누구나 한다.
- 타 지점 최소 요약은 OWNER·MANAGER와 새 권한 `customers:cross-branch-read` 보유 직원으로 제한한다. 권한 코드 이름은 구현 제안이다.

## 4. 구현 내용

- `docs/db/ADR-M6-001.md`: M6-D01~D06과 스키마 영향을 기록했다.
- 저장소 밖 변경(이 커밋에 포함하지 않음): 작업공간 SRS를 v1.4로 만들었다. POL-11~14를 추가하고 FR-LOCK-02·FR-ROOM-04·FR-PAY-12·FR-MEM-03을 갱신했다.

## 5. 검증 결과

- 문서 변경만 있어 테스트는 실행하지 않았다.
- V1 DDL(`rooms`, `room_reservations`, `room_reservation_slots`, `room_usages`, `lockers`, `locker_assignments`, `locker_assignment_charges`, `customer_service_interactions`, `payments`, `refunds`, `permission_definitions`)과 `BranchAction`을 읽어 결정과 맞는지 확인했다.

## 6. 남은 작업 / 보류 사항

- 룸 단위 변경과 권한 정의 추가는 M6 구현 이슈에서 새 버전 SQL로 만든다.
- 룸 운영 시간(`room_weekly_hours`) 안에서만 예약을 받을지는 SRS 요구가 없어 정하지 않았다.
