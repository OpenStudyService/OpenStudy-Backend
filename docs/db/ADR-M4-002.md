# ADR-M4-002 · 이용권 유효기간 시작, 고객 지점 범위, Mock 결제·환불 권한

- 상태: **확정(사용자 의사결정)**
- 기록일: 2026-10-28
- 적용 범위: M4 고객·판매·환불 계약과 이후 M5 입실·차감
- 대체: [ADR-M3M4-001](ADR-M3M4-001.md)의 M3M4-D03, D05. D04(기간권 1일 = 연속 24시간)는 계산 기준을 유지하고 기준 시각만 바꾼다.
- 근거: `FR-MEM-01/02/05`, `FR-PASS-01/02/08/10`, `FR-PAY-01/04/09/10`, SRS v1.2

## 결정

| ID | 최종 결정 | 선택 이유/결과 |
| --- | --- | --- |
| M4-D01 | **모든 이용권의 유효기간은 결제 승인·발급 시각에 시작한다.** 시간권·정액권·기간권 모두 `status=ACTIVE`, `started_at=발급 시각`으로 발급한다. | 세 유형을 같은 기준으로 다뤄 조회·만료·환불 판정을 단순하게 한다. SRS의 "발급 시 시작·종료 결정" 문구와도 다시 일치한다. |
| M4-D02 | **기간권 `expires_at = started_at + snapshot_period_days × 24시간`**, 경계는 `[started_at, expires_at)`. | ADR-M3M4-001 D04의 연속 24시간 계산을 유지한다. 기준 시각만 첫 입실에서 발급 시각으로 바뀐다. |
| M4-D03 | **시간권·정액권은 `snapshot_valid_days`가 있으면 `expires_at = started_at + valid_days × 24시간`, 없으면 `expires_at = NULL`(만료 없음).** 잔여 시간·잔액은 실제 이용 시에만 차감한다. | ADR-M3M4-001이 미결로 남긴 시간권·정액권 유효기간 시작 기준을 확정한다. |
| M4-D04 | **환불은 승인 결제이고, 이용권에 실제 사용 이력이 없고, 아직 만료되지 않은 경우에만 원결제 전액으로 허용한다.** | 기간권도 사용 없이 만료될 수 있게 되어, 만료 여부를 다루지 않던 기존 규칙의 공백을 막는다. 오래전에 산 미사용 이용권을 언제든 환불하는 일을 막는다. |
| M4-D05 | **고객 조회 범위 = 등록 지점이 접근 가능 지점이거나, 접근 가능 지점에서 결제한 고객.** V2에 `customers.registered_branch_id`를 추가한다. | V1의 `customers`는 전사 원장이라 지점 열이 없어 FR-MEM-01의 지점 범위를 판정할 수 없다. 타 지점 고객 최소 요약(POL-01)은 M6 FR-MEM-03에서 다룬다. |
| M4-D06 | **고객 응대 메모는 V2의 `customers.memo`(선택 입력)에 저장한다.** | FR-MEM-02의 선택 입력 항목을 저장할 열이 V1에 없다. 이력이 필요해지면 후속에서 분리한다. |
| M4-D07 | **Mock 결제의 승인·실패는 요청의 `mockOutcome: APPROVED \| FAILED`로 정하고 기본값은 `APPROVED`다.** | FR-PAY-04의 실패 기록을 실제 화면에서 재현할 수 있게 한다. 실제 금전 이동이 없음을 응답과 화면에 표시한다. |
| M4-D08 | **환불은 원결제 지점에서 `payments:write` 권한을 가진 사용자가 처리한다.** 처리 지점은 원결제 지점으로 고정한다. | 지점 관리자가 아니어도 결제 권한을 위임받은 직원이 현장에서 환불할 수 있게 한다. 일반 직원 기본 프리셋(Q5)에는 결제 권한이 없으므로 명시적으로 부여받은 직원만 해당한다. 타 지점 환불은 후속이다. |

## 미사용·만료 판정

- **실제 사용 이력**은 해당 이용권의 `seat_sessions` 행 또는 `pass_balance_events`의 `USE` 행이 하나라도 있는 경우다. 기간권은 잔량을 차감하지 않으므로 `seat_sessions` 존재로 판정한다.
- 기존에는 기간권의 `NOT_STARTED` 상태가 미사용의 근거였다. M4-D01 이후에는 상태로 미사용을 판단하지 않고 위 이력을 직접 확인한다.
- **만료**는 `expires_at`이 있고 요청 처리 시각이 `expires_at` 이상인 경우다. 저장된 `status`가 아직 `EXPIRED`로 바뀌지 않았더라도 시각으로 판정한다.
- 환불 처리는 원결제·이용권을 잠근 뒤 위 조건을 다시 확인하고, 환불 사건·결제 `REFUNDED`·이용권 `REFUNDED`·감사·멱등 결과를 한 트랜잭션으로 남긴다. 부분 환불은 없다.

## 스키마 정합성

- V1의 `ck_passes_period_activation`은 기간권 `ACTIVE`에 `started_at`·`expires_at`이 모두 있고 `expires_at > started_at`이기를 요구한다. M4-D01·D02의 발급 값이 이 조건을 만족하므로 P4 때문에 바꿀 스키마는 없다.
- `NOT_STARTED` 값과 해당 CHECK 분기는 V1에 그대로 남는다. 신규 발급 흐름은 이 상태를 만들지 않으며, 서비스가 보장한다. 이미 적용된 V1은 수정하지 않는다.
- V2는 M4-D05·D06의 열 두 개만 추가한다. 실제 SQL과 기존 고객 행의 `registered_branch_id` 처리 방식은 M4 계약 이슈에서 작성·검증한다.

## 영향

- M5 첫 입실: 기간권을 활성화하는 트랜잭션이 필요 없다. 입실 가드는 `ACTIVE`와 `[started_at, expires_at)` 경계만 확인한다.
- 조회: 기간권 "미개시" 표시가 사라지고, 모든 이용권이 발급 직후 시작·만료 일시를 가진다(만료 없는 시간권·정액권 제외).
- 환불 화면: 환불 버튼 노출 기준이 "관리자"에서 "`payments:write` 보유 + 미사용 + 미만료"로 바뀐다.
