# ADR-M7-001 · 업무·문의·시설 점검·공지·채널 권한과 시설 담당 모델

- 상태: **확정(사용자 의사결정)** · M7-D05~D07은 SRS 문구와 V1 스키마에서 도출한 구현 기준이며 리뷰에서 조정할 수 있다.
- 기록일: 2026-10-28
- 적용 범위: M7 업무·채널·현장 협업
- 근거: `FR-TASK-01~08`, `FR-CHAT-01/02/04~07/09`, `FR-FAC-01~05`, `FR-INQ-01~04`, `FR-NOTI-01~03`, SRS v1.5 POL-15~18

## 결정

| ID | 최종 결정 | 선택 이유/결과 |
| --- | --- | --- |
| M7-D01 | **업무는 지점 직원 누구나 등록한다. 내용·담당자·기한 수정은 등록자·담당자·해당 지점 MANAGER 이상이 한다. 상태 변경과 체크리스트도 같은 사용자가 한다.** 담당자는 해당 지점의 활성 직원만 지정할 수 있다. | 업무는 현장 협업 도구라 등록을 막지 않는다. 수정은 관련자로 좁혀 다른 직원의 업무를 임의로 바꾸지 못하게 한다. 새 권한 코드가 필요 없다. |
| M7-D02 | **고객 문의는 지점 직원 누구나 대리 등록하고 답변한다. 담당자 변경은 현재 담당자와 해당 지점 MANAGER 이상이 한다.** 대상 고객은 기존 고객 조회 범위(ADR-M4-002 M4-D05)와 정확 일치 조회(ADR-M5-001 M5-D05)로 찾는다. | 문의 접수·응대는 현장 업무다. 고객 정보 노출 범위는 넓히지 않는다. |
| M7-D03 | **시설의 담당자와 처리 상태는 진행 중인 점검 작업(`facility_works`, `kind = INSPECTION`)에 둔다.** 시설마다 열린 점검 작업은 하나다. 점검을 완료하면 작업을 닫고 시설의 상태·마지막 점검일을 갱신한 뒤, 같은 담당자로 다음 점검 작업을 연다. | V1 스키마를 그대로 쓴다. 시설 상태(정상·점검 필요·고장·사용 중지)와 업무 진행 상태를 분리한 V1 의도와 맞다. |
| M7-D04 | **전체 공지와 전체 채널은 OWNER만 만든다.** 지점 채널과 참여자는 해당 지점 MANAGER 이상이, 지점 공지는 대상 지점 모두에 `notices:write`가 있는 사용자가 관리한다. | 전체 범위 변경은 모든 지점에 영향을 주므로 최상위 역할로 제한한다. |
| M7-D05 | **시설 점검 항목의 등록·수정은 해당 지점 `facilities:write`, 점검 완료는 그 점검 작업의 담당자 또는 `facilities:write` 보유자가 한다.** | FR-FAC-02~04의 "시설 변경 권한"·"담당 권한"을 기존 권한 코드로 표현한다. |
| M7-D06 | **다음 점검일 = 마지막 점검 완료일 + 점검 주기(일).** 마지막 점검일이 없으면 등록일을 다음 점검일로 보고 바로 점검 대상이 된다. 목록과 홈은 같은 계산을 쓴다. | FR-FAC-05. 점검 이력이 없는 시설을 놓치지 않게 한다. |
| M7-D07 | **채널 참여 자격은 지점 소속 활성 직원이다.** 직원의 지점 소속이 해제되거나 계정이 비활성·이용 제한되면 해당 지점 채널 참여가 즉시 종료(`left_at`)되고 메시지를 읽을 수 없다. 공유된 업무 카드는 업무 원본의 접근 권한을 다시 확인한다. | M7 완료 기준의 "권한 회수를 후속 범위로 미루지 않는다"를 따른다. |

## 스키마 영향

없음. V1의 `work_tasks`, `task_checklist_items`, `task_events`, `conversations`, `conversation_members`, `messages`, `facility_types`, `facilities`, `facility_works`, `inquiries`, `inquiry_events`, `announcements`, `announcement_branches`로 구현한다. DM(`conversations.kind = DM`)과 채팅 실시간 전송은 M14 범위다.
