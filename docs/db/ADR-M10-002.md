# ADR-M10-002 · 팀 채팅 제외와 AI 채팅 단일화, AI 대화 저장 범위

- 상태: **확정(사용자 의사결정)** · M10-D09~D13은 2026-11-06 사용자 선택이다. 저장 데이터의 세부 칼럼과 operation 형태는 #92 계약에서 정한다.
- 기록일: 2026-11-06
- 적용 범위: M10 자연어 분석·동적 시각화(AI 채팅). M7 채널·메시지, M9 홈 메시지 카드, M14 1:1 대화·채팅 스트림의 범위를 바꾼다.
- 관련: [ADR-M10-001](ADR-M10-001.md)(엔진 경계·진단 로그), [ADR-M7-001](ADR-M7-001.md) M7-D04·D07~D09, [ADR-M14-001](ADR-M14-001.md) M14-D07·D08, [ADR-M9-001](ADR-M9-001.md)(홈 요약)
- 근거: SRS v1.14 POL-50·51, `FR-AICHAT-01~08`, `FR-DASH-05`, `FR-UI-01`, `FR-TASK-08`. SRS v1.14에서 `FR-CHAT-01~09`·`FR-TASK-07`을 삭제했다.

## 배경

SRS v1.13까지 채팅 화면은 직원 간 팀 채팅(채널·메시지·스레드·읽음·업무 카드 공유)이었고, M7에서 Backend #76·#77·#155와 Frontend 채팅 화면으로 구현됐다. 1:1 대화와 채팅 전용 실시간은 M14(#118·#121)로 남아 있었다.

사용자는 팀 채팅을 서비스에 넣지 않기로 했다. 채팅 화면은 AI 채팅 하나만 두고, 이 화면에서 DomainLens로 자연어 DB 조회만 한다.

## 결정

| ID | 최종 결정 | 선택 이유/결과 |
| --- | --- | --- |
| M10-D09 | **채팅 화면은 AI 채팅 하나다.** 직원 간 채널·참여자·메시지·스레드·읽음·업무 카드 공유·1:1 대화·채팅 실시간은 서비스 범위에서 뺀다. 업무 분석 아래의 별도 "AI 분석" 메뉴도 두지 않고 채팅 탭으로 합친다. | 사용자 선택. |
| M10-D10 | **이미 구현된 채널·메시지 코드와 테이블은 지우지 않고 비활성화한다.** `modules/chat`, `conversations`·`conversation_members`·`conversation_thread_reads`·`messages`는 남긴다. 설정 플래그(기본값 꺼짐)로 `/api/channels/**`를 노출하지 않고, Frontend도 같은 기준으로 팀 채팅 화면·채널 설정·업무 카드 공유를 보이지 않는다. 플래그 이름과 꺼졌을 때의 응답(404 여부)은 구현 이슈에서 정한다. | 사용자 선택. 되살릴 가능성을 남기고 마이그레이션·DROP 위험을 지금 지지 않는다. 남은 테이블은 DomainLens 의미 카탈로그(#93)에 등록하지 않는다. |
| M10-D11 | **홈의 "읽지 않은 메시지" 카드는 데이터 없는 AI 채팅 바로가기로 바꾼다.** 홈 요약 API(#90)에서 메시지 카드(`messages`·`HomeMessageCard`·`HomeChannelItem`·`link.screen=channel`)를 뺀다. 바로가기는 Frontend가 AI 조회 권한이 있을 때만 보인다. | 사용자 선택. 홈 API가 AI 채팅 데이터를 다시 모으지 않는다. |
| M10-D12 | **AI 대화는 서버에 저장한다. 질문·검증된 QuerySpec/ViewSpec·처리 상태·기준 시각만 저장하고 결과 데이터는 저장하지 않는다.** 대화는 만든 직원 본인만 본다. 저장된 대화를 다시 열면 저장된 명세를 현재 권한·지점 범위·예산으로 다시 검증·실행하고 새 기준 시각으로 보인다. 다시 열 때 모델을 호출하지 않는다. 실행할 수 없으면 결과 대신 사유를 보인다. | 사용자 선택. 권한이 회수된 뒤 과거 수치가 남아 보이지 않고, 결과 행이 보존·파기 대상에 들어가지 않는다. |
| M10-D13 | **AI 대화의 자동 보관 기간은 #99 보존 기간 결정에 포함한다.** 확정 전에는 사용자 삭제만 제공하고 자동 삭제하지 않는다. 진단 로그 질문 원문의 30일 보관(M10-D04)은 그대로다. | 사용자 선택. POL-31과 같은 방식으로 기간 없이 구조를 먼저 만든다. |

## 범위 영향

| 대상 | 변경 |
| --- | --- |
| M7 채널·메시지·업무 카드(#76·#77·#155) | 구현은 남기고 비활성화한다. M7-D04의 채널 부분과 M7-D07~D09는 플래그가 켜졌을 때만 의미가 있다. |
| M9 홈 요약(#90) | 메시지 카드를 빼고 나머지 카드는 그대로다. |
| M10 자연어 분석(#92~#97) | #92 계약에 AI 대화 저장·목록·다시 열기·삭제·제목 수정을 더한다. 질문 하나는 지금과 같이 자연어 요청 하나다. M10에서는 질문마다 독립적으로 해석한다. |
| M14(#118·#121) | 1:1 대화와 채팅 전용 스트림(M14-D07·D08)을 범위에서 뺀다. |
| M15(#124~#126) | 후속 질문 문맥(FR-NL-25)은 그대로 M15다. 최근 질의(FR-NL-23, POL-47)는 AI 대화 목록과 겹치므로 #124에서 대화 목록 위에 둘지 다시 판단한다. |

## 스키마 영향

- 채팅 테이블: 변경 없음(DROP하지 않는다).
- AI 대화: V1의 `ai_threads`(대화, `employee_id`·`last_used_at`)와 `ai_requests`(대화 안의 요청, `thread_id`·상태)를 대화와 질문으로 쓴다. 두 테이블에는 제목·삭제 표시와 대화용 질문 원문·검증된 QuerySpec/ViewSpec·기준 시각 칼럼이 없으므로 다음 미사용 번호의 마이그레이션으로 더한다. V1은 수정하지 않는다. 칼럼 이름과 형태는 #92 계약과 그 구현 이슈에서 정하고, 번호는 병합 직전에 정한다(#128 규칙).
- M10-D08의 진단 정보와 겹치는 칼럼이 생긴다. 진단 로그의 질문 원문은 30일 뒤 지우고(M10-D04), 대화의 질문은 사용자가 지우거나 #99 기간이 끝날 때까지 남는다. 두 보관 기준이 섞이지 않게 저장 위치를 나눌지 #92에서 정한다.

## 남은 결정

- 비활성화 플래그 이름, 꺼졌을 때 응답, 채널 참여 자동 종료 리스너(`ChannelParticipationEnding`)를 계속 돌릴지
- AI 대화 operation 형태와 자연어 요청(#96)과의 연결 방식, 대화 질문과 진단 로그 원문의 저장 위치(#92)
- AI 대화 보관 기간(#99)
