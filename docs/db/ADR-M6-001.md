# ADR-M6-001 · 스터디룸 예약 단위, 사물함 요금·기간, 예약 취소, 공간 업무 권한, 타 지점 최소 요약

- 상태: **확정(사용자 의사결정)** · M6-D06의 권한 코드 이름은 구현 제안이며 리뷰에서 조정할 수 있다.
- 기록일: 2026-10-28
- 적용 범위: M6 룸 예약·사물함 유료 운영
- 관련: [ADR-M4-002](ADR-M4-002.md)(환불 권한 M4-D08, 고객 조회 범위 M4-D05), [ADR-M5-001](ADR-M5-001.md)(정확 일치 조회 M5-D05~D07)

## 결정

| ID | 최종 결정 | 선택 이유/결과 |
| --- | --- | --- |
| M6-D01 | **스터디룸 예약은 정시(매시 00분)에 시작하고 1시간 단위로 잡는다. 요금은 `예약 당시 시간당 요금 × 이용 시간`이다.** V1의 30분 슬롯·30분당 요금 구조를 새 버전 마이그레이션으로 바꾼다. V1은 수정하지 않는다. | SRS FR-ROOM-02·06이 정한 단위를 스키마 제약까지 맞춘다. 서버 검증만 두면 DB가 30분 예약을 허용해 원장과 요구사항이 어긋날 수 있다. |
| M6-D02 | **사물함 4주(28일) 요금은 사물함마다 둔다(V1 `lockers.rate_per_4weeks_krw`).** 지점의 요금 정책은 사물함 등록·수정 시 요금 설정과 "지점 사물함 요금 일괄 적용"으로 관리한다. 거래에는 결제 당시 요금을 스냅샷으로 남긴다. | 스키마 변경 없이 지점별 요금 운영이 가능하다. 크기·위치에 따라 요금이 다른 사물함도 표현할 수 있다. |
| M6-D03 | **사물함 배정·연장 기간은 28일의 배수만 허용한다.** 연장은 현재 종료일부터 이어 붙인다. 조기 반납은 잔여 이용료를 환불하지 않고 배정을 종료하며, 같은 사물함을 즉시 다른 고객에게 배정할 수 있다. | V1 `locker_assignment_charges`의 `(end_date - start_date) = 과금 구간 × 28` 제약과 FR-PAY-12의 비환불 기준을 그대로 따른다. 남는 날짜를 일할 계산하지 않는다. |
| M6-D04 | **확정 예약의 취소·전액 환불은 예약 시작 시각 전까지만 허용한다.** 시작 시각 이후에는 이용 시작이 없어도 취소·환불하지 않는다. 변경은 기존 예약 취소·환불 후 새 예약으로 처리한다. | 규칙이 단순하고, 시작 시각이 지난 시간대를 다시 판매할 수 없다는 점과 맞는다. |
| M6-D05 | **룸·사물함 원장과 요금 관리는 `operations:write`, 예약·배정·연장·취소 환불은 해당 지점의 `payments:write`가 필요하다. 룸 이용 시작·완료와 사물함 반납은 해당 지점 직원이면 처리할 수 있다.** 비활성 지점에서는 신규 예약·배정·연장을 거부하고, 취소 환불·반납·이용 완료는 허용한다. | M4 판매·환불과 같은 권한 기준이다. 결제가 따르지 않는 현장 처리는 결제 권한 없는 직원도 할 수 있게 한다. FR-BR-08을 따른다. |
| M6-D06 | **타 지점 고객 최소 요약(POL-01, FR-MEM-03)은 OWNER·MANAGER와 새 권한 `customers:cross-branch-read`를 받은 직원만 조회한다.** 조회 시 응대 사유를 입력받아 `customer_service_interactions`에 기록한다. 요약은 보유 이용권·유효 상태·이용 일시·이용 지점으로 제한한다. 결제 상세는 대상 지점의 `payments:read`를 따로 확인한다. | POL-01이 정한 "관리자가 별도 응대 권한을 부여한 직원"을 기존 권한 부여 구조로 표현한다. 권한 정의는 새 버전 마이그레이션으로 추가한다. |

## 스키마 영향

새 버전 SQL 한 개(작성 시점의 다음 미사용 번호)로 다음을 처리한다. V1은 수정하지 않는다.

- `rooms.rate_per_30min_krw` → 시간당 요금 컬럼
- `room_reservations`: 시간당 요금 스냅샷과 시간 수 컬럼, 정시 시작·1시간 배수 CHECK, 금액 CHECK
- `room_reservation_slots`: 정시 슬롯 CHECK(중복 방지 유니크 키 `(room_id, slot_start_at)`는 유지)
- `permission_definitions`: `customers:cross-branch-read` 추가(관리자 전용 아님)

사물함 테이블(`lockers`, `locker_assignments`, `locker_assignment_charges`)은 변경하지 않는다.

## 영향

- 결제·멱등성은 M4 결제 구현(`payments.purpose = ROOM | LOCKER`, `idempotency_records`)을 재사용한다.
- 룸 취소 환불은 M4의 환불 원장(`refunds`, 결제당 1회 전액)을 그대로 쓴다.
- 룸 운영 시간(`room_weekly_hours`) 안에서만 예약을 받을지는 SRS에 요구가 없어 이 ADR에서 정하지 않았다.
