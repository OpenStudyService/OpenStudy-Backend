# ADR-COM-001 · 명시적 화면 갱신과 요청 시 권한 재검증

- 상태: **확정(사용자 의사결정), 구현 전환은 후속 작업**
- 결정일: 2026-11-06
- 적용 범위: 공통 업무 화면·승인 대기·근태·AI 채팅과 관련 API·배포·검증
- 근거: SSE 제거 영향 평가 후 사용자가 수동 갱신 방식을 선택하고 SRS·설계·이슈에 기록하도록 요청했다.
- SRS: v1.15 POL-52·POL-53, FR-COM-13, FR-COM-11·12·14, FR-STAFF-04, FR-AICHAT-08, FR-NL-20

## 배경

기존 공통 SSE는 커밋 후 무효화, 재연결 후 재조회, 다른 세션의 권한 변경 감지를 수행한다. 그러나 관리 업무 화면에서 읽거나 편집하는 중 목록과 수치가 바뀌는 동작은 필수 요구가 아니다. 팀 채팅도 서비스 범위에서 제외했다(ADR-M10-002). 최신 AI 화면은 JSON 요청·응답으로 조회한다.

화면을 안정적으로 유지하고 연결·재연결·heartbeat·정기 조회 관리 비용을 줄이기 위해 명시적 갱신으로 전환한다. 이는 서버 인가·트랜잭션·버전 검증을 완화하는 결정이 아니다.

## 검토한 선택지

| 선택지 | 검토 결과 |
| --- | --- |
| SSE 유지 | 다른 세션의 변경을 빠르게 알지만 연결·재연결·권한 회수 전파와 배포 설정을 계속 관리해야 한다. |
| Polling으로 교체 | 연결은 단순해지나 갱신 주기·화면 가시성·부하·세션 활동 분류가 필요하고 편집 중 자동 갱신 문제도 남는다. |
| 사용자 행동에 따른 명시적 갱신 | 변경 반영 지연을 수용하는 대신 화면 안정성과 구현 단순성을 얻는다. **이번에 선택했다.** |

## 결정

| ID | 확정 내용 |
| --- | --- |
| COM-D01 / POL-52 | **업무 데이터의 변경 알림·상태 확인을 위한 SSE와 polling을 사용하지 않는다.** WebSocket 등 다른 상시 알림 방식으로 대체하지 않는다. |
| COM-D02 / POL-52 | 메뉴 진입·같은 메뉴 재클릭·브라우저 새로고침·검색·필터·정렬·페이지·지점 변경 시 서버에서 다시 읽는다. 단순 탭 포커스 복귀·네트워크 복구·시간 경과로 조회하지 않는다. |
| COM-D03 / POL-52 | 업무 화면은 마지막으로 받은 상태를 유지한다. 같은 메뉴 재클릭 시 유효한 조회 조건을 유지하고 재조회에 실패해 이전 결과를 표시할 때는 안내를 표시한다. 승인 대기는 화면에 진입하거나 브라우저를 새로고침할 때 상태를 조회한다. 조회 실패를 0건·저장 성공으로 대체하지 않는다. |
| COM-D04 / POL-52 | 본인의 등록·수정·처리 성공은 응답과 관련 목록·상세·필요한 요약에 반영한다. 관련 없는 화면을 일괄 재조회하지 않는다. 미저장 입력은 보호하고 이동·갱신 시 기존 이탈 경고를 적용한다. |
| COM-D05 / POL-53 | 다른 세션에서 바뀐 계정·권한은 **다음 API 요청부터 현재 서버 상태로 차단**한다. 아무 요청 없이 열린 화면·메뉴까지 즉시 지우는 보장은 요구하지 않는다. 신규 로그인 차단·서버 세션 만료·CSRF·지점 인가는 유지한다. |
| COM-D06 / POL-53 | 감지된 401, 접근 범위 변경, 로그아웃·계정·지점 전환에서는 해당 비공개 캐시·입력·진행 요청을 정리하고 늦은 응답을 버린다. 403/404는 기존 공개 범위 규칙을 유지한다. 백그라운드 `/me` 조회는 추가하지 않는다. |
| COM-D07 / POL-52·53 | 오래된 좌석·예약·결제 화면으로 명령해도 서버가 최신 상태·권한·버전·중복·금액을 최종 검증한다. 충돌 시 입력을 보존하고 최신값 확인 후 재시도한다. 사용자가 고치지 않은 최신 필드를 덮어쓰지 않는다. |
| COM-D08 / POL-52 | AI 채팅도 JSON 요청·응답으로 상태·결과·확인 필요·오류를 처리한다. 서버 단계의 실시간 표시·SSE 재연결·상태 polling은 필수가 아니다. 요청 중 중복 제출, 기존 취소 요구의 처리 범위, 제한 시간과 늦은 응답 보호는 별도 계약에서 유지·검증한다. 실제 비동기 상태 조회가 필요해지면 후속 의사결정으로 정한다. |

### 자동 처리를 모두 금지하는 결정은 아니다

로컬 시계·입력 debounce·사용자 요청에 대한 페이지 조회와 저장 결과 적용은 허용한다. SMTP 메일 재시도·보존 기간 정리 등 서버의 업무용 스케줄러는 화면 polling과 별개다. 유휴 60분·최대 12시간의 서버 세션 정책도 바꾸지 않는다.

## 구현 전환 범위와 현재 상태

- 이번 변경은 **문서·요구사항·이슈 기록**이다. 현재 SSE endpoint·스케줄러·Outbox와 프론트 공통 연결·타이머가 제거됐다는 뜻이 아니다.
- Backend는 공통 SSE 및 남아 있는 AI SSE 호환 경로, 전달 전용 세션 검사·발행 스케줄러와 workspace Outbox 생산/소비를 함께 검토한다. 소비만 끄고 미발행 행이 계속 쌓이지 않도록 한다. 초대 메일 발송 큐·감사 원장은 유지한다.
- `workspace_event_outbox` 테이블의 DROP이나 기존 Flyway 수정은 확정하지 않았다. 스키마 정리는 후속 구현에서 사용처·이력 보존과 함께 판단하고 필요하면 새 migration을 사용한다.
- Frontend는 공통 EventSource, 창 포커스·네트워크 복귀 자동 재조회, 근태 30초·승인 대기 15초 등의 서버 조회 타이머를 제거할 대상이다. 같은 메뉴 클릭을 단순 URL 이동으로 처리하지 않고 실제 재조회를 연결해야 한다. 캐시의 staleTime만 늘려 해결했다고 보지 않는다.
- OpenAPI·생성 타입·SSE 전용 계약 테스트는 실제 endpoint 전환과 함께 수정한다. 이 문서 변경만으로 현재 구현 계약의 operation을 삭제하거나 새 API가 구현됐다고 표시하지 않는다.
- SSE buffering·heartbeat·연결 수·fan-out 관련 배포 인수는 전환 후 적용하지 않는다. 일반 API·AI 장시간 HTTP 요청의 timeout·HTTPS·쿠키·CSRF 검증은 유지한다.

## 인수 조건

- 화면을 계속 보고 있거나 창 복귀·네트워크 복구만 일어나면 데이터 조회 요청이 생기지 않는다. 화면 상태 확인용 타이머와 EventSource가 없다.
- 메뉴 진입·같은 메뉴 재클릭은 서버를 조회한다. 재클릭 시 조건을 유지하고 빈값과 오류를 올바르게 표시한다. 일반 재조회는 메뉴 재클릭과 브라우저 새로고침으로 제공하고, 오류 복구와 작업별 재조회는 해당 화면에서 제공한다. 승인 대기에서는 화면 진입 또는 브라우저 새로고침으로 승인·반려 결과를 확인한다.
- 본인 저장 성공은 관련 결과에 반영되며 실패·409·조회 오류·미저장 입력은 보호된다.
- 다른 세션에서 권한 회수 후 다음 API가 거부되고, 오류를 받은 화면의 비공개 상태가 정리된다. 아무 요청 없는 화면을 즉시 정리하는 시험은 새 기준이 아니다.
- 두 사용자의 좌석·예약·버전 충돌, 중복 결제·응답 유실 재시도, 계정·지점 변경 뒤 늦은 응답을 실제 서버로 검증한다.
- API 계약·MSW·브라우저·배포 문서의 SSE/polling 전제가 함께 정리되고, SMTP·감사·세션 보안 회귀가 유지된다.

## 이전 결정과의 관계

기반 설계 D9, workspace-api의 SSE 전달 요구, M10-D01의 SSE 부분, M14-D02의 스트림 종료 부분과 이전 실시간 인수 조건은 이 결정으로 대체한다. 이전 ADR 본문·검증 기록은 당시 구현의 근거로 남긴다. 팀 채팅 제외와 AI 대화 저장 정책(ADR-M10-002), 서버 인가·거래 정합성·세션 시간은 유지한다.
