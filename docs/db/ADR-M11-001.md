# ADR-M11-001 · 보존 기간 미정 상태의 파기 구조, 인프라 작업 관리, 기존 검증 이슈, 관측 방식

- 상태: **확정(사용자 의사결정)** · M11-D05~D08은 SRS 문구와 V1 스키마에서 도출한 구현 기준이며 리뷰에서 조정할 수 있다.
- 기록일: 2026-10-28
- 적용 범위: M11 릴리스 검증·운영 준비
- 근거: `FR-MEM-09`, `FR-AUD-05`, `FR-UI-09/10`, `NFR-SEC-09/11`, `NFR-PERF-08`, `NFR-OPS-03/05/08`, POL-02·POL-03, SRS v1.9 POL-31~34

## 결정

| ID | 최종 결정 | 선택 이유/결과 |
| --- | --- | --- |
| M11-D01 | **개인정보 자동 파기와 감사 이벤트 정리는 정보 종류별 규칙 설정으로 만들고, 보존 기간이 확정되기 전에는 모든 규칙을 비활성으로 둔다.** 기간(개인정보·감사 이벤트·백업) 확정은 별도 결정 이슈로 관리한다. 기간이 확정되기 전에는 M11의 정책 인수를 완료로 표시하지 않는다. | POL-02·03이 임의 기간 적용을 금지한다. 구조를 먼저 만들어 기간이 정해지면 설정만 바꾸면 되게 한다. |
| M11-D02 | **백업·복구 실행, HTTPS 프록시, 지표 수집 같은 인프라 쪽 작업은 Backend 이슈에 요청 사항으로 적고, 인프라 팀원에게는 메시지로 전달한다.** Infra 저장소에 M11 마일스톤을 만들지 않는다. | 사용자 선택. 인프라 작업의 진행 확인은 Backend 이슈의 체크리스트로 한다. |
| M11-D03 | **M11 범위와 겹치는 기존 열린 이슈(Backend #10·#18·#29, Infra #1·#2)는 현재 마일스톤에 두고, M11 이슈가 그 결과를 선행으로 참조한다.** 같은 검증을 M11에서 다시 만들지 않는다. | 중복 작업과 이력 분산을 막는다. |
| M11-D04 | **상태 점검과 지표는 Actuator·Micrometer로, 로그는 구조화(JSON) 표준 출력으로 내고 ECS의 CloudWatch에서 본다.** 별도 모니터링 서버는 두지 않는다. | 현재 ECS 구성에 추가 인프라 없이 붙일 수 있다. |
| M11-D05 | **개인정보 파기는 고객 행을 지우지 않고 식별 필드(이름·연락처·이메일·메모)를 파기 표시 값으로 바꾸는 익명화로 처리한다.** 결제·이용권·이용 기록의 참조와 집계는 그대로 유지한다. 처리 기록(규칙, 대상 수, 시각, 성공·실패)은 원문 없이 남기며, 이를 위한 테이블은 다음 미사용 번호의 마이그레이션으로 추가한다. | FR-MEM-09의 "거래 이력과 통계 정합성 유지"와 "파기 원문을 처리 기록에 남기지 않음"을 함께 지킨다. |
| M11-D06 | **전체 업무 회귀는 Frontend의 Playwright로 실제 Backend·MySQL에 연결해 실행한다.** 실제 메일·DomainLens·운영 프록시처럼 로컬에서 재현하지 못한 항목은 미검증으로 분리해 기록한다. | 이미 Frontend에 Playwright가 있다. NFR-OPS-08에 따라 모킹 성공을 완료 증거로 쓰지 않는다. |
| M11-D07 | **live 빌드에는 MSW·데모 사용자 전환·가상 원장 초기화·임의 결제 실패 입력 코드가 번들에 포함되지 않는다.** 빌드 결과물 검사로 확인한다. | NFR-OPS-08. 화면에서 숨기는 것만으로는 부족하다. |
| M11-D08 | **보안 헤더(X-Content-Type-Options, X-Frame-Options 또는 frame-ancestors, Referrer-Policy, 기본 CSP)는 앱에서, HSTS는 HTTPS 종단(프록시)에서 설정한다.** | NFR-SEC-11. TLS 종단 위치에 맞게 책임을 나눈다. |

## 스키마 영향

M11-D05의 파기 처리 기록 테이블과 규칙 설정 저장 위치를 다음 미사용 번호의 마이그레이션으로 추가한다. V1은 수정하지 않는다. `customers` 행은 삭제하지 않는다.
