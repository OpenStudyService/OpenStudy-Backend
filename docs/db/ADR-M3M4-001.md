## 거래·환불과의 결합

- 원 결제는 승인 시각·원 금액을 보존한다. 환불은 별도 `refunds` 사건(원결제당 최대 1회)으로 기록하고 `payments`/`passes` 상태를 원자적으로 갱신한다.
- **실제 사용 이력이 없다면** 승인 거래 전액 환불을 허용한다. 기간권은 `NOT_STARTED`면 아직 사용하지 않았음이 명확하다. 단, 사용 이력이 없는 다른 종류 이용권의 환불은 단순 `ACTIVE` 상태가 아니라 실사용/차감 이력까지 검사한다.
- 결제 즉시 유효기간이 시작돼도 이론적으로 환불은 가능하지만, 이번 결정은 기간권의 **유효기간 자체를 첫 입실부터** 계산하는 것이다. 환불 가능성과 기간 시작은 별개 정책이다.
- 이미 개시된 기간권이 사용 이력이 있는 경우 전액 환불은 거절한다. 환불 시 미개시 기간권의 `started_at`, `expires_at`은 계속 NULL이다.

## 정책 변경 영향

기존 기반 DB 설계 Q2의 '상품에는 period_days, 실제 시작/종료는 구매·발급 시 결정' 중 **일수 저장은 유지**, 기간권의 '실제 시각을 발급 시 확정'만 이 ADR의 **첫 입실 시 확정**으로 대체한다. `FR-PASS-01` 조회의 미개시 표시, `FR-PASS-08` 계산 기준, `FR-PASS-11` 검색 조건, `FR-SEAT-06` 입실 가드, M4/M5 API DTO에서 `NOT_STARTED` 상태를 명시한다.

## 이 ADR이 확정하지 않은 사항

- 시간권·정액권의 선택적 유효기간 개시 기준. 기존 설계 방식을 임의 변경하지 않는다.
- 상품 판매 범위와 발급 이용권 사용 범위의 동일성·스냅샷 여부(`FR-PASS-13`, M5).
- 결제 승인/실패를 사용자가 모의 제어하는 UI 방식, 무료·수동 발급 모델(향후 단계).
- 개인정보 법정 보존기간과 타 지점 접근 감사 범위(후속 별도 결론).
