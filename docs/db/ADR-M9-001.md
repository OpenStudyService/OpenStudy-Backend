# ADR-M9-001 · 정형 집계 기간·환불 기준·매출 범위·추세 구간과 홈 집계 기준

- 상태: **확정(사용자 의사결정)** · M9-D05~D09는 SRS 문구와 V1 스키마에서 도출한 구현 기준이며 리뷰에서 조정할 수 있다.
- 기록일: 2026-10-28
- 적용 범위: M9 운영 홈·정형 집계. M10 자연어 분석이 같은 지표 정의를 재사용한다.
- 근거: `FR-AGG-01~03/06~11/14/17/18`, `FR-PASS-05`, `FR-DASH-02/03/05/06`, `FR-UI-08`, `NFR-PERF-04`, SRS v1.7 POL-23~26

## 결정

| ID | 최종 결정 | 선택 이유/결과 |
| --- | --- | --- |
| M9-D01 | **기간이 없으면 이번 달 1일 0시부터 내일 0시 미만까지(Asia/Seoul)를 적용한다. 366일을 넘는 기간은 400으로 거부한다.** 적용한 기간은 응답 메타정보로 돌려준다. | 무제한 조회를 막고(FR-AGG-08), 운영자가 가장 자주 보는 범위를 기본으로 한다. |
| M9-D02 | **기본 환불 기준은 환불 처리일이다.** 요청에서 원결제일 기준을 고를 수 있다. 카드·표·차트·최소 원장·AI 응답이 같은 기본값을 쓴다. | 이미 지난 기간의 수치가 나중에 바뀌지 않는다. |
| M9-D03 | **매출(승인액·환불액·순매출)은 이용권·스터디룸·사물함 결제를 모두 포함하고 용도(`payments.purpose`)별 소계와 필터를 제공한다.** 판매량·상품 순위·발급 건수는 이용권만 대상이다. | 지점 매출 전체를 한 기준으로 보면서 이용권 지표는 따로 볼 수 있게 한다. |
| M9-D04 | **추세의 주는 월요일에 시작한다(Asia/Seoul). 기간 안의 모든 일·주·월 구간을 반환하고 거래가 없는 구간은 0으로 채운다.** 기간 경계에 걸친 첫·마지막 구간은 기간 안의 부분만 집계하고 그 사실을 메타정보로 표시한다. | 차트가 끊기지 않고, 경계 처리 기준이 일관된다(FR-AGG-14). |
| M9-D05 | **매출 귀속 지점은 원결제 지점이다.** 환불은 처리 지점(`refunds.processing_branch_id`)이 아니라 원결제 지점의 매출에서 차감한다. 이용권 소비 차감과 실패 결제는 매출에 넣지 않는다. | FR-AGG-01의 "결제 지점 귀속, 이용 지점과 구분"을 환불까지 일관되게 적용한다. |
| M9-D06 | **V1에는 결제 없는 이용권 발급(무료·수동 발급)이 없다(`passes.purchase_payment_id` 필수).** 발급 건수 = 생성된 이용권 수(이후 환불된 것 포함), 순판매량 = 승인된 이용권 결제의 발급 수량 − 환불된 수량, 결제 건수 = 승인 결제 수로 각각 따로 반환한다. 무료·수동 발급이 생기면 발급 건수에만 더한다. | SRS의 세 지표 구분(FR-PASS-05, FR-AGG-03)을 현재 스키마로 표현한다. |
| M9-D07 | **집계·최소 원장은 요청한 모든 지점에 `sales:read`가 있어야 한다.** 권한 밖 지점이 하나라도 있으면 403이다. 결제 상세는 `payments:read`를 따로 확인한다. 최소 원장에는 고객 이름·연락처를 넣지 않는다. | 권한 밖 지점이 합계에 섞이는 일을 막는다(FR-AGG-11, FR-AGG-18). 조용히 제외하면 사용자가 잘못된 합계를 볼 수 있다. |
| M9-D08 | **홈의 "오늘"은 Asia/Seoul 날짜다.** 오늘의 업무는 기한이 오늘 이전·오늘인 미완료 업무와 오늘 완료한 업무이며, 완료율 = 오늘 완료 ÷ 오늘의 업무다. 오늘의 근무 계획은 오늘과 겹치는 취소되지 않은 예정 근무다. OWNER는 선택 범위(전체 또는 지점)의 업무를, 직원은 본인 업무를 기본으로 본다. | 홈 카드와 원본 목록이 같은 필터로 재현되게 한다(FR-DASH-02·03·05). 각 원본 기능(M5·M7·M8)의 집계 API를 재사용한다. |
| M9-D09 | **비율은 소수 첫째 자리까지 반올림(HALF_UP)하고, 분모가 0이면 "해당 없음"으로 반환한다. 금액은 원 단위 정수다.** 0, 데이터 없음, 해당 없음을 서로 다른 값으로 표현한다. | FR-AGG-10·FR-UI-08의 공통 형식을 서버 응답에서부터 고정한다. |

## 스키마 영향

새 테이블은 없다. 원거래(`payments`, `refunds`, `passes`, `product_revisions`)에서 직접 계산한다. 원결제일 기준 환불 집계와 상품별 판매량에 인덱스가 부족하면, 실행 계획을 확인한 뒤(NFR-PERF-04) 다음 미사용 번호의 마이그레이션으로 인덱스만 추가한다.
