# ADR-M15-001 · 최근 질의 범위, 내보내기 위치, 동의어 관리, 문맥·실행 계획 재사용

- 상태: **확정(사용자 의사결정)** · M15-D04~D08은 SRS 문구와 M10 결정에서 도출한 구현 기준이며 리뷰에서 조정할 수 있다.
- 기록일: 2026-10-29
- 적용 범위: M15 분석 사용성·재사용 확장
- 관련: [ADR-M10-001](ADR-M10-001.md)(질문 원문 30일 M10-D04, 결과 상한 M10-D03, 매출 질문 권한 M10-D06), [ADR-M9-001](ADR-M9-001.md)
- 근거: `FR-NL-22~25`, `FR-NL-35`, `FR-AGG-16`, SRS v1.13 POL-47~49

## 결정

| ID | 최종 결정 | 선택 이유/결과 |
| --- | --- | --- |
| M15-D01 | **최근 질의는 본인 질의 중 30일 안의 최신 20건을 보여 준다.** M10 진단 로그의 원문 보관 기간(30일)과 맞추고 별도 저장소를 두지 않는다. 다른 사용자의 질의는 보이지 않고, 재실행할 때 현재 권한을 다시 확인한다. | 원문 보관 기간과 충돌하지 않는다. |
| M15-D02 | **CSV는 서버가, 이미지는 브라우저가 만든다.** CSV는 원 실행의 조건으로 서버가 권한을 다시 확인해 만들고(최대 1,000행), 조회 조건·단위·통화·기준 시각을 머리말에 넣으며, 내보내기를 감사에 남긴다. 이미지는 화면에 그린 차트를 브라우저가 저장하고 조건·기준 시각을 그림에 넣는다. | CSV에 권한 밖 데이터가 섞이지 않게 서버가 책임지고, 이미지는 화면과 똑같게 만든다. |
| M15-D03 | **동의어는 M10 의미 카탈로그에 코드로 두고 리뷰로 관리한다.** 오타·띄어쓰기 변형은 서버의 정규화 규칙으로 처리한다. 관리자 편집 화면은 만들지 않는다. | 잘못된 동의어가 수치를 바꾸는 일을 코드 리뷰로 막는다. |
| M15-D04 | **검증된 실행 계획은 같은 사용자·같은 세션에서 30분 동안 재사용한다.** 페이지·정렬·상세 요청은 모델을 다시 부르지 않고 계획을 다시 실행하며, 요청마다 현재 권한과 결과 상한을 확인한다. 권한이 바뀌었으면 재사용하지 않는다. | FR-NL-35의 불필요한 모델 재호출 방지와 권한 재검증을 함께 지킨다. |
| M15-D05 | **해석 필터 수정은 기간·지점·상품 조건만 바꿀 수 있고, 서버가 바뀐 QuerySpec을 M10 검증기로 다시 검증한 뒤 실행한다.** 모델은 다시 부르지 않는다. | FR-NL-22. 사용자가 직접 바꾼 조건도 같은 검증을 거친다. |
| M15-D06 | **후속 질문은 같은 대화의 직전 성공 요청의 조건을 이어받는다.** 응답에 이어받은 조건과 바뀐 조건을 구분해 표시한다. 선택 지점 범위가 바뀌면 문맥을 끊는다. 문맥에서 이어받은 지점도 현재 권한으로 다시 검증한다. | FR-NL-25와 마일스톤 비고의 "문맥을 권한의 근거로 재사용하지 않는다". |
| M15-D07 | **CSV 셀 값이 `=`, `+`, `-`, `@`로 시작하면 수식으로 실행되지 않게 처리한다.** | 스프레드시트에서 열 때의 수식 주입을 막는다. |
| M15-D08 | **같은 의미·조건의 질문은 표현이 달라도 같은 정규화된 QuerySpec으로 바뀌어 같은 결과를 낸다.** 대표 변형 질문 세트를 테스트로 둔다. | FR-NL-24의 일관성. |

## 스키마 영향

없음. 최근 질의는 M10 진단 저장 구조를 쓰고, 실행 계획 재사용은 세션 범위 저장소를 쓴다. 다중 인스턴스에서 세션 범위 저장소를 공유해야 하면 구현 이슈에서 정한다.
