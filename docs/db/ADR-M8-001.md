# ADR-M8-001 · 근무표 관리 권한, 근태 조회 범위, 근무 길이, 운영 중지 지점

- 상태: **확정(사용자 의사결정)** · M8-D05~D08은 SRS 문구와 V1 스키마에서 도출한 구현 기준이며 리뷰에서 조정할 수 있다.
- 기록일: 2026-10-28
- 적용 범위: M8 근무표·본인 출퇴근
- 근거: `FR-SHIFT-01~04`, `FR-ATT-01~05`, `FR-BR-08`, SRS v1.6 POL-19~22

## 결정

| ID | 최종 결정 | 선택 이유/결과 |
| --- | --- | --- |
| M8-D01 | **예정 근무의 등록·수정·취소는 그 근무가 속한 지점의 MANAGER 이상이 한다.** 대상 직원은 그 지점의 활성 소속 직원이어야 한다. | SRS의 "관리자"를 기존 역할 판정으로 표현한다. 새 권한 코드가 필요 없다. |
| M8-D02 | **일반 직원은 본인의 근무표·근태만 본다. MANAGER는 MANAGER 이상인 지점에서 기록된 근무표·근태만 본다. OWNER는 전체를 본다.** 같은 직원이 다른 지점에서 일한 기록은 그 지점 권한이 없으면 보이지 않는다. | 지점 선택만으로 다른 지점의 개인 근태가 노출되지 않게 한다(FR-ATT-05). |
| M8-D03 | **예정 근무는 종료가 시작보다 늦고 길이가 24시간 이하여야 한다. 예정 휴게 분은 근무 길이보다 짧아야 한다.** 자정을 넘는 근무는 허용한다. | 날짜 입력 실수를 막는다. |
| M8-D04 | **운영 중지 지점에서는 새 출근과 새 근무 등록·수정을 거부한다. 진행 중인 근태의 휴게·퇴근, 근무 취소, 과거 기록 조회는 허용한다.** | FR-BR-08(신규 거래 제한, 진행 중 정리 허용)과 같은 기준이다. |
| M8-D05 | **근무 충돌 검사는 같은 직원의 모든 소속 지점에서 취소되지 않은 근무를 대상으로 한다.** 충돌 오류에는 겹친 시간 구간을 담는다. 겹친 근무가 요청자가 볼 수 없는 지점이면 지점·근무 상세 대신 "다른 지점 근무"로만 알린다. | FR-SHIFT-03의 "겹친 시간·대상 정보" 요구와 M8-D02의 조회 범위를 함께 지킨다. |
| M8-D06 | **승인 휴가와의 충돌은 `leave_requests.status = APPROVED`인 휴가의 날짜 구간(Asia/Seoul 기준 하루 전체)과 비교한다.** 승인 흐름은 M12에서 만들며, M8은 같은 검사 지점만 둔다. 대체근무(`shift_swaps`)도 M12에서 같은 검사에 연결한다. | 마일스톤 비고의 "후속 휴가·대체근무가 존재한다고 가정하지 않고 확장 가능한 계약으로 둔다"를 따른다. |
| M8-D07 | **실근무 분 = (퇴근 시각 − 출근 시각 − 휴게 구간 합)을 초 단위로 계산한 뒤 분 미만을 버린다.** 진행 중 휴게가 있으면 퇴근을 거부한다. 목록과 상세는 같은 계산을 쓴다. | 계산 기준을 하나로 고정해 목록·상세·이후 정정 결과가 일치하게 한다(FR-ATT-04). |
| M8-D08 | **출근은 본인만, 선택 지점의 활성 소속으로만 기록한다.** 같은 지점의 예정 근무 중 출근 시각을 포함하는 근무가 있으면 그 근무와 연결하고, 없으면 연결 없이 기록한다. 예정 근무만으로 출근 처리하지 않는다. | V1 `attendance_records.shift_id`가 선택 참조이고, 실제 출퇴근은 계획과 독립이라는 V1 설계를 따른다. |

## 스키마 영향

없음. V1의 `shifts`, `shift_events`, `attendance_records`, `attendance_breaks`, `leave_requests`로 구현한다. 중복 출근은 V1의 `active_employee_id` 유니크 키로 막는다.

M8용으로 예약했던 V3 번호는 쓰지 않는다. 이후 스키마 변경은 V2(M4) 다음의 미사용 번호를 쓴다.
