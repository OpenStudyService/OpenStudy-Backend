# ADR-M10-001 · DomainLens 엔진 경계, 자연어 질의 제한, 결과 상한, 진단 로그 보관

- 상태: **확정(사용자 의사결정)** · M10-D05~D08은 SRS 문구와 V1 스키마에서 도출한 구현 기준이며 리뷰에서 조정할 수 있다.
- 기록일: 2026-10-28
- 적용 범위: M10 자연어 분석·동적 시각화
- 관련: [ADR-M9-001](ADR-M9-001.md)(공통 집계 기반·지표 정의), [ADR-M5-001](ADR-M5-001.md) M5-D08(제한값을 측정 후 정하는 방식)
- 근거: `FR-NL-01~07/09~13/15~18/20/27~30/36/37`, `FR-VIZ-01~03/05/07~11/13~16`, `FR-AUD-02`, `NFR-SEC-04/10/12/13`, `NFR-PERF-01~03/09`, `NFR-DATA-04`, `NFR-OPS-07`, SRS v1.8 POL-27~30

## 배경

SRS는 DomainLens 엔진과 LLM으로 질문을 QuerySpec·ViewSpec으로 바꾸도록 요구한다. 2026-10-28 기준 DomainLens(`D:\Dev\workspace\DomainLens`)는 Boot 3.3 기반 실험 단계이며, OpenStudy가 의존할 `domainlens-engine-starter`는 아직 만들어지지 않았다.

## 결정

| ID | 최종 결정 | 선택 이유/결과 |
| --- | --- | --- |
| M10-D01 | **OpenStudy는 명세 생성을 포트(인터페이스) 뒤에 둔다.** 의미 카탈로그, IR 재검증, 권한·예산 검사, 검증된 QuerySpec의 JPA 실행, 요청 상태·SSE, 화면은 OpenStudy에서 만든다. DomainLens starter 개발은 DomainLens 쪽 작업이며, 실제 엔진 연동과 호환성 검증(NFR-OPS-07)은 starter가 나온 뒤 별도 이슈로 진행한다. | 엔진 일정과 무관하게 OpenStudy 쪽 보안·실행 경계를 먼저 완성한다. 엔진이 무엇을 만들든 서버가 다시 검증하므로 경계가 바뀌지 않는다. |
| M10-D02 | **자연어 질의의 빈도·동시 실행·실행 예산 제한은 설정값 구조로 만들고, 값은 실제 모델 지연·비용을 측정한 뒤 사용자가 확정한다.** 개발 기본값은 보수적으로 둔다. 제한 초과는 공통 429다. | 근거 없는 값으로 정상 사용을 막지 않는다(M5-D08과 같은 방식). |
| M10-D03 | **표는 서버 페이지 50행, 한 결과는 최대 1,000행이다. 차트는 상위 20개 항목만 그리고 나머지는 생략 표시한다. 기간은 M9와 같이 366일 이하다.** 상한에 걸리면 잘린 범위를 메타정보로 알린다. | 대량 전수조회를 막고(NFR-PERF-02) 잘린 결과를 전체로 오해하지 않게 한다(FR-VIZ-07). |
| M10-D04 | **진단 로그에 질문 원문을 저장하고 30일 뒤 원문만 삭제한다.** 요청 ID, 검증된 QuerySpec 식별정보, 검증 결과, 적용 범위, 단계별 시간은 계속 남는다. 비밀번호·인증정보·세션 정보는 원문에서 제거한 뒤 저장한다. | 해석 품질 분석에 원문이 필요하고, 개인정보 노출 기간은 짧게 유지한다. |
| M10-D05 | **자연어 결과의 수치는 M9 공통 집계 기반(ADR-M9-001)을 같은 조건 객체로 호출해 계산한다.** M10에서 지표 계산을 따로 구현하지 않는다. 의미 카탈로그의 지표는 M9 지표 정의와 1:1로 연결한다. | NFR-DATA-04의 "같은 원천·같은 계산 로직"을 구조로 보장한다. |
| M10-D06 | **매출 질문은 `ai:read`와 대상 지점 모두의 `sales:read`가 필요하다.** 권한 밖 지점이 포함되면 실행하지 않고 재입력 안내를 돌려준다. 확인 질문 선택 후 재실행할 때 현재 권한을 다시 확인한다. | FR-NL-09, FR-NL-37. M9-D07과 같은 지점 권한 기준이다. |
| M10-D07 | **모델에는 등록된 업무 용어·지표·차원·예제만 보낸다.** DB 원본 행, 고객 개인정보, 인증·세션 정보는 보내지 않는다. 모델이 만든 SQL·JPQL·JavaScript는 실행하지 않고, 검증된 QuerySpec만 서버의 허용 실행 계획으로 바꾼다. | NFR-SEC-12·13, FR-NL-17·18·30. |
| M10-D08 | **V1 `ai_requests`에는 질문 원문·QuerySpec·적용 범위·단계별 시간·클라이언트 요청 키 칼럼이 없다.** 진단과 중복 제출 방지를 위해 다음 미사용 번호의 마이그레이션으로 진단 테이블(또는 칼럼)을 추가한다. V1은 수정하지 않는다. | FR-AUD-02, FR-NL-20. M8에서 V3 예약이 해제되었으므로 작성 시점의 다음 번호를 쓴다. |

## 영향

- 실제 엔진 없이 개발·테스트하려면 포트의 테스트 구현(고정 명세 생성기)이 필요하다. 이 구현의 성공은 실제 엔진 호환성 검증으로 인정하지 않는다(NFR-OPS-07). 고정 예문 응답만으로 M10을 완료하지 않는다(FR-NL-01).
- M10 마일스톤 인수(실제 모델·MySQL 대표 질문 수치 일치)는 엔진 연동 이슈가 끝나야 가능하다.
- M5 후속 조회 횟수 제한(Backend #65)과 자연어 제한은 같은 공통 제한 컴포넌트를 쓸 수 있다.
